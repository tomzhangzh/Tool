## 一、项目亮点

### （一）战略性能力：配置 ↔ 手写代码双向通道（代码生成落地）

这是平台最重要的架构演进，直接补上了纯配置型低代码的天花板问题——"设计器只能配、程序员不能改"。

1. **GeneratedViewPath 落库**：PageSetting 新增 `GeneratedViewPath` 字段（实体 + 建表 SQL + 启动幂等迁移），页面配置与生成视图一一对应，可追溯。
2. **ViewGenerateService 代码生成**：把 ConfigJson 组件树生成为**可手改的真实 cshtml**，生成后自动回写路径，形成"设计器产物 → 标准视图文件"的闭环。
3. **逐区块加载策略**：FilterApp / DetailApp 加载时"**有路径走文件、无路径走 JSON 动态渲染**"，粒度到区块级；可逐页面、逐区块回退，风险可控。
4. **统一组件契约**：标签命名与运行时注册统一（`dyn-` + kebab-case），生成视图与 JSON 动态渲染走**同一套组件契约**，手改视图不影响运行时解析。
5. **手写体验工程化**：
   - `DynNodeViewOptions` 类 + `new { ... }.ToJson()`：手写选项有 **IDE 补全和编译期检查**；
   - `class` 等 C# 关键字键自动用字典初始化器；
   - 非法标识符键回退 C#11 原始字符串，边界情况不崩。
6. **裸标签属性直收**：`_BaseLayout` 裸标签可接收 `comoptions` / `labeloptions` / `itemoptions` / `wrapperoptions` 等属性（对象或 JSON 字符串均可），字符串侧 `JSON.parse` 失败仅 warn 不崩页——设计器配置与手写视图两条路径的容错一致。
7. **管理页行操作通用化**：`rowActions` 声明式配置，setting 102 已接入"生成视图"按钮 + 覆盖确认。

**意义**：平台形成 `可视化设计器 → 标准 cshtml → 程序员自由手改 → 运行时按路径加载` 的完整闭环，且逐页面、逐区块可回退。**这是"玩具低代码"与"生产级快速开发平台"的分水岭能力。**

### （二）UpdateEl 服务端 HTML 注入（页面部件级刷新）

大量页面交互通过 `dyn.updateEl(targetEl, url, body)` 实现：拉取**服务端渲染好的 HTML 片段**，注入目标容器并自动重挂载 Vue App。区别于普通低代码的"JSON 驱动重渲染"或"整页刷新"，它做到的是**页面部件级（partial）刷新**：

- 服务端可以参与权限判断、数据预取、模板拼接，再以 HTML 形式下发；
- 前端只做注入与挂载，配合 `dyn.html` / `dyn.reload` / `fetchPartial` 形成完整的碎片化更新体系；
- 这是平台区别于一般低代码方案的核心机制之一。

### （三）JS 数据桥：前端 ↔ 后端双向调用

- **前端 → 后端**：前端通过 JS 数据桥直接调用后端代码（服务端方法暴露为可调用的桥接口），业务逻辑不必全部前置到 API；
- **后端 → 前端**：后端代码可通过 `ActionHelper` 执行前端脚本，服务端可以主动触发前端动作/回调；
- 两条通路合围，前后端逻辑可互相编排，配合动作管道实现"服务端决策 + 前端表现"的混合编排。

### （四）多 VueApp + ShareModel

- **多 VueApp 共存**：同页多个 Vue App 独立挂载（`dyn-init="createApp"` 声明式），互不干扰；
- **ShareModel 共享模型**：跨 App 共享响应式数据模型，配合 DynEventBus 事件通信 + 参数上下文链，形成"**数据共享 + 事件解耦**"的完整体系——BlockApp 之间既可共享状态又可各自独立演进。

### （五）双渲染链路架构

区别于纯前端低代码和纯后端渲染，VueLibV4 同时支持两条渲染管线：

- **纯前端渲染**：后端只返回 JSON Config，前端 dyn-core 纯 JS 渲染 → 弹窗、局部区块速度极快；
- **后端 Razor 渲染**：服务端先跑 Razor 拼好 HTML，前端只挂 Vue → 权限过滤、服务端动态下拉、预查询数据场景天然支持。

混合架构让低代码平台既有前端的灵活交互，又有后端的安全控制和数据预加载。

### （六）组件双定义源（Razor View 优先 + DB 回退）

- 组件代码在 `.cshtml` 文件里（三段标记 `TEMPLATE/SCRIPT/STYLE`），Git 版本控制，改完刷新即生效；
- 数据库 `ComponentMeta` 作为运行时回退，支持设计器导出；
- `RazorComponentRenderer` 正则提取三段内容，无需额外构建。

### （七）V2 BlockApp 积木化 + DynEventBus

- 四个独立 BlockApp（Filter / List / Detail / Tree）是独立 Razor partial，通过 `DynEventBus` + ExecId 通信，互相零引用；
- 模板只管组装与事件名转换（如 TreeDetailV2 的 `tree.nodeClick → detail.editForm`）；
- **快照补发机制**：晚挂载的 BlockApp 自动读快照拿到最新 payload，解决挂载时序问题；
- 全局 `Map<execId, rootEl>` 让弹窗脱离 DOM 后仍能按 ExecId 通信。

### （八）统一动作管道语法

```
dyn-click="Submit|Toast('保存成功')|Reload"
```

- 声明式管道，`|` 分隔按序执行，某步返回 false 即中止；
- 所有动作可入库（`DynActionHelper` 表），前端启动时自动注册；
- 支持 `$before` / `$onSuccess` / `$onFail` / `$after` 钩子与 `{{params.xxx}}` / `{{model.xxx}}` / `$result.xxx` 占位。

### （九）免模型动态 CRUD

- 知道表名即可分页查询 / 增 / 删 / 改，后端不需要为每张表建实体；
- ADO.NET 动态拼**参数化 SQL**（防注入），自动识别主键、字段类型；
- `save` 自动判定 insert/update，`saverelations` / `getrelations` 支持主子表关系；
- `project` 参数隔离业务库/平台库。

### （十）透明渲染包装 + 裸标签直连

- `<dyn-el-input v-model="x" label="名称" />` 不传任何 JSON 配置即可用：`directMode` 把直连 props 合成内存配置，**复用同一套**配置驱动/穿透/校验逻辑；
- 手写标签与设计器导出的 JSON 配置两条路径完全统一（与代码生成双向通道同契约呼应）；
- DynDynamicCom 透明包装层不覆盖真实组件的 meta/校验（同一根元素上共存）。

### （十一）组件属性穿透（provide/inject + compassthrough）

- 容器按 `compassthrough` 清单把自身 comoptions / labeloptions 向下 provide；
- 子组件仅继承"自身未显式配置"的路径；支持白名单开/关两种模式，多级链式穿透；
- `mergedOptions` computed 保证穿透值实时跟随，配置变化即时生效。

### （十二）配置契约全小写 + 旧键自动迁移

- 配置键名约定一律全小写无分隔（`comoptions`/`labeloptions`/`itemoptions`），与 SQL 种子、PageGen、设计器属性面板一致；
- `_migrateLegacyOptions` 运行时原地把旧驼峰配置（`comOptions`/`labelOptions`/`comInnerInfo`）迁移成新契约，设计器一保存即净化，存量数据**无感升级**。

### （十三）校验器体系 + evalCondition 动态条件

- 8 类内置校验（required/min/max/length/pattern/email/phone/number）+ `custom` 表达式 + `enableWhen` 条件启用；
- `evalCondition` 可动态改 shell / labeloptions / comoptions 三件套（显隐、禁用、换配置）；
- 校验结果写回根元素 `__dynErrors` 供父级表单聚合；动态脚本有 `disableEvalJs` 全局开关做安全兜底。

### （十四）下拉四数据源 + 父值级联

static / dict / table / ajax 四种数据源统一归一 `{value,label}`，支持 `valueKey`/`labelKey` 映射；`parentValuePath` 变化自动重新加载选项，联动零手写。

### （十五）设计态 / 运行态严格隔离

- 设计器选中态、hover、Tab 预览切换**绝不写入** ConfigJson；
- 下发运行时自动剔除 `designerMeta` / `designerOperates`；
- 画布 Overlay 不包装 DOM（不影响运行时 DOM 结构）。

### （十六）参数上下文链 + 动态参数面板

- L0 模板静态参数 → L1 页面 data-* → L2 共享 scope；支持 fork（弹窗继承父上下文）、commit（跨 App 同步）；
- **动态参数面板**：运行时可视化查看/编辑参数上下文，排查"参数从哪来、被谁改"更直观。

### （十七）页面组成图（X6 图谱）

- **X6 图谱**递归展开「页面 → 模板 → 槽位/页签/弹窗 → PageSetting / 子页面」的完整组成关系；
- 按积木的 Events / Commands 元数据**绘制事件总线连线**，页面通信关系一目了然；
- 编辑弹窗内嵌只读小图、独立大图支持点节点抽屉式编辑——复杂页面的结构可视化与诊断利器。

### （十八）Seeder 幂等增量迁移 + Razor 运行时编译

- 建表 + 种子 SQL（补表/补列/改名/补种子，不删数据），可重复启动；
- `AddRazorRuntimeCompilation` 改 .cshtml 即时生效，组件/模板开发**零重启**。

### （十九）鉴权体系分层

- API Key + Cookie 双通道、本地回环放行（AllowLocal）；
- ForwardedHeaders 反向代理头处理（保证代理后 RemoteIpAddress 为真实客户端 IP）；
- `PermissionFilter` 全局过滤器（API 401 / 页面跳登录）+ `IPermissionHook` 行级数据权限扩展点。

### （二十）零构建前端

所有 JS/CSS 为 UMD 本地文件，无 npm/Vite/Webpack 构建链路；改 `.cshtml` 即时生效，适合企业内部快速迭代。

### （二十一）产品体验层

- **双桌面壳**：Windows 拟物工作台 + macOS 拟物桌面（低代码平台里少见的"操作系统级"产品化体验）；
- **PageGen 页面生成向导**：选项目/选表/选字段 → 一键生成三屏页面；
- **SchemaLabel（93 条）**：字段中文名映射体系，字段语义无需业务方重复配置；
- **Emoji 图标体系** + 设计器组件库分类 + 容器子项拖拽排序。

## 二、改进建议

### 高优先级（影响稳定性 / 开发效率）

1. **错误处理与日志完善**
   - `SysLog` 已有 1034 条日志，但接口请求失败缺少结构化上报（目前主要打 console）；
   - 建议在 `DynCall.post/get` 统一加错误拦截器，失败自动上报；BlockApp 挂载失败显示带重试的错误占位 UI。
2. **dyn-core.js / dyn-debug.js 按需加载**
   - `dyn-debug.js`（约 98KB）生产环境也在加载；建议按环境条件注入；
   - `dyn-designer-*` 系列只在设计器页面加载，不全局加载。
3. **配置契约的 JSON 侧校验**
   - 手写侧已有 `DynNodeViewOptions` 编译期检查；建议 JSON 侧（设计器保存前）也做未知字段名警告，两端对齐。

### 中优先级（影响功能完整性）

4. **权限模型细化**
   - 按钮级权限（详情页删除按钮按 `authCode` 隐藏）、列级权限（按角色隐藏价格列）建议在 PageSetting 中声明，运行时自动生效。
5. **V2 BlockApp 生态扩展**
   - 现有 TabApp（V1）、KanbanBoard（非 BlockApp）逐步迁移为 V2 模式；补充 ChartApp（ECharts）、CalendarApp 等新 BlockApp。
6. **模板市场 / 示例库**
   - 21 个模板按"CRUD / 树形 / 看板 / 仪表盘"分类展示，附在线 Demo，支持 JSON 导入导出。

### 低优先级（长期优化）

7. **前端性能**：表格 >1000 行无虚拟滚动，页面首屏加载全部 UMD 依赖（约 1.5MB），建议虚拟滚动 + 懒加载。
8. **国际化**：文案硬编码中文，建议提取语言包。
9. **自动化测试**：核心 JS（getByPath/setPath/deepMerge/DynEventBus 快照）建议补单元测试，dyndata CRUD 补集成测试。
