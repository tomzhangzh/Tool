## 二、双渲染链路（核心设计）

### 2.1 前端模板模式（templateType = frontend）

```
后端仅返回 configJson + model
    → 前端 dyn-core 纯客户端 JS 渲染
    → 适用于弹窗、局部区块、简单卡片
```

### 2.2 后端 MVC 模板模式（templateType = backendMvc）

```
后端 Razor 服务端渲染 → 输出 HTML 片段 + 内嵌组件配置
    → 前端仅挂载 Vue 实例
    → 适用于权限过滤、服务端动态拼接、预查询数据
```

**V2 BlockApp 属于 backendMvc 模式**：每个 BlockApp 是独立的 Razor partial，服务端渲染好 HTML + dynconfig script，前端只负责挂载 Vue 实例和事件通信。

## 三、组件双定义源

### 3.1 设计决策

组件定义有两个来源，**Razor View 代码优先，数据库 ComponentMeta 回退**：

1. **Razor View**：`Views/Shared/Components/*.cshtml`
   - 三段标记：`<!--TEMPLATE_START-->` / `<!--SCRIPT_START-->` / `<!--STYLE_START-->`
   - 文件头元数据：`@* ComponentType: Page *@` / `@* RoutePath: /xxx *@`
   - 优势：代码即文档，Git 版本控制，改完刷新即生效

2. **数据库 ComponentMeta**：
   - 存储 TemplateContent / ScriptContent / StyleContent / PropertyConfigJson
   - 优势：运行时可编辑、可从设计器导出

### 3.2 加载流程

```
Layout 渲染
  → @await Component.InvokeAsync("DynComRegistry")
  → 序列化 DB 启用组件清单为 <script id="dyncom-registry">
  → 前端 vueLoadCom 用 new Function 解析 export default
  → 注册进全局 DynCom 对象
```

`ComponentService.GetDefineByName`：先查 Razor View（`RazorComponentRenderer` 正则提取三段），找不到再回退 DB。

## 四、V2 BlockApp 体系

### 4.1 设计动机

V1 的问题：
- 每个页面模板把树/列表/表单代码**内联**在 .cshtml 里，无法跨模板复用
- 跨 App 通信用 `DynBlocks.createBlockHandle` 句柄，弹窗脱离 DOM 后句柄丢失

V2 的改进：
- 每个 BlockApp 是**独立的 Razor partial**，标记 `dyn-init="createApp"`
- 通信统一走 `window.DynEventBus` + ExecId，不持有其他 App 引用
- 模板只管**组装**（传参）和**事件名转换**，不管业务逻辑

### 4.2 四个 BlockApp

| BlockApp | 职责 | 数据接口 |
|----------|------|----------|
| FilterApp | 查询表单 + 查询按钮 | 无直接数据，emit search |
| ListApp | 表格展示 + 分页 + 增删改 | `/api/dyndata/search` |
| DetailApp | 表单编辑 + 保存/删除 | `/api/dyndata/insert` / `update` / `delete` |
| TreeApp | 树形展示 + 拖拽排序 | `/api/dyndata/search` / `save` |

### 4.3 模板组装示例（TreeDetailV2）

```
TreeDetailV2.cshtml
  ├── .tr-root (data-exec-id=execId)
  │     ↓ DynEventBus.registerRoot(rootEl)
  ├── .tr-pane-left
  │     └── PartialAsync(AppsV2/TreeApp.cshtml, {ExecId, TableName, ...})
  ├── .tr-gutter (模板自管拖拽)
  └── .tr-pane-right
        └── PartialAsync(AppsV2/DetailApp.cshtml, {ExecId, DetailSettingId, ...})

模板 Scripts 段：
  mount(tEl) + mount(dEl)
  on(nodeClick) → emit(editForm, {row})
  on(addRoot)   → emit(newForm, {preFill:{}})
  on(addChild)  → emit(newForm, {preFill})
  on(saved)     → emit(reload, null)
```

## 五、DynEventBus 事件总线

### 5.1 设计

- 每个模板根 DOM 元素拥有一个独立 `execId`（GUID）
- 事件总线就是这个元素本身（`element.dispatchEvent(CustomEvent)`）
- 全局只维护一张 `Map<execId, rootElement>`，供弹窗跨 DOM 按 execId 找根节点

### 5.2 快照机制

时序问题用「快照」解决：
- `emit` 时把 payload 存在 `rootEl.__snap[eventName]`
- 晚注册的 `on()` 在读快照，有就立刻执行一次
- 解决了 BlockApp 挂载顺序不确定导致的事件丢失问题

### 5.3 API

```js
// 注册模板根
const execId = DynEventBus.registerRoot(rootEl);

// 发事件（存快照 + dispatch）
DynEventBus.emit(execId, 'nodeClick', { row: data });

// 监听（读快照补发一次 + addEventListener）
const off = DynEventBus.on(execId, 'editForm', (payload) => { ... });

// 解绑
DynEventBus.off(execId, 'editForm', handler);

// 销毁（清快照 + 删 Map）
DynEventBus.destroy(execId);
```

## 六、动作系统（dyn-action.js）

### 6.1 管道语法

```
dyn-click="ActionHelper.Submit|ActionHelper.Toast('保存成功')|ActionHelper.Reload"
```

- 用 `|` 分隔多个动作
- 按顺序执行，某步返回 `false` 则中止
- 上一步结果通过 `$result` 占位传递
- 支持 `$before` / `$onSuccess` / `$onFail` / `$after` 钩子

### 6.2 动作分类

| 类型 | 说明 | 示例 |
|------|------|------|
| 内置动作 | 代码注册 | submit / open / reload / toast |
| 入库动作 | DB DynActionHelper 表 | 脚本型 / API 型 / 链型 |
| 组合动作 | chain / switch | 多步业务流程 |

### 6.3 参数上下文（dyn-params.js）

统一的参数上下文链：
- L0：模板静态参数（ParamsJson）
- L1：页面参数（data-* 属性）
- L2：共享 scope（跨 App）
- 占位符：`{{params.xxx}}` / `{{model.xxx}}` / `$result.xxx`

## 七、免模型动态 CRUD

### 7.1 设计

后端不需要为每张业务表建实体类：
- `DynDataApiController` 接收 `{table, data, ...}` 请求
- 用 ADO.NET 动态拼 SQL（参数化防注入）
- 自动识别主键、字段类型

### 7.2 核心 API

| 端点 | 说明 |
|------|------|
| `POST /api/dyndata/search` | 分页查询（支持 where / order / pageSize / pageIndex） |
| `GET /api/dyndata/get?table=X&id=Y` | 按主键取单行 |
| `POST /api/dyndata/insert` | 新增 |
| `POST /api/dyndata/update` | 更新 |
| `POST /api/dyndata/save` | 保存（自动判断 insert/update） |
| `POST /api/dyndata/delete` | 删除 |
| `GET /api/dyndata/tables?project=X` | 列出项目下所有表 |
| `GET /api/dyndata/columns?table=X` | 列出表字段 |

## 八、设计器架构

### 8.1 核心能力

- **组件库**：左侧列出所有已注册组件，按分类分组
- **画布**：拖拽放置、缩放（0.25~1.5）、标尺、撤销重做（20步）
- **属性面板**：右侧编辑选中组件的配置
- **容器子项管理**：由 `ComponentMeta.designerMeta` 驱动，自动增删排序

### 8.2 设计态 / 运行态隔离

- 设计器所有交互逻辑运行态不存在
- 运行时 JSON 自动剔除 `designerMeta` / `designerOperates`
- 画布选中态、hover、预览切换 **不写入** ConfigJson

### 9.2 配置契约（ConfigJson DSL）

```json
{
  "component": "DynElContainer",
  "modelname": "",
  "options": {
    "comoptions": { "direction": "vertical", "size": "small" },
    "labeloptions": { "label": "", "show": false },
    "itemoptions": { "style": {}, "class": "" },
    "compassthrough": "comoptions.size,labeloptions.labelposition"
  },
  "validators": [],
  "childrenctrls": [],
  "slots": {},
  "extendinfo": {}
}
```

**铁律**：配置键名全小写无分隔（comoptions / labeloptions / itemoptions），运行时状态/方法不入此结构。

## 十、关键设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 前端构建 | UMD 无打包 | 零构建步骤，改 .cshtml 即生效，适合低代码平台 |
| 数据库 | SQLite 默认 | 免安装，首次启动自动建库；可切 SQL Server |
| 组件定义 | Razor View 优先 | 代码即文档，Git 版本控制；DB 回退运行时编辑 |
| BlockApp 通信 | DynEventBus | 解耦，弹窗跨 DOM 可通信，快照补发防事件丢失 |
| 动作系统 | 管道语法 | 声明式，可入库，可组合 |
| 参数上下文 | L0/L1/L2 链 | 支持模板静态参数、页面 data-*、跨 App 共享 |
| 配置契约 | 全小写下划线 | 与 SQL 种子、PageGen 生成器、设计器属性面板一致 |
