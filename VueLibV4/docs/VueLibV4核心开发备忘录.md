## 一、整体架构总览（核心灵魂）

VueLibV4 是 **.NET Razor + Vue3 混合渲染低代码引擎**。
区别于市面上所有纯前端低代码，**独有双渲染链路架构**。

### 1. 两大渲染模式（全局核心规则，不可破）

#### 1）前端模板 `templateType = frontend`
- 流程：后端仅返回 `configJson + model`
- 渲染：前端 `dyn-core` **纯客户端 JS 渲染**
- 适用：弹窗、局部区块、预览、简单卡片
- 特点：速度快、无 Razor 参与

#### 2）后端 MVC 模板 `templateType = backendMvc`
- 流程：后端先执行 **Razor 服务端渲染** → 输出 HTML 片段 + 内嵌组件配置
- 渲染：前端仅挂载 Vue 实例
- 适用：权限过滤、服务端动态拼接、预查询数据、动态下拉
- 独有优势：可以 C# 直接循环生成 DOM/Option，不依赖前端 AJAX

### 2. 全局最高铁律（整个系统的基石）

> **设计态临时状态，绝对禁止持久化、绝对禁止写入 PageSetting.ConfigJson**

以下所有状态 **只存在内存 Scope，不落库、不进快照、不影响运行态**：
1. Tab 设计态预览激活 `previewActiveTabKey`
2. 画布选中状态、Overlay 框
3. 设计器 hover、拖拽中状态
4. 预览模式开关

## 二、设计态 / 运行态 完全隔离规范（重中之重）

### 1. 隔离原则
1. 设计器所有交互逻辑，运行态完全不存在
2. 运行态业务逻辑，设计器不干扰
3. 两套状态完全独立，互不污染

### 2. 具体隔离落地
1. 组件通过 `pageCtx.designMode` 判断环境
2. 设计态 Tab 切换：仅修改 `previewState`，**不改原始 component JSON**
3. 运行态 Tab 切换：组件内部自有响应式状态
4. 下发运行时 JSON 时：**自动剔除所有设计器元信息**
   - `designerMeta`
   - `designerOperates`

## 三、ComponentMeta 组件元数据完整规范（系统核心范式）

### 新增字段固化（V4 标志性升级）
所有容器组件能力全部靠这套字段驱动，**零硬编码**。

### 1. `designerMeta` 通用设计器元信息（自动容器子项管理）

用于：系统自动生成「新增/删除/排序/拖拽子项」，无需写任何 JS 代码。

```json
{
  "isContainer": true,
  "childrenSchemaPath": "comExtra.tabs",
  "childKey": "tabKey",
  "childTitleField": "title",
  "supportDragSort": true
}
```

**关键字段解释**
- `childrenSchemaPath`：子项数组在组件 JSON 中的路径（核心）
- `childKey`：子项唯一主键
- `childTitleField`：子项显示名称

**已接入组件**
- DynElTabs：`comExtra.tabs`
- DynTable：`comOptions.columns`
- DynElCollapse：`childrenctrls`

### 2. `designerOperates` 组件专属扩展操作

位置：画布 Overlay「上移按钮前面」，两种类型，统一范式：

**类型1：command 内置命令（简单动作）**
例如：Tab 上一Tab、下一Tab 预览切换。

**类型2：view 自定义弹窗视图（复杂批量配置）**
目前三大标准弹窗：
1. `TableColumnConfigView` —— 表格列批量配置
2. `TabConfigView` —— 标签页批量改名、增删、排序
3. `CollapseConfigView` —— 折叠面板批量配置

### 3. 系统强制规则
1. **普通组件**：`designerMeta=null`、`designerOperates=null`
2. **容器组件**：必须配置 `designerMeta` 实现通用子项管理
3. **特殊容器**：追加 `designerOperates` 实现专属配置弹窗

## 四、四大容器组件统一开发范式（完全固化）

> Table / Tab / Collapse / 未来 Steps 全部统一这套流程。

### 标准开发步骤（新增任意容器组件通用模板）
1. ComponentMeta 配置 `designerMeta` 自动增删排序
2. 配置 `designerOperates` 挂载 view 弹窗
3. 编写对应 `XXXConfigView` 弹窗
4. 弹窗内**深拷贝数据副本**（不直接改原节点）
5. 确定：写回原组件节点、刷新画布
6. 取消：丢弃副本、无变更
7. **预览状态与数据状态严格分离**

### 统一能力（所有容器自带）
- 新增子项
- 删除子项
- 上移 / 下移排序
- 批量编辑属性
- 确定写回 / 取消丢弃

## 五、画布核心能力固化（已全部完成）

### 1. 撤销 / 重做（Undo / Redo）

**核心机制**
- 最大记录步数：20
- 仅**真实修改页面数据的操作**才存快照
- 临时预览操作 **不存快照**

**存入快照的操作**
- 新增、删除、复制组件
- 组件拖拽放置
- 所有容器子项增删改排序
- 批量配置弹窗确定保存
- 属性面板属性变更

**不存入快照**
- Tab 预览切换
- 画布缩放
- 预览模式切换
- 选中 / 取消选中

### 2. 画布缩放系统
- 范围：0.25 ~ 1.5
- 支持：工具栏滑杆 + Ctrl+滚轮缩放
- 核心技术：`transform: scale()` + **坐标反向换算**
- 保证：缩放后拖拽、选中、Overlay 框**绝对精准不偏移**

### 3. 预览模式
- 切换后隐藏所有 Overlay、操作按钮、禁止拖拽
- 完全模拟线上运行效果
- 保留标尺、缩放，方便整体布局查看

### 4. 标尺系统
- 横向标尺完整可用、跟随缩放
- 纵向标尺预留二期迭代

## 六、渲染层关键避坑记录（历史所有坑固化，永不重踩）

### Bug1：DynDynamicCom 快照污染（重大底层坑）
**问题**：组件 setup 阶段缓存 `jc` 快照，父节点数组更新后，子组件永远不更新。
**根因**：`const jc = props.jsonconfig` 一次性快照，不响应式。
**永久修复**：所有动态组件模板**禁止使用 setup 缓存 jc**，必须直接读取 `props.jsonconfig`。

### Bug2：容器子组件标题不刷新（Collapse 专属坑）
子组件内部缓存旧配置，父数组更新 UI 不动。
统一规范：**所有子组件展示字段直接链式读取 props，不缓存局部变量**。

### Bug3：缩放后坐标错位
所有鼠标位置、拖拽位置、Overlay 位置**必须除以当前缩放比例**。

### Bug4：设计态预览状态落库
全局铁律：preview 类状态**绝对不进 PageJson、不进快照、不落库**。

## 七、数据库核心表结构规范

### 1. PageSetting 页面主表核心字段
- `templateType`：frontend / backendMvc
- `authCode`：权限标识
- `paramJson`：页面参数
- `ConfigJson`：页面核心 DSL

### 2. ComponentMeta 组件元数据表扩展字段
```sql
designerMeta NVARCHAR(MAX) NULL
designerOperates NVARCHAR(MAX) NULL
```

### 3. 运行时自动过滤规则
下发前端运行时：**自动剔除两个设计器专属字段**，保证运行 JSON 干净、体积小、无冗余。

## 八、ActionHelper 动作引擎设计规范

### 设计理念
**尽量少手写 JS，全部配置化**。
- 页面动作存在 PageSetting
- 多组件共享 `shareModel`
- 实现三屏联动：筛选 → 列表 → 详情

### 内置标准动作
- `queryData` 数据查询
- `updateElement` 局部刷新（MVC 模板核心）
- `open` 打开弹窗页面
- `tabSwitch` Tab 切换
- `formValidate` 表单校验
- `assignModel` 变量赋值

## 九、前后端双模板调度核心逻辑（伪代码固化）

### 统一入口 `dynRender()`
1. 判断 `templateType`
2. frontend：拿 JSON + model 前端渲染
3. backendMvc：请求 Razor 视图 HTML 片段 → 挂载组件

### 局部刷新核心 `updateElement`
- 请求后端视图片段
- 替换指定 DOM
- 局部刷新、不整页刷新

## 十、所有组件开发统一约束

1. 所有设计态能力，运行态必须自动销毁
2. 所有设计器配置字段，运行态必须剔除
3. 修改组件数据必须走「快照保存 → 修改 → 刷新」
4. 容器子项修改**必须副本编辑，确认再落节点**
5. 禁止硬编码判断组件类型（全部元数据驱动）
6. 新增容器优先复用现有三套弹窗范式

## 十一、当前系统能力边界（哪些能、哪些不能、取舍逻辑）

### ✅ 完全成熟可无限扩展
- 任意表单组件
- 任意容器组件（Tab / Table / Collapse / Steps）
- 双模式渲染
- 设计态完整编辑能力
- 撤销重做 / 缩放 / 预览 / 标尺
- 属性穿透 comPassThrough

### ✅ 可实现（只差开发工程量，无架构障碍）
- 属性面板 showWhen 条件联动
- 页面模板、组件片段复用
- 细粒度权限控制
- 组件数据联动、事件联动
- 草稿 / 发布版本管理

### ⚠️ 架构取舍（天生边界，不做、也不需要做）
1. 不支持重度自定义 JS 脚本堆砌（保证系统稳定、业务整洁）
2. 不做超复杂表达式引擎（优先配置化、规范化）
3. 不做跨页面全局乱状态（页面隔离、结构清晰）

## 十二、最终全局开发守则（以后所有迭代必须遵守）

1. **绝不硬编码组件类型判断**，全部用 ComponentMeta 驱动
2. **设计态与运行态永久物理隔离**
3. **临时预览状态永久不落库**
4. **容器组件统一 designerMeta + view 弹窗范式**
5. **所有数据修改必先存快照**
6. **子组件永远直接读 props，不缓存快照变量**
7. **运行时 JSON 必须干净无设计垃圾字段**
8. **优先配置化，最后手写 JS**
