# V2 版本标记 + 动态参数面板 + 页面组成图（2026-10-13 ~ 2026-10-14）

> 范围：DynTemplate / DynBlock 的架构版本字段、V2 模板参数配置（ConfigJson）补齐、DynWebPage 编辑弹窗"参数配置"动态面板（可复用组件）、"页面组成图"X6 可视化（弹窗内嵌只读小图 + 独立大图，可递归展开子页面与事件总线连线）。
> 所有结论均锚定当前仓库代码与本地 Platform.db 实测数据；不涉及 git commit。

## 1. 背景与目标

平台的"壳模板（DynTemplate）+ 积木（DynBlock）+ 槽位装配（DynTemplateBlock）"V2 体系落地后，存在三个痛点：

1. **V1 / V2 模板混在一张表里，没有任何字段区分**。V2（LoadBlock + DynEventBus 槽位装配，17/18/19/20/21/22/24）与 V1 旧 DSL 模板只能靠 Id 记忆，无法在管理界面识别和维护。
2. **DynWebPage 的 `ParamsJson` 没有可视化编辑入口**。模板自身参数（如 tpl21 的 `Project`、`child.*`、`masterDetailSettingId`）和各槽位积木参数（`blocks.filter.settingId` 等）散落在 JSON 里，只能手工写；且不同模板/积木的参数定义（`DynTemplate.ConfigJson`、`DynBlock.ParamConfigJson`）部分缺失（如 tpl17 只有 DrawerWidth、tpl24 的 tabs 无编辑 UI）。
3. **V2 页面跨页面装配后"看不见全貌"**。一个业务页面由"壳模板 + 多个积木 + 各自 PageSetting"组成，`tabDialogPageId`、`childUrl` 还会递归跳到其他 DynWebPage（如 WP6 模板管理 → WP39 页签弹窗），积木之间靠 DynEventBus 的 query/create/update/saved 事件通信。这些关系只存在于 ParamsJson 和积木元数据里，排障与新人理解成本高，需要一张可视化组成图。

本次完成：

- DynTemplate / DynBlock 增加 **`Version`** 字段并回填数据，管理页可维护，面板有版本徽章；
- 新增**自包含、可复用的动态参数面板** `_WebPageParamsPanel`，按"模板 ConfigJson + 各积木 ParamConfigJson"自动生成表单，与 InspectorPanel 同源（`paramschema` 接口），支持宿主表单内嵌与 URL 独立两种模式；
- 新增 **页面组成图**：X6 图谱，递归展开"页面 → 模板 → 槽位/页签/弹窗 → PageSetting / 子页面"，并按积木 Events/Commands 元数据绘制事件总线连线；编辑弹窗内嵌只读小图、独立大图可点节点抽屉式编辑；
- 补齐 V2 模板的 ConfigJson 与 tpl21 的槽位关系；
- 修复面板与宿主 App 桥接的时序/根节点 bug。

## 4. 动态参数面板：设计与数据契约

### 4.1 三种使用形态

| 形态 | 入口 | 保存方式 |
|---|---|---|
| **宿主表单内嵌** | DynWebPage 编辑弹窗 → 参数配置 Tab（Detail_118 内 Partial） | 修改实时序列化进宿主 `form.ParamsJson`，随弹窗"保存"一并提交；无独立保存按钮 |
| **独立完整页** | 浏览器直访 `/Platform/Page/ParamsPanel?templateId=21&pageId=6` | 顶栏显示"独立模式"+"保存参数"按钮，直接 POST SaveParams 写库 |
| **裸片段注入** | 同 URL 加 `&raw=1`（XHR） | 返回不带布局的片段 HTML，供 ActionHelper.Load / updateEl 注入任意容器；挂载后同样可用独立保存 |

页面结构（内嵌与独立完全同一份 Partial）：

1. 顶栏：`模板：{名称}` + 蓝色 `Vn` 徽章；右侧模式提示 + 刷新 + 独立模式的保存按钮；
2. 折叠分组：
   - **基础参数**：TableName / KeyField / ChildFkField / ModalPageId；
   - **模板参数**：`dyn-dynamic-com` 渲染 `template.configJson`（空对象 `{}` 时整组不显示）；
   - **每个槽位一组**：标题 `🧩 {槽位中文名}（必选）`，右上角灰色 `{block.code} · Vn`，`dyn-dynamic-com` 渲染该积木的 ParamConfigJson，绑定 `pageParams.blocks[slot]`；
   - **原始 ParamsJson（高级）**：textarea 与表单双向同步，JSON 语法错误时保留文本不覆盖表单。

### 4.2 接口契约

**`GET /api/platform/dynwebpage/paramschema?templateId=21&pageId=6`**

```jsonc
{
  "code": 0,
  "data": {
    "template": { "id": 21, "code": "...", "name": "...", "version": 2,
                  "configJson": "{组件树 schema}", "defaultJson": "..." },
    "params": { /* 该 DynWebPage 已保存的 ParamsJson（含 blocks） */ },
    "slots": [
      {
        "slot": "filter", "slotName": "筛选区", "required": true, "sortNo": 1,
        "block": { "id": 1, "code": "filter", "name": "筛选积木", "version": 2,
                   "paramConfigJson": "...", "commands": [], "events": [] },
        "values": { "settingId": 110, "model": {}, "options": null }
      }
    ]
  }
}
```

`values` 由后端 `BuildSlotValues` 做**三层合并**：积木 `ParamDefaultJson` 默认值 → 实例 `blocks[slot]` 新结构 → 旧扁平键兜底，统一输出 `{settingId, model, options}`。

**`POST /Platform/Page/SaveParams`**：body `{ "webpageId": 6, "paramsJson": { ... } }`，整体覆盖写 `DynWebPage.ParamsJson`，返回 `{code:0}`。

### 4.3 ParamsJson 结构（面板保存的事实格式）

以 WP6（模板管理，tpl21）实测为例：

```json
{
  "TableName": "DynTemplate",
  "KeyField": "Id",
  "ChildFkField": "",
  "ModalPageId": null,
  "Project": "__platform__",
  "masterDetailSettingId": 112,
  "tabDialogPageId": 39,
  "child": { "table": "DynTemplateBlock", "foreignKey": "TemplateId",
             "listSettingId": 122, "detailSettingId": 123 },
  "blocks": {
    "filter": { "settingId": 110, "model": {} },
    "list":   { "settingId": 111, "model": {} },
    "detail": { "settingId": 112, "model": {} }
  }
}
```

关键规则：

- 模板参数取/存**顶层键**，支持点路径嵌套（`child.table`，由 `_BaseLayout` 的 fullModelName + lodash get/set 支撑）；
- 积木参数取/存 `blocks.{slot}`，下拉值是 `settingId`，其余在 `model`；
- **表单未定义的顶层键原样保留**（合并式写回，不重建对象），因此手工维护过的字段不会被面板冲掉。

### 4.4 宿主桥接机制（内嵌模式）

- 面板是 `dyn-init="createApp"` 的独立 App，GUID 容器 id；
- mounted 后每 100ms 轮询、最多 20 次（2s），沿容器节点的 `parentElement` 链向上找最近的带 `__dynProxy` 且含 `form` 的宿主；
- 找到后：缓存 hostForm，`$watch` 宿主 `form.TemplateId` / `form.Id`（选模板、新增保存拿到 Id 时自动重拉 schema），`watch.pageParams.deep` 实时 syncToHost；
- 2s 内无宿主：query 带 templateId 走独立模式加载，否则显示"请先选择壳模板"空状态。

## 5. 页面组成图（X6 可视化）

把一个 V2 页面的装配关系画成图：**WebPage 组框 → 壳模板 → 槽位积木 / 页签 / 弹窗 → PageSetting 或子 WebPage（递归）**，并叠加积木间的 DynEventBus 事件流连线。后端纯算坐标输出 X6 JSON，前端只负责渲染。

### 5.1 两个入口

| 入口 | 形态 | 交互 |
|---|---|---|
| 编辑弹窗 → **页面组成图** Tab（[Detail_118.cshtml L95-275](../src/VueLibV4.Web/ViewsAutoGenerate/Platform/DynWebPage/Detail_118.cshtml)） | 内嵌只读小图（460px 高），fetch `/Platform/Page/PageGraphData` | 只读（`interacting:false`）、Shift+拖拽平移、滚轮缩放、"刷新组成图"、"弹出大图" |
| **大图页** `GET /Platform/Page/PageGraphDemo?id=N`（默认 id=34，[PageGraphDemo.cshtml](../src/VueLibV4.Web/Areas/Platform/Views/Page/PageGraphDemo.cshtml)） | 独立页 720px 画布 + 节点/事件流双图例 | 可缩放平移；**点 wp/tpl/blk/ps 节点 → 右侧 55% 抽屉加载 DetailModalV2 片段就地编辑**；dyn 运行时不可用时降级浏览器新窗口 |

小图的加载时序（避免 X6 在隐藏容器里渲染成 0 宽）：

- 500ms 轮询，条件同时满足才渲染：容器 `offsetParent != null`（Tab 已激活）且 `data-wp-id`（绑 `form.Id`）有值——**新增页面必须先在"基本信息"保存出 Id**，未保存时显示引导文案；
- 切走 Tab 后重置 renderedId，回来自动重绘（display:none 下 X6 尺寸会失真）；轮询 5 分钟后自动停止省资源，手动刷新不受限。

### 5.2 图谱语义（WP6 实测：19 节点 / 12 边，递归到 WP39）

每个 WebPage 是一个蓝色虚线**组框**（标题 `📄 页面名 #Id · code`），组内固定三列布局：

```
┌─ 📄 模板管理 #6 · dyntemplate ─────────────────────────────┐
│  ┌──────────┐   ┌──────────────────┐   ┌─────────────────┐ │
│  │ 🧩 模板   │   │ 🔍 筛选积木       │──→ │ 🔒 PS #110 筛选 │ │
│  │ #21      │   │   slot=filter    │配 │   Filter_110…   │ │
│  │ filter-  │   │ 📋 列表积木       │──→ │ ⚙️ PS #111 列表 │ │
│  │ list-    │   │ 📝 明细表单积木   │──→ │ 🔒 PS #112 详情 │ │
│  │ tabbed   │   │ 📑 子表页签       │──→ │ ⚙️ PS #122/#123│ │
│  │          │   │ 🪟 编辑弹窗页签   │═══▶ 组框 📄 WP #39   │ │
│  └──────────┘   └──────────────────┘   └─────────────────┘ │
└────────────────────────────────────────────────────────────┘
          事件流：🔍筛选 ──query──▶ 📋列表 ──create/update──▶ 📝明细
                  📝明细 ──saved(红粗)──▶ 📋列表
```

**中列来源节点（5 类）**：

| 节点 | 颜色 | 数据来源 |
|---|---|---|
| 槽位积木 🔍筛选/📋列表/📝明细/🌳树/🧩 | 橙色；**非必选槽位虚线框** | DynTemplateBlock 关系表为准，`ParamsJson.blocks` 并集兜底（按 ImplementsRole / Code 反查积木；未注册积木显示"（未注册积木）"且不可点） |
| 📑 主信息页签 | 靛蓝 | `masterDetailSettingId`；与 detail 槽 settingId 同值时不重复画 |
| 📑 子表页签 | 靛蓝 | `child.{table,foreignKey,listSettingId,detailSettingId}` |
| 📑 childUrl 页签 | 靛蓝 | childUrl 正则匹配 `DynWebPage?id=N` → 子页面；其他 URL → 青色 🔗**自定义片段**节点 |
| 🪟 编辑弹窗页签 | 紫色 | `tabDialogPageId` → 递归子 WebPage |

**右列叶子**：

- **PageSetting**：紫色 ⚙️ 动态配置（1.5px 边框）；**🔒 红粗框 = 固定视图**（`GeneratedViewPath` 非空，或 RenderMode=Back 且有 PartialPath，标签附视图文件名，如 Detail_112.cshtml）；配置已删除则灰色 ⚠️；
- **子 WebPage**：向右偏移 800px 递归成新组框，同深度列用 `NextY[]` 防重叠；目标页面不存在画灰色缺失节点；
- **循环/复用引用**：已 Visited 的页面折叠为 `📄↩ 复用/循环引用` 虚节点，不再递归（深度无限但不出环）。

**边的语义**：

- 配置关系：紫色虚线，带文字标签（配置 / 主信息 / 子表-列表 / 子表-详情）；
- 子页面跳转：蓝色 2px 实线（编辑弹窗 / childUrl）；
- **事件流边**（`AddEventEdges`，只在同一组框的积木之间连，依据 `DynBlock.Events`（发）与 `DynBlock.Commands`（听）的交集）：
  - `query`：橙色 2.5px；
  - `create` / `update`：蓝色 2px（同对积木两个事件合并显示 "create/update"）；
  - `saved`：红色 3px。

**V1 / 无壳页面**：判定条件是 `tpl.ViewPath` 包含 `DynTemplates`（[ToolController.cs L151](../src/VueLibV4.Web/Areas/Platform/Controllers/ToolController.cs)）——**注意当前不是读 Version 字段**。不满足时返回 `isV2:false` + error，只画一个灰色 "V1 壳，不展开" 节点；小图显示红色错误遮罩，大图显示红框提示条。

### 5.4 大图节点就地编辑的接线

点实体节点 → `openEditDrawer(data)`：

1. 仅 `kind ∈ wp/tpl/blk/ps` 可编辑，且必须有 `modalId`（构图时预查 4 个内置弹窗页的 Id：`dynwebpage-modal` / `dyntemplate-modal` / `dynblock-modal` / `pagesetting-modal`）和 `rowId`；
2. 拉 `/Platform/Page/DetailModalV2?id={modalId}&rowId={rowId}&project={project}&execId={execId}` 片段，在 layer 右侧抽屉（55% 宽）中 `dyn.fetchPartial` + `dyn.html(holder, html, true)` 挂载 DetailApp；
3. **execId 必须有**：挂载前 `DynEventBus.registerRoot(holder)` 取 execId——DetailApp.mounted 首行无 execId 直接 return，rowId 数据回填不会执行；
4. detail 句柄 `on('cancel'|'saved')` 双保险关窗；抽屉 `end` 时 unmount App、`DynEventBus.destroy(execId)`、移除 holder。

### 5.5 依赖与技术要点

- 图形库：[wwwroot/lib/x6.js](../src/VueLibV4.Web/wwwroot/lib/x6.js)（本地 AntV X6，约 495KB，10/4 已入库，**非本次新增，无 CDN 依赖**）；
- **X6 父子嵌入顺序**：`graph.fromJSON` 按数组顺序 addCell，父组框必须先于组内节点——后端把组框节点 `Insert(groupStart)` 前插保证顺序，前端再遍历 `getParentId()` / `addChild()` 兜底；
- **脚本就绪时序**：浏览器直访时 `<script src="~/lib/x6.js">` 先于内联脚本；经 `dyn.html()` 片段注入时 dyn-core 会抽出全部 script、外部 src 串行 await onload 后再执行内联——两种入口都保证 `window.X6` 就绪；
- 坐标全部后端计算（常量 GRP_W=760、三列 x=16/236/486、子页面 CHILD_DX=800），前端无布局逻辑。

## 6. 如何使用

### 6.1 配置一个页面的参数（日常）

1. 打开 DynWebPage 管理列表（WP7），点某行"编辑"；
2. 弹窗切到**参数配置** Tab：
   - 基础参数：填表名/主键（弹窗类模板这两项常留空）；
   - 模板参数：按所选壳模板的 ConfigJson 自动出现（下拉数据源是 `/api/platform/pagesetting/all?type=List|Detail|Filter`）；
   - 各 🧩 槽位组：为每个积木选 PageSetting（如"模板管理 - 筛选区 #110"）；
3. 改完直接点弹窗的**保存**（参数实时写入，无需额外按钮）；也可在"原始 ParamsJson"里直接贴 JSON。
4. 切换"基本信息"里的壳模板，参数 Tab 会自动按新模板重拉。

### 6.2 在新窗口/其他容器里打开参数面板

- 完整页：`/Platform/Page/ParamsPanel?templateId={模板Id}&pageId={网页Id}`（pageId 可省略用于新增预览，但保存需要 pageId）；
- 片段注入：拉取时加 `raw=1`，HTML 注入容器后由宿主页面的 dyn 引导自动挂载。

### 6.3 维护模板/积木的架构版本

- DynTemplate：模板管理（WP6）编辑弹窗 → 架构版本下拉（固定视图 Detail_112）；
- DynBlock：DynBlock 管理 → 列表"版本"列、详情"架构版本"下拉（PS114/115）；
- 新建 V2 模板/积木时把 Version 选成 2，面板与 schema 即显示 V2 标识。

### 6.4 给新 V2 模板补"模板参数"编辑 UI

在 DynTemplate 管理里编辑 ConfigJson（或照迁移脚本构造），结构是 dyn 组件树 schema：

- 根：`{component:"DynElContainer", modelname:"", options:{comoptions:{direction:"vertical",size:"small"}, ...}, childrenctrls:[...]}`；
- 子节点常用组件：
  - 文本：`DynElInput`（modelname 如 `DrawerWidth`）；
  - 数字：`DynElInputNumber`（comoptions.min）；
  - 开关：`DynElSwitch`；
  - 选 PageSetting：`DynElSelect` + comoptions `{sourceType:"ajax", url:"/api/platform/pagesetting/all?type=List", valueKey:"Id", labelKey:"Name"}`；
  - 静态枚举（如 Version）：`{sourceType:"static", optionValues:[{value:1,label:"V1"},...]}`；
  - 数组（如 tpl24 tabs）：`DynElArray`（comoptions `{itemLabel:"页签", addable, removable, sortable}`，childrenctrls 为子项字段，modelname 自动改写为 `[i].字段`）；
  - 嵌套对象用点路径 modelname（`child.table`）；
- 模板没有自身参数时 ConfigJson 保持 `{}`，面板会隐藏"模板参数"组（tpl19 即是如此）。

各积木的槽位参数同理，写 DynBlock.ParamConfigJson（filter/list/detail/tree/table 五个已配置好）。

### 6.6 查看 / 编辑页面组成图

- **弹窗内**：DynWebPage 编辑弹窗 → 页面组成图 Tab。新增页面先在"基本信息"保存（需要 Id）；改完参数配置保存后点"刷新组成图"重拉；

## 7. 对项目的影响

### 7.1 兼容性

- **加列安全**：`Version INTEGER NOT NULL DEFAULT 1`，存量数据全部默认 V1，旧代码不读不写该列，无感知；
- **ParamsJson 合并式写回**：面板只覆盖它认识的键，未知键（历史手工数据、其他模板参数）原样保留；
- **paramschema 槽位兜底**：未登记 DynTemplateBlock 的旧实例 blocks 也能渲染编辑，不依赖关系数据补录；
- 端点 ParamsPanel 原来返回 Partial，直访无布局时不引导（裸 `{{ }}`）；现在默认返回完整视图，**要旧行为加 `raw=1`**——目前无已知调用方使用旧的直访方式；
- **页面组成图为纯新增只读视图**：两个新端点 + 一个新视图 + Detail_118 多一个 Tab，不改任何写路径；V1 页面、未保存的新页面都有明确空态，不影响基本信息/参数配置 Tab；构图只读元数据，失败也仅图区报错。

### 7.2 运行时行为

- Version 是元数据，不进入渲染分支，不影响现有 V1/V2 页面打开与保存；
- tpl17 弹窗尺寸从硬编码改为读 DrawerWidth/DrawerHeight（默认值与原硬编码一致 60%/80%），行为不变、可调；
- Detail_118 参数 Tab 从原来的静态/半静态配置改为动态面板，ExtJson/ExtViewPath 移入折叠，字段保存路径未变；
- 组成图 V2 判定以 **ViewPath 含 `DynTemplates`** 为准（非 Version 字段）——若以后新建 V2 模板的外壳不放在 Views/DynTemplates 下，会被判 V1；Version=2 但 ViewPath 不合规时图不展开（面板不受影响，面板只看 ConfigJson）。

### 7.3 管理与开发体验

- V1/V2 在列表、详情、参数面板三处可视、可维护；
- 新增壳模板/积木的参数编辑能力 = 写一份 ConfigJson/ParamConfigJson，**零面板代码改动**（dyn-dynamic-com 通用渲染）；
- paramschema 同时服务 InspectorPanel 与本面板，参数定义只有一处事实来源；
- 组成图让跨页面装配（tabDialogPageId / childUrl 递归）、积木事件总线接线（谁发 query、谁听 saved）从"读 JSON 脑补"变成一屏可见，且大图可直接点节点改配置，形成"看图 → 改配置 → 刷新验证"闭环。

## 8. 踩坑记录（复用前必读）

1. **`this.$el` 不一定是 DOM 元素**：dyn 引导以容器节点 `el` 调 `app.mount(el)`（[dyn-core.js L597](../src/VueLibV4.Web/wwwroot/dyn/dyn-core.js)），组件为多根片段时，`this.$el` 是占位**文本节点**（nodeType=3），其 parentElement 虽在容器内，但 App 方法里拿不到引导期的 `element` 形参。面板根节点必须在 dynconfig 执行期缓存 `element`（`this._rootEl`），再从 `_rootEl.parentElement` 向上找宿主——这是本次面板桥接失败的根因。
2. **Razor 里的 CSS `@media`** 会被当 C# 代码报 CS0103，必须写 `@@media`。
3. **dyn-el-select 的静态选项不能用裸 slot `<el-option>`**（组件模板只 v-for comInnerInfo.options），必须用 comoptions `sourceType:"static"` + `optionValues:[{value,label}]`。
4. **SqlSugar 仓储无 `FirstOrDefault()` 扩展**：用 `.Query(pred).ToList().FirstOrDefault()`。
5. **找宿主 form 不能取全文档第一个 `.__dynProxy`**：会命中内层 block App，其 form 是片段模型（只有 TableName/KeyField/blocks）；必须沿面板容器祖先链（或限定同一 layui-layer）找 DetailApp 的 `dyn-blk-detail`。
6. Vue3 `@click.stop` 必须绑函数不能绑 `true`（面板内用 `noop(){}`）；`:dyn-click` 接 JS 字符串且 Razor 中要转义反斜杠/单引号。
7. 浏览器自动化经验：dyn 片段异步挂载（外层 mount 后才依次挂子 App），真机验证要预留 5-6s 等待；browser_use 对长 IIFE 常回 undefined，读数据优先用页面快照文本。
8. **X6 组框 embed 必须父先于子**：`graph.fromJSON` 按数组顺序 addCell，子节点先到会挂不到 parent。后端构图先占 `groupStart` 位、组框构造完再 `Insert(groupStart)` 前插；前端仍要遍历 `getParentId()` + `addChild()` 兜底。
9. **X6 不能在 display:none 容器初始化**：el-tab-pane 未激活时容器 0 宽，画出来尺寸/坐标全失真。小图轮询 `offsetParent` 可见再 new Graph，切走 Tab 后销毁并允许回来重绘。
10. **大图抽屉编辑必须带 execId**：DetailModalV2 片段的 DetailApp.mounted 第一行就校验 execId，没有就 return，rowId 回填整段不执行；须先 `DynEventBus.registerRoot(holder)` 拿到 execId 拼 URL，关窗时对应 `destroy`。
11. **图谱判断 V2 用 ViewPath 而非 Version**：`tpl.ViewPath.Contains("DynTemplates")` 是当前构图前提；这是历史事实（组成图先于 Version 字段落地），两者口径后续应收敛（见第 10 章建议）。
