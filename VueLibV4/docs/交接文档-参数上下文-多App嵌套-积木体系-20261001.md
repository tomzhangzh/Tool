## 2. 规范一：统一参数上下文（怎么传参数）

实现：[dyn-params.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-params.js)，全局对象 `window.DynParams`；便捷入口 `dyn.params(el)`（[dyn-core.js L971](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-core.js#L971)）。

### 2.1 取值优先级（数字小者赢）

`ctx.resolveOne` 的实际查找顺序（[dyn-params.js L170-L201](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-params.js#L170-L201)）：

| 顺序 | 层 | 来源 | 说明 |
|---|---|---|---|
| 1 | L0 explicit | 调用点 one-shot 入参 | 链路内部使用 |
| 2 | L0 runtime | `ctx.set(k,v)` | 本上下文私有覆盖，影响本层及子孙，兄弟不可见 |
| 3 | L1 static | 容器静态声明（见 2.2） | `data-dyn-params` → dynparams script → `data-blk-config`，**后者覆盖前者** |
| 4 | shared | `ctx.commit(k,v)` | 跨 fork 共享实体层，全链同一个 reactive 引用，兄弟 tab 可见 |
| 5 | L2 model | 挂载元素 `el.__dynModel` | 本 App 的业务 model，按键命中才取 |
| 6 | L3 parent | 父 ParamContext | 沿片段注入/嵌套 App 链向上 |
| 7 | L4 url | `window.location.search` | **只在链根查一次**，全局兜底 |

### 2.2 参数声明的三种官方方式（L1 静态层）

```html
<!-- ① 属性：最常用，模板根节点声明页面级参数 -->
<div class="tsb-root" data-dyn-params='{"tableName":"Course","project":"7"}'>

<!-- ② 服务端渲染片段下发参数：直接子级 script（只认 :scope > script） -->
<script type="application/json" tag="dynparams">{"courseId":27}</script>
```

```js
// ③ Block 适配（自动，无需手写）：data-blk-config 整体并入 L1，
//    老 Block 零改动就进入统一参数链（dyn-params.js readBlkConfig）
```

Razor 侧写 JSON 一律走 `DynPageViewHelper.SafeJson(jObject)`（转义 `</`），参考 [TriScreenBlocks.cshtml L64-L71](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/Views/DynTemplates/TriScreenBlocks.cshtml#L64-L71)。

### 2.3 怎么取值

```html
<!-- 模板内：响应式视图，shared/父层变化时跟随型表达式自动更新 -->
<div>当前课程：{{ $params.courseId }}</div>
<div>行内插值：{{ '/api/x?id=' + $params.id }}</div>
```

```js
// JS / dynconfig 内

ctx.get('form.Name');                   // 支持点路径

ctx.inspect();                          // 调试：每个 key 的值 + 获胜层（L1:static/shared/L4:url…）

// Vue setup 内（core 已 provide）：
// const p = Vue.inject('dynParams'); p.get('x')
```

### 2.4 派生（fork）、发布（commit）、跟随（watch）

```js
// 片段/tab/弹窗挂载点：从父链派生，localParams 是该点一次性入参
parentCtx.fork(holderEl, { rowId: 27 });
// dyn.html 注入时可显式指定父上下文（按钮与注入目标不在同一 DOM 子树时）：
dyn.html(paneEl, html, true, { parentCtx: ctx, local: { mode: 'edit' } });

ctx.commit('courseId', newId);   // 发布到共享层：链式各 fork/兄弟 tab 立即可见
ctx.set('rowId', 27);            // 私有覆盖：仅本上下文及子孙可见
```

**快照型 vs 跟随型**（Tabs 场景的核心语义，Demo 见 [TabsParams.cshtml](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/Views/Platform/Demo/TabsParams.cshtml)）：

- **快照型**：挂载时 `ctx.get()` 取一次值，上游之后变化与我无关（默认行为）。
- **跟随型**：挂载点声明 `data-dyn-watch-params="courseId,mode"`，键变化时该元素派发冒泡事件 `dyn-param-changed`（`detail:{key,value,oldValue}`），编排方 `addEventListener` 决定是否重新加载（[dyn-core.js bindParamWatchers L341-L351](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-core.js#L341-L351)）；也可用 `ctx.watch(keys, cb)` 编程订阅。

**跨容器流动参数必须是具名实体**（`courseId`、`rowId`），禁止用裸 `id`——多 Block 同页时裸 id 必然串值。

### 2.5 动作里的参数语法（`$params` / `$model` / `$result`）

动作 `options` 在构建时自动经触发元素所属 ctx 解析（[dyn-action.js buildCtx L356-L394](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-action.js#L356-L394)）：

| 写法 | 语义 |
|---|---|
| `"$params.courseId"` | **整串 token**：替换为原始类型值（数字还是数字）；缺失时保留原串，链路产生 `$result` 后自动重解析 |
| `"$model.form.Name"` | 取本 App model |
| `"$result.data.Id"` | 动作链上一步结果；未产生时保留原串 |
| `"x={{$params.id}}"` | 行内插值，字符串化；缺失保留占位 |

**URL 参数约定（重要）**：URL query 对全层可见（L4 兜底），但**不会自动随请求发送**——只有在动作里显式写 `$params.x` / 放进 `options.params` 才会进请求体/querystring。不要假设"URL 上有什么接口就收到什么"。

### 2.6 `setparams` 动作（后端保存后回写参数的官方通道）

前端定义见 [dyn-action.js L854-L891](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-action.js#L854-L891)。保留键：`scope / params / key / value`。

```js
// ① 平铺：除保留键外全部写共享层（默认 scope=shared → commit）
{ action:'setparams', options:{ courseId: "$result.data.Id" } }
// ② 单键
{ action:'setparams', options:{ key:'courseId', value:27 } }
// ③ 批量
{ action:'setparams', options:{ params:{ rowId:27, mode:'edit' } } }
// ④ 私有层（仅本上下文及子孙）
{ action:'setparams', options:{ scope:'local', params:{ rowId:27 } } }
```

后端在 `ApiResult` 的 `dyn-actions` 数组里下发即可（无需 C# 专门方法，拼 JSON 就行），前端响应后自动执行：

```json
{ "success": true, "data": { "Id": 27 },
  "dyn-actions": [ { "action": "setparams", "options": { "courseId": "$result.data.Id" } } ] }
```

> buildCtx 会自动把触发元素的非 `data-dyn-*` 的 `data-*` 属性收进 params；setparams 已通过 `__elParams` 标记把这些自动收集键（如 `data-v-app`）过滤掉，不会污染参数层。

## 3. 规范二：多 Vue App 嵌套（dyn-core）

### 3.1 挂载模型（主干规则）

- 根标记：`data-dyn-mode="createApp"`；待引导节点可先写 `data-dyn-init-createapp`，由 `initActions` 扫描后补标记。
- `dyn.mount(el)` 流程（[dyn-core.js mountCore L414-L537](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-core.js#L414-L537)）：
  1. 幂等：`el.__dynApp` 直接返回；并发挂载共享同一个 `el.__dynMounting` Promise；
  2. **先建参数上下文** `DynParams.ensure(el, parentEl)`（必须在掩码前，L1 要读直接子级 dynparams）；
  3. `maskNested`：把**直接嵌套**的子 App 节点临时搬进 `#dyn-holder`，原位留 `<dyn-host data-dyn-uid>` 占位（避免子 App 模板被父 Vue 先编译）；
  4. 删本 App 自身 script → 父 App `createApp().mount()`；
  5. **`for...of await` 逐个**按 uid 重查渲染后的 liveHost，把子节点还原并递归挂载（异步组件注册竞态靠串行解决）；
  6. 绑定 `data-dyn-watch-params` / 检查 `data-dyn-require-params` → `initActions` → `DynBlocks.scan` 收集句柄。
- 挂载失败走 `rollbackMasked`：销毁半成品 app、节点从 holder 还原回占位符。

### 3.2 卸载与台账

- `registerApp` 维护 `el.__dynChildApps`（Set）/ `el.__dynParentAppEl`；`unmount` 先按**台账级联**（子 App 可能已脱离 DOM、滞留在 holder），再用 DOM 查询兜底旧节点，最后销毁参数 ctx（[L773-L798](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-core.js#L773-L798)）。
- 取实例：`dyn.getApp(el)`、`dyn.getModel(el)`、`el.__dynProxy`。

### 3.3 片段注入：`dyn.html(el, html, boot, bootInfo)` 的 boot 生死线

| 场景 | boot | 原因 |
|---|---|---|
| `open` / `updateEl` 直接注入片段 | `true`（默认） | 内部先 unmount 旧内容、fork 参数链、注入后立即 initActions + scan 句柄 |
| `render` / `reload` / `data-dyn-url` 远程片段后还要走 `mount()` | **必须 `false`** | 否则内嵌 App 被提前挂载，与 mountCore 掩码递归冲突，产生**孤儿 App/双挂载** |

### 3.4 两条铁律（模板/Block 开发）

1. **两个 App 的 DOM 子树必须不相交**：Block 容器不能放进某个 App 的受管模板内部（其 `v-*`/`{{}}` 会被外层先编译）。栏布局用普通 div。
2. **往活 App 里注入内容必须用官方注入点** `<dyn-inject-host name="x"></dyn-inject-host>`（Vue 不 diff 其内命令式子节点，外层重渲染不会抹掉注入内容）。往普通元素注入会有开发态告警（`warnIfUnsafeInject`，每元素一次）。

### 4.4 Block 协作契约：实例句柄（不是事件总线）

实现 [dyn-blocks-common.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/blocks/dyn-blocks-common.js)。Block 挂载后在容器上暴露 `element.__dynBlock`：

```js
handle.send(cmd, payload)   // → Promise；命令未注册/已销毁则 reject
handle.on(evt, fn) → off    // 订阅，返回注销函数
handle.emit(evt, payload)   // Block 内部发事件
handle.reg(cmd, fn)         // Block 内部注册命令
handle.introspect()         // {destroyed, commands:[], events:[]}
handle.destroy()            // beforeUnmount 必须调；之后全静默，防悬垂订阅
```

| Block | 命令 send | 事件 emit |
|---|---|---|
| filter | — | `changed {字段:{op,value}}` |
| list | `loadData {filter}` / `reload` | `add {}` / `edit {row}` / `addChild {row}` |
| detail | `newForm {preFill}` / `editForm {row}` | `saved {action,row}` / `cancel {}` |

**边界规则**：

- Block mounted 只做自身初始化（首屏加载/rowId 回填），**不得 emit 外事件**；外事件只能由用户交互触发——模板 `await` 全部 mount 后才接线，接线必然先于事件。
- Block 内**不写 layer.close、不发 window 事件、不带 modal 标志**：保存成功只 `emit('saved')`。关不关窗、刷不刷新是编排层的事。
- 请求收口在 `DynBlocks`：按 URL 前缀 `/api/platform/` 区分平台库（扁平实体）与业务库（`{table,data,project}`），Block 内不写分支；统一走 `DynCall.post` 解包信封。

### 4.5 模板 = 纯布局 + 薄接线

模板默认不是 App。范例 [TriScreenBlocks.cshtml](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/Views/DynTemplates/TriScreenBlocks.cshtml)：Razor 拼三个 Block 的 `data-blk-config` → 输出纯 HTML 卡片（互不相交）→ Scripts 段 `Promise.all([dyn.mount…]).then(接线)`：

```js
filter.on('changed', p => list.send('loadData', { filter: p }));
list.on('add',      () => detail.send('newForm', { preFill: {} }));
list.on('addChild', p  => detail.send('newForm', { preFill: childPreFill(p.row) }));
list.on('edit',     p  => detail.send('editForm', { row: p.row }));
detail.on('saved',  () => list.send('reload'));
```

弹窗形态：`detail-modal` 是**零 JS 片段**，宿主负责拉片段 → 注入 layer → mount → scan 接线；遵循"**谁注入，谁编排**"，不用任何 window 全局事件。

模板自身需要动态 UI 时（如 tree-detail 左树）可建 App，但必须与各 Block **平级**、DOM 子树不相交，通过自己容器上的 `data-blk-role` 句柄协作。

## 6. 开发与调试纪律

- **JS 改动后 bump 版本**：[dyn-lib.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-lib.js) 的 `version`（当前 `4.4.1`），否则浏览器缓存旧文件；验证时强刷或加 `&nc=时间戳`。
- **cshtml 热重载**：Razor RuntimeCompilation，cshtml / sqlite / 静态 JS 改完刷新即生效；但 cshtml 内 JS 的 `@` 必须写成 `@@`。
- **C# 改动需编译重启**：先停掉锁 dll 的旧站点进程 → `dotnet build` → `dotnet run --no-build --urls http://localhost:5010`（工作目录 `src/VueLibV4.Web`，否则 WebRootPath 找不到）。
- **弹窗/提示**：`dyn.showMessage` 走 layui layer.msg（选择器 `.layui-layer-content`，约 2.2s 消失），自动化断言不要找 `.el-message`。
- **参数调试**：`dyn.params(el).inspect()` 看每个键的值与获胜层；Block 调试用 `el.__dynBlock.introspect()`。
- **后端约束**：所有中间件/action 用 async/await；强类型平台库访问走自动注入的平台服务，`DbFactory` 仅限运行时表名/动态库/临时连接三场景；Razor 视图不编译进 dll。
- **种子 SQL 方言**：现有种子为 SQLite 方言，适配 SQL Server 需手工改写。
