# 权限管理模块使用文档

> 版本：2026-10-05
> 适用：VueLibV4 低代码平台

---

## 1. 概述

平台内置轻量级 RBAC（基于角色的访问控制），设计原则：

- **面向 .NET 程序员**，不是业务人员，配置极简
- **两层控制**：页面级 + 字段级，不做 Block 级（Block 继承 WebPage）
- **动态 Model 自动受管**：免 Controller，权限打在表元数据上
- **前后端双重校验**：前端做 UI 显隐，后端 AOP 做真正安全校验
- **业务可扩展**：`IPermissionHook` 接口支持行级数据权限等自定义逻辑

---

## 2. 数据模型

### 四张表

| 表 | 作用 |
|---|---|
| SysRole | 角色（Name + Remark + ProjectId） |
| SysUserRole | 用户-角色映射（UserName + RoleId） |
| SysResource | 资源目录树（ParentId 串树） |
| SysResourcePermission | 角色授权（Read/Edit/Delete 三个 bool） |

### SysResource 字段

| 字段 | 说明 |
|---|---|
| Id / ParentId | 主键 + 父节点，串成树 |
| Key | 权限编码，如 `Customer.List.Export` |
| Name | 中文名，如"客户列表导出" |
| Type | Module / Menu / Page / Operation / Field |
| HasRead / HasEdit / HasDelete | 这个资源支持哪几个权限位 |
| **TableNames** | **绑定的数据库表名（逗号分隔），动态数据接口按表名反查** |
| SortNo | 排序 |

## 3. 后端使用方式

### 3.1 打特性标记

```csharp
using VueLibV4.Web.Core;

// 类级别：整个 Controller 需要某资源的 Read 权限
[ResourcePermission("Customer.List", "Read")]
public class CustomerController : ControllerBase
{
    // 方法级别：导出按钮需要 Edit 权限
    [OperationPermission("Customer.List.Export")]
    public IActionResult Export() { ... }

    // 方法级别：显式声明需要 Delete
    [ResourcePermission("Customer.List", "Delete")]
    public IActionResult Delete(int id) { ... }

    // 跳过校验（登录即可访问）
    [AllowAnonymousPermission]
    [HttpGet("public-info")]
    public IActionResult PublicInfo() { ... }
}
```

### 3.2 动态表级权限（免 Controller）

不需要写代码，直接在 SysResource 表里配置 `TableNames`：

```
Key: Customer
Name: 客户管理
Type: Module
TableNames: Customer,CustomerContact,CustomerAddress
HasRead: true, HasEdit: true, HasDelete: false
```

然后所有 `/api/dyndata/*` 请求自动校验：

| 请求 | 校验级别 |
|---|---|
| POST /api/dyndata/search | Read |
| GET  /api/dyndata/get | Read |
| POST /api/dyndata/insert | Edit |
| POST /api/dyndata/update | Edit |
| POST /api/dyndata/save | Edit |
| POST /api/dyndata/delete | Delete |
| POST /api/dyndata/batch | Edit |

**未绑定 TableNames 的表 = 不限制**（向后兼容，不阻塞现有开发）。

### 3.3 业务项目扩展（行级数据权限等）

```csharp
public class MyProjectPermissionHook : IPermissionHook
{
    public bool? Check(string resourceKey, string userName, string level)
    {
        // 返回 null = 走默认 RBAC 逻辑
        // 返回 true = 强制放行
        // 返回 false = 强制拒绝

        // 示例：只允许看自己部门的数据
        if (resourceKey == "Customer.List" && level == "Read")
        {
            var userDept = GetUserDept(userName);
            return userDept == "Sales";
        }
        return null;
    }
}
```

注册到 DI：
```csharp
builder.Services.AddScoped<IPermissionHook, MyProjectPermissionHook>();
```

## 4. 前端使用方式

### 4.1 自动扫描（已内置）

`dyn-permission.js` 页面加载后自动执行：
1. 调 `/api/platform/permission/me` 拉当前用户权限清单
2. 存到 `sessionStorage`
3. 扫描所有 `data-permission-*` 属性，无权限的元素自动 disable / 隐藏 / 只读

### 4.2 标记按钮

```html
<!-- 无权限就 disable -->
<button data-permission-op="Customer.List.Export">导出</button>

<!-- 无权限就整个隐藏 -->
<button data-permission-op="Customer.List.Delete" data-permission-mode="hide">删除</button>

<!-- 字段无 Edit 权限就只读 -->
<input data-permission-field="Customer.Price" />
```

## 5. 管理页面

**地址：** http://localhost:5010/Platform/Page/PermissionAdmin

### 5.1 资源管理（右边上）

- **扫描代码注册新资源**按钮：自动扫描程序集里的 `[ResourcePermission]` 特性
- 新扫描出来的资源自动归到 **"未分配"** 父节点下
- 人工编辑：
  - **名称**：改成中文
  - **绑定表名**：填逗号分隔的表名，这个节点就自动管这些表
  - 拖拽或改 ParentId 把节点挪到对应模块下

### 5.2 角色授权（左边树）

1. 顶部选角色
2. 左边资源树里勾权限：
   - 勾 **Edit** → 自动勾 Read
   - 勾 **Delete** → 自动勾 Read
   - 取消 Read → 自动取消 Edit/Delete
3. 点 **保存授权**

### 5.3 用户管理（右边下）

- 输入用户名 → 加到当前角色
- 角色下的用户列表 → 可移除
- **一个用户可以属于多个角色，权限取并集**

### 5.4 新建角色

顶部"新建角色"按钮，填角色名和备注即可。

## 6. 接口清单

| 接口 | 说明 |
|---|---|
| GET  /api/platform/permission/me | 当前用户权限清单 |
| GET  /api/platform/permission/roles | 角色列表 |
| POST /api/platform/permission/role/save | 新建/编辑角色 |
| POST /api/platform/permission/role/delete | 删除角色 |
| GET  /api/platform/permission/resources | 资源树扁平列表 |
| POST /api/platform/permission/resource/save | 新建/编辑资源 |
| POST /api/platform/permission/resource/scan | 扫描代码注册新资源 |
| GET  /api/platform/permission/granted?roleId= | 查角色已授权 |
| POST /api/platform/permission/grant | 保存授权 |
| GET  /api/platform/permission/userroles?roleId= | 角色下的用户 |
| POST /api/platform/permission/userrole/add | 加用户到角色 |
| POST /api/platform/permission/userrole/remove | 从角色移除用户 |

---

## 7. 特殊说明

- **admin 用户**：默认超管，所有权限放行（开发期不阻塞）
- **多角色合并**：用户属于多个角色时，权限取并集（任何一个角色有就放行）
- **ProjectId**：SysRole 和 SysResource 都有 ProjectId，支持按项目隔离角色
- **SQLite 列名**：Delete 是保留字，数据库列名用 `CanDelete`，C# 属性名仍是 `Delete`（加了 `[SugarColumn(ColumnName="CanDelete")]`）

## 8. 快速上手示例

### 场景：给"业务员"角色配置客户表只读权限

1. 打开权限管理页面
2. 新建角色：业务员
3. 点"扫描代码注册新资源"（如果代码里打了特性）
4. 或者手动新建资源：
   - Key: `Customer`
   - 名称: 客户管理
   - 绑定表名: `Customer,CustomerContact`
   - HasRead: true, HasEdit: false, HasDelete: false
5. 选"业务员"角色
6. 在资源树里勾 Customer 的 Read
7. 保存授权
8. 把业务员账号加到这个角色

**效果：**
- 业务员查客户表 → 放行
- 业务员改客户表 → 403
- 前端"导出"按钮自动 disable
