## 一、总体结论

**V4 完成了"内核重构"，但 V1 的"业务外壳"大部分尚未回迁。**

| 维度 | V1 | V4 现状 | 完成度 |
|------|----|---------|--------|
| 渲染内核 | nutLoadCom + 运行时模板编译 | h() 函数式 DynRender，cfg 驱动 | ✅ V4 更先进 |
| 数据访问 | 项目专用 DynCrudService | 通用免模型 DynamicCrudService（10 种 filter） | ✅ V4 更通用 |
| ElementUI 组件库 | ~50 个 | ~71 个（含新增） | ✅ 已超越 |
| 设计器画布 | lc-node 包装 DOM | overlay 悬浮层，不干扰布局 | ✅ V4 更先进 |
| 设计器功能闭环 | 完整（保存/预览/导入导出/动作链） | **仅画布可用，保存/预览未接线** | ⚠️ ~40% |
| 平台管理界面 | 9 个管理页面 | **0 个（只有 API）** | ❌ 0% |
| 移动端 NutUI | ~40 组件 + 手机壳预览 | 无 | ❌ 0% |
| 三屏运行时（DynRun） | 完整（汇总/明细/筛选/列表/树） | 无 | ❌ 0% |
| 开箱数据 | 完整 SQL 脚本（48+ 个） | 平台表有，**业务库无建表无种子** | ❌ 断点 |

## 六、V4 相比 V1 的增强（已确认，不要回迁倒退）

回迁 V1 功能时注意保留这些 V4 优势：

1. **SQLite 默认零依赖** + DbFactory 按连接串特征自动识别 SQLite/SqlServer，相对路径自动解析
2. **通用免模型 CRUD**：DynamicCrudService 的 10 种 filter op（eq/neq/gt/ge/lt/le/like/notlike/in/between）+ 按列 DataType 自动类型转换 + 分页上限保护，比 V1 的项目专用实现更通用
3. **h() 函数式渲染**：不编译模板，设计态/运行态同一份 cfg，无运行时编译器依赖
4. **WeakMap scope 共享**：替代 V1 的全局 `window.LCDesignerStore`，多页隔离性更好
5. **overlay 悬浮选中层**：不包装 DOM，flex/grid 布局零干扰（V1 的 lc-node 包装曾导致布局偏差）
6. **calc 计算动作**：支持 +=、-=、*=、/= 与四则运算（V1 无）
7. **Seeder 幂等自愈初始化**：缺组件时自动清表重跑种子
8. **DYN_LIB_CONFIG 按需裁剪**：可关 Layui/ElementPlus/Tailwind/CodeMirror
9. **去 jQuery**：dyn-core 纯 Vue + axios（V1 动作系统强依赖 jQuery）
10. **组件新增**：DynEChart / DynCombination / DynForm / DynGridContainer / DynElCollapse(Item) / DynOpenWindow / DynWrapper / DynSlot / DynText / DynCodeMirror 等为 V4 新增

## 八、建议的回迁顺序

```text
P0 数据断点（1-2 天）
  business.sql + 种子 → 保存链路 → validator 加载 → 桌面 bug
        ↓
P1 设计器闭环（3-5 天）
  预览 → 事件Tab → 模板Tab → 3个管理页 → undo/redo → 组合组件 → 相对绑定
        ↓
P2 管理与体验（1-2 周）
  动作链编辑器 → 桌面窗口 → 组件/工程/字典管理 → HTML生成 → 属性设计器
        ↓
P3 大模块（按需立项）
  NutUI 移动端  ‖  DynRun 三屏运行时（可并行，建议三屏用 V4 h() 内核重建）
```

**关键原则**：P3 的 DynRun 回迁不要照搬 V1 的"服务端 PartialView + jQuery 局部刷新"模式——V4 已有 h() 渲染器和 DynamicCrudService，三屏应当用 cfg + JSON API 重建，只借 V1 的 ColumnDefs 数据模型设计。
