## 1. 验收范围

### 1.1 M1 打通底座

1. 内核统一：移除 `dyn-render.js`，组合/弹窗类组件统一使用 `DynDynamicCom`
2. 动作系统：`dyn-click="ActionHelper.A|B"` 管道语法、`updateEl` 页面分块局部刷新
3. layui layer 统一：open/close/toast/confirm 弹窗与消息
4. `ApiResult` 增加 `dyn-actions` 通道，后端可下发前端动作链
5. 数据库动作助手（DynActionHelper）从平台库加载并动态注册

### 1.2 M2 数据组件

1. `DynCommonController`：options / dicts / tablelist / upload 四类公共接口
2. 8 个数据型组件适配统一 code 信封，数据源支持 static / dict / table / ajax
3. BusinessDb 初始化：Student/Course/BusinessDict 建表与 12 名学生种子
4. PlatformDb 追加种子：业务项目、字典、桌面快捷方式、网页登记、组件注册、演示动作
5. 免模型 CRUD Demo 端到端可用

## 6. 验收中发现的缺陷与修复记录

验收过程中共发现 **8 项缺陷**，均已修复并回归通过：

| 编号 | 严重级 | 缺陷 | 根因 | 修复 | 回归 |
|---|---|---|---|---|---|
| BUG-01 | 高 | 7 个页面（Crud/ActionHelper/4 个 Demo/WebPageRender/Designer）报 `Vue is not defined`，整个页面不渲染 | 内联 IIFE 在 dyn-lib 异步加载完 Vue 前同步执行（历史遗留） | 全部改为 `DynLib.ready(function(){...})` 包裹 | ✅ 页面正常挂载 |
| BUG-02 | 高 | DynCrudPage 组件加载不到，Crud 表格区空白 | ComponentMeta 无该组件注册，异步加载器查不到 define | seed-extra.sql 幂等补注册（ViewPath 指向 Razor 定义） | ✅ define 接口返回成功 |
| BUG-03 | 高 | 组件脚本解析失败 `Identifier 'comExtra' has already been declared` | DynCrudPage setup 与 _ContainerLayout 基座重复 `const comExtra` | 改为 `Object.assign(comExtra, {...})` | ✅ 组件渲染成功 |
| BUG-04 | 中 | ComCheckboxGroup/ComLookup 存在同类 comExtra 重复声明隐患 | 同上 | 同步修复；ComLookup 顺带重写为 layer 弹窗 | ✅ 编译/运行通过 |
| BUG-05 | 高 | ActionHelper 页 `DynActionHelper.loadAll is not a function`，动作列表为 0 | dyn-action.js 中 DB 加载函数是空桩 | 实现 loadDbActionHelpers + registerDbAction，支持 script/url/api/chain 四类，启动自动拉取 | ✅ 列表 5 行、chain/script 执行通过 |
| BUG-06 | 中 | 修改 Razor View 后浏览器仍使用旧组件定义 | define 响应被 HTTP 缓存 | 组件/动作请求加 `cache:'no-store'`，dyn-lib 版本 4.0.0→4.0.1 | ✅ 新代码即时生效 |
| BUG-07 | 高 | DynCrudPage 渲染正常但表格 Total 0、不发查询 | Demo 页以裸 props 传参，组件契约是 `:jsonconfig` | Demo 改为配置驱动，comoptions 内声明 table/project/columns/searchFields/formFields | ✅ 12 行加载成功 |
| BUG-08 | 中 | dyn-core `const _uidSeq=0` 自增异常；dyn-com `_regPromise` 声明在函数内致注册缓存失效 | M1 改造时的语法/作用域错误 | 改 `let`；提为模块级变量 | ✅ 组件注册正常 |

## 7. 遗留问题与风险评估

| 编号 | 项 | 级别 | 说明与建议 |
|---|---|---|---|
| R-01 | 不存在的表抛 HTTP 500 完整堆栈 | 低 | `tablelist?table=NoSuchTable` 时 DynamicCrudService 异常未被转成 ApiResult 信封（Development 异常页含堆栈）。options 入口有字段白名单，主链路不受影响。**建议**后续里程碑加全局异常中间件，统一输出 `{code:500,msg}` 并在生产关闭异常页 |
| R-02 | CRUD 保存/物理删除未做浏览器落库实测 | 低 | 为保护验收库，弹窗均点"取消"，未实际提交。后端 save/insert/update/delete 属 M1 前已存在能力，本轮只做了查询链路；**建议**下阶段用独立测试库补增删改回归 |
| R-03 | updateEl / open(iframe) / api 类动作无端到端页面 | 低 | 本轮标注"静态走查通过"，待 M3 动态网页场景承载后补实测 |
| R-04 | DynCrudPage 表单弹窗仍是 el-dialog | 低 | 原则 4 要求弹窗统一 layer；M2 目标是"数据先通"，ComLookup 已改 layer，CRUD 编辑窗计划下阶段替换 |
| R-05 | runJsonActions 为 fire-and-forget | 低 | 多个 dyn-actions 并发执行（forEach 不 await），顺序敏感场景需走管道 runPipe；实施规划中已明确本轮不改 |
| R-06 | 仅实测 SQLite | 中 | DbFactory 已具备 SqlServer 切换能力但本轮未在 SqlServer 环境验证；上线前需补一轮 SqlServer 兼容性测试（分页/参数/表结构查询） |
| R-07 | dyn-designer.js 仍有 DynRender 引用 | 信息 | 该文件是死代码、不在 DYN_MODULES 加载列表，不影响运行；建议后续清理 |
