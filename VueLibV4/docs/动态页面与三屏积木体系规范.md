## 1. 总览：四层模型与职责划分

系统把「动态页面」拆成四个独立概念，各管一件事，互不越界：

| 层 | 实体/文件 | 职责 | 一句话 |
|---|---|---|---|
| **PageSetting**（页面区块） | 库表 `PageSetting` | 定义**一个区块**长什么样（组件树 + 数据骨架） | “筛选区/列表区/详情区”各自存一份 |
| **DynTemplate**（模板） | 库表 `DynTemplate` + `Views/DynTemplates/*.cshtml` | 定义**外观与积木之间如何流转**，接收实例参数 | 把若干 Block 串成一个整体 |
| **DynWebPage**（页面实例） | 库表 `DynWebPage` | 模板的**实例**，填了参数就能跑 | 一个页面 = 一个模板 + 一份 ParamsJson |
| **Block**（积木） | `Views/DynBlocks/Apps/{FilterApp,ListApp,DetailApp}.cshtml` | 独立、可复用的功能单元，**各自是独立 VueApp** | 拼积木的最小模块，自读配置、自带 createApp |

**边界铁律**：

- PageSetting 只存「组件树 ConfigJson + default 骨架」，**不存 URL、不存项目**（ProjectId 仅作归属标记）。
- URL（search/save/delete）属于**页面实例参数**，由 `DynWebPage.ParamsJson` 提供（支持顶层扁平键与 `blocks` 槽位分组两种写法）。
- Block 不自查 PageSetting、不自带 URL，**唯一输入是容器上的 `data-blk-config` 单个 JSON**（外加统一参数链的就近覆盖）。
- 模板是树根，是唯一知道「我里面有哪几个 Block、各自参数是什么、事件怎么接线」的人。
- Block 之间**不直接认识、不发 window 事件**，一律通过容器上的实例句柄 `element.__dynBlock`（send/on/emit）协作，由模板显式接线（见 §7）。

## 2. 渲染入口与整体数据流

**入口**：`GET /Platform/Page/DynWebPage?id={DynWebPageId}` → `PageController.DynWebPage`。

```
DynWebPage(id)
   │  读实例 + 读其绑定的模板 DynTemplate
   ├─ ① TryParseDict(page.ParamsJson)               → rawParams（实例参数）
   ├─ ② BuildEffectiveParams(rawParams)             → TableName 有值且 URL 留空时自动补 dyndata 端点
   ├─ ③ 解析模板 ConfigJson 顶层 mPassThrough        → 透传属性
   ├─ ④ LoadSetting(Filter/List/DetailPageSettingId) → 引用的区块配置
   └─ ⑤ 组装 DynSharedModel → View(template.ViewPath, Model=DynWebPage)
           模板 cshtml 内再用 DynPageViewHelper.ParseParams(Model.ParamsJson) 自取参数，
           Partial 引入 Apps/FilterApp|ListApp|DetailApp（各自独立 VueApp），
           在 ready 脚本里 dyn.mount(...) 后用 __dynBlock 句柄接线。
```

**关键机制 1：组件的 `model` 由 dynmodel script 承载**。Block 容器内放
`<script type="application/json" tag="dynmodel">{…}</script>`，mountCore 读出后作为该 App 的响应式 model（`this.model`）。写在 `dynConfig.data()` 里的是组件普通属性（`this.xxx`），不是 `this.model`。

**关键机制 2：每个 Block 是独立 createApp**。模板外壳本身一般**不是** VueApp（纯 HTML 布局 + 一段原生 JS 编排），避免「外层 App 编译内层 Block 模板指令」。Block 的挂载/卸载走 dyn-core 的多 App 嵌套台账（holder 掩码、父子台账、级联 unmount、失败 rollback）。

**关键机制 3：片段可嵌入任意位置**。弹窗（layui layer）、tabs 页签、行展开注入的都是后端返回的 HTML 片段，经 `dyn.fetchPartial + dyn.html` 注入后挂载；片段自动通过统一参数链（§9）与宿主建立 fork 父子关系。

## 3. PageSetting（页面区块配置）

### 3.1 字段

| 字段 | 说明 |
|---|---|
| `Id` | 自增主键 |
| `Code` | 业务编码，如 `page-mgmt-filter` |
| `Name` | 名称 |
| `SettingType` | `Filter`=筛选区 / `List`=列表区 / `Detail`=详情区 |
| `ProjectId` | 归属项目（DynProject.Id），可为空 |
| `TableName` | 关联业务表名（本区块操作哪张表），可为空 |
| `ConfigJson` | **组件树**：动态组件（DynCom）树，与设计器画布同构 |
| `RenderMode` | `Front`=前端 DynCom 动态控件 / `Back`=后端 Razor 局部视图 |
| `PartialPath` | RenderMode=Back 时的局部视图路径 |
| `DefaultJson` | **数据骨架 / 初始值**（按类型含义不同，见 3.2） |
| `SortNo` / `IsActive` | 排序 / 启用 |

### 3.2 三种类型的 ConfigJson / DefaultJson 各存什么

| 类型 | ConfigJson（组件树） | DefaultJson（骨架） |
|---|---|---|
| **Filter** | 筛选区控件树（如页面编码输入框、模板下拉） | 默认查询条件：`{ "字段": {"op":"like","value":null} }`（嵌套，推荐）或 `{ "字段": 默认值 }`（扁平） |
| **List** | 必须是 `{ "columns": [{field,label,width,minWidth,cellType,options,...}, ...] }` | 一般不用（可空） |
| **Detail** | 表单控件树（输入框/下拉/开关/文本域…，可带校验） | 新增时的初始骨架 `{ 字段: null/默认 }` |

List 列定义补充：

- `cellType:"tag"` → 值以 el-tag 渲染；否则走文本。
- `options:[{value,label,type}]` → 非 tag 列也会按字典把值翻译成 label（如 TemplateId 显示模板名）；tag 列命中时用 `type` 上色。
- 整数布尔列（数据库存 1/0）配 `DynElSwitch` 时必须在 comoptions 里给 `activeValue:1, inactiveValue:0`（见 §15 坑 7）。

### 3.3 ConfigJson 组件树结构（Filter / Detail 同构）

```json
{
  "component": "DynElContainer",
  "modelname": "",
  "options": {
    "comoptions": { "direction": "vertical" },
    "labeloptions": { "label": "", "required": false, "show": false }
  },
  "validators": [],
  "childrenctrls": [
    {
      "component": "DynElInput",
      "modelname": "Name",
      "options": {
        "comoptions": { "placeholder": "请输入名称", "clearable": true },
        "labeloptions": { "label": "名称", "required": false, "show": true }
      },
      "validators": []
    }
  ],
  "slots": {},
  "extendinfo": {}
}
```

- `component`：动态组件名（DynElInput / DynElSelect / DynElSwitch / DynJsonDesigner / DynElContainer…）。
- `modelname`：绑定到 model 的字段名；嵌套筛选条件支持点路径 `字段.value`（lodash `_.get/_.set`）。
- `options.comoptions`：控件本身配置；`options.labeloptions`：标签配置。
- 校验写在 `validators`（如 `{"type":"required","message":"不能为空"}`）。

## 4. DynTemplate（模板）

### 4.1 字段

| 字段 | 说明 |
|---|---|
| `Id` | 自增主键 |
| `Code` | 模板编码，如 `filterlist-crud` / `detail-modal` / `tabs-basic` |
| `ViewPath` | 渲染用 Razor 视图，如 `~/Views/DynTemplates/FilterListCrud.cshtml` |
| `DefaultJson` | 模板默认配置/默认值；新建页面实例时复制为初始参数（等价旧 TemplateJson） |
| `ConfigJson` | **实例参数 UI 定义**：描述这个模板接收哪些参数（含顶层 `mPassThrough`） |
| `Category` / `Icon` / `Description` / `SortNo` / `IsActive` | 分类、图标、说明、排序、启用 |

### 4.2 实例参数 UI 由 ConfigJson 定义

模板的 `ConfigJson` 用动态组件树描述「该模板接收的参数面板」。用户建页面实例时按面板填参数，结果存进 `DynWebPage.ParamsJson`。三种主力模板的参数形态见 §5.2。

### 4.3 模板清单与选型

| Code | 视图 | 定位 | Block 组成 | 典型用途 |
|---|---|---|---|---|
| `filterlist-crud` | FilterListCrud.cshtml | 筛选+列表主页，增删改走**弹窗** | FilterApp + ListApp（+ 拉取 detail-modal 弹窗） | 90% 管理后台主页（PageGen 默认产物） |
| `detail-modal` | DetailModal.cshtml | 纯片段：一个 DetailApp 弹窗 | DetailApp | 被主页 fetchPartial 注入 layer，不单独访问 |
| `tabs-basic` | TabsBasic.cshtml | 多页签容器，每签加载一个 URL 片段 | 自身非 App；页签内是任意片段 | 一个对象多视角（基本信息/关联页面/…） |
| `triscreen-blocks` | TriScreenBlocks.cshtml | 同页三屏（筛选+列表+详情同屏） | FilterApp + ListApp + DetailApp | 需要详情区常驻同屏的页面 |
| `crud-basic` | CrudBasic.cshtml | 免 Model 单屏 CRUD（老式直配） | 无 Block，控制器组装 DynSharedModel | 历史页面/极简页 |
| `tree-basic` / `tree-detail` | TreeBasic.cshtml / TreeDetail.cshtml | 左树右表/树+详情（tree-detail 为 Block 化版本） | tree Block + DetailApp | 菜单、组织机构 |
| `tree-master-detail` | [TreeMasterDetail.cshtml](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/Views/DynLayouts/TreeMasterDetail.cshtml) | **布局壳 v1**：spec 驱动的左树右详情壳，零 URL | tree + detail，壳内默认连线 | 壳模型最小验证：SysMenu 演示页 id=21，详见 §18 |
| `master-detail-basic` | MasterDetailBasic.cshtml | 主子表 | — | 订单+明细类 |

> `filterlist-crud` / `detail-modal` / `tabs-basic` 都支持**片段双形态**（浏览器直访出整页、被 fetchPartial 拉取出片段），见 §10。

## 5. DynWebPage（页面实例）

### 5.1 字段

| 字段 | 说明 |
|---|---|
| `Id` | 自增主键 |
| `Code` | 实例编码（如 `page-mgmt`） |
| `ProjectId` | 归属项目（DynProject.Id，int，**可为空**；平台管理页填平台项目 Id=2） |
| `Name` | 页面名 |
| `TemplateId` | 使用的模板（DynTemplate.Id） |
| `PageJson` | 页面 JSON；**为空时回退模板 DefaultJson** |
| `ParamsJson` | **实例参数**（原 ConfigJson 改名）：模板自身参数（顶层扁平）+ `blocks` 槽位分组 |
| `Url` | 独立运行地址（菜单/跳转用） |
| `ExtViewPath` | **页面扩展视图**（真实 cshtml，限 `~/Views/DynPages/Ext/`），见 §13 |
| `IsActive` / `CreateTime` / `ExtJson` | 启用 / 创建时间 / 扩展 JSON |

### 5.2 ParamsJson 结构（新老兼容）

**通用结构**：

```jsonc
{
  // —— 模板自身参数：顶层扁平（老版本全部是这种写法，继续兼容）——
  "TableName": "DynWebPage",
  "KeyField": "Id",
  "ModalPageId": "18",        // filterlist-crud：编辑弹窗用的 detail-modal 页面 Id
  "ChildFkField": "",         // 主子「+子」预填外键，可空

  // —— 积木槽位分组（PageGen 新结构）；model 里不再需要任何 *Url ——
  "blocks": {
    "filter": { "settingId": 87, "model": { } },
    "list":   { "settingId": 88, "model": { } },
    "detail": { "settingId": 89, "model": { } }
  },

  // —— 数据域坐标（平台表必填 "__platform__"；业务库可留空；项目库填 Code/Id）——
  "Project": "__platform__"
}
```

读取辅助（`DynPageViewHelper`，cshtml 侧）：

```csharp
var ps   = DynPageViewHelper.ParseParams(Model.ParamsJson);       // JObject
var fid  = DynPageViewHelper.SlotSettingId(ps, "filter", "FilterPageSettingId"); // 槽位优先，老扁平键回退
// URL 无需再配：Block 默认 /api/dyndata/*；project 实例参数优先、页面 ProjectId 兜底
var project = ps["Project"]?.ToString() ?? Model.ProjectId?.ToString() ?? "";
```

**tabs-basic 的 ParamsJson 是特殊形态**（注意 TabsJson 的值本身是 JSON **字符串**——字符串套 JSON）：

```jsonc
{
  "TabsJson": "[{\"title\":\"基本信息\",\"url\":\"/Platform/Page/DynDetail?...\",\"lazy\":false,\"keepAlive\":true}]",
  "SharedParamsJson": "{\"rowId\":0}"
}
```

### 5.3 filterlist-crud 主页实例参数示例（page-mgmt，平台库）

```json
{
  "TableName": "DynWebPage",
  "KeyField": "Id",
  "ModalPageId": "18",
  "Project": "__platform__",
  "blocks": {
    "filter": { "settingId": 87 },
    "list":   { "settingId": 88 }
  }
}
```

> 系统表（DynTemplate/DynWebPage/PageSetting/SysMenu 等）页面在实例参数里声明 `"Project":"__platform__"` 即可；不写任何 URL，Block 自动走 `/api/dyndata/*`。业务库页面 Project 可留空（默认 BusinessDb），项目库填 DynProject Code/Id。

## 6. Block（积木：独立 BlockApp）

当前四个 Block 全部位于 `Views/DynBlocks/Apps/`（FilterApp / ListApp / DetailApp / TreeApp；旧的 `Views/DynBlocks/*Block.cshtml`、「双模式 data-root-ext-id」、`message-center.js` **已全部删除**，禁止再参考旧文档/旧写法）。

### 6.1 共同契约

- 容器：`<div data-dyn-mode="createApp" data-blk-role="filter|list|detail|tree" data-blk-config="{…}">`。
- **唯一输入**：`data-blk-config` 一个 JSON（服务端拼装、HTML 编码烘焙）。
- 取值两级：脚本内 `dyn.params(element).get(key)` 走统一参数链（L0~L4，可被 fork/URL/共享层覆盖），链上没有才回退 `__cfg[key]`。
- 数据请求零配置：cfg 里的 `*Url` 全部可省，缺省即 `/api/dyndata/*`，数据域只看 `project`（见 §8）。
- 每个 Block 自挂一个独立 VueApp，mounted 时创建实例句柄并注册命令；beforeUnmount 时 destroy。
- Block **只报告「发生了什么」**（emit 事件），不做关窗、不发 window 消息、不刷新别人——这些全由模板/壳订阅后决定。

### 6.2 四个 Block 的输入/命令/事件

| Block | data-blk-config 主要键 | 命令（handle.send） | 事件（handle.on 订阅） |
|---|---|---|---|
| **FilterApp** | `filterConfig`（UI树）、`filterDefault`（骨架）、`project` | `submit`（以当前输入主动发一次 changed） | `changed`，载荷 = `{字段:{op,value}}`，空对象 `{}` 表示无条件 |
| **ListApp** | `columns`、`table`、`keyField`、`project`（`loadUrl`/`deleteUrl` 可省） | `loadData`（载荷 `{filter}`，回第 1 页）、`reload`（按当前条件刷新） | `add`（`{}`）、`edit`（`{row}`）、`addChild`（`{row}`）；删除在 Block 内完成并自刷新 |
| **DetailApp** | `detailConfig`、`detailDefault`、`table`、`keyField`、`project`、`rowId`、`preFill`（`addUrl/editUrl/deleteUrl` 可省） | `newForm`（`{preFill}`）、`editForm`（`{row}`） | `saved`（`{action:'add'|'edit'|'delete', row}`）、`cancel`（`{}`） |
| **TreeApp** | `table`、`keyField`、`parentField`、`titleField`、`iconField`、`sortField`、`project`、`enableDrag`、`dragSameLevelOnly`（`loadUrl/editUrl` 可省） | `reload`（重拉整棵树） | `nodeClick`（`{row}`）、`addRoot`（`{}`）、`addChild`（`{preFill}`）；拖拽排序由 Block 内部串行提交 |

DetailApp mounted 自举逻辑（片段弹窗靠它，不需要外部先喂数据）：

```js
mounted: function () {
  __handle.reg('newForm', p => { self.newForm(p.preFill || {}); })
         .reg('editForm', p => { self.editForm(p.row); });
  var rowId   = __pv('rowId', null);                 // 链上取：fork 入参 > cfg 烘值 > URL
  var preFill = __pv('preFill', null) || __cfg.preFill || {};
  if (rowId) {
      // 编辑态：自拉单行 GET /api/dyndata/get?table=&id=&project=，回来整体 editForm
      DynCall.get(DynBlocks.getUrl(this.table, rowId, this.project), {}, {silent:true})
             .then(row => { if (row) self.editForm(row); });
  } else if (Object.keys(preFill).length) {
      this.newForm(preFill);                         // 新增态预填（主子外键 / filterInit 裸值）
  }
}
```

### 6.3 ListApp 首屏加载（含预置筛选）

```js
mounted: function () {
  __handle.reg('loadData', p => { self.model.filter = (p && p.filter) || {}; self.model.page = 1; return self.loadData(); })
         .reg('reload', () => self.loadData());
  var fi = __P && __P.get('filterInit');             // 链上预置（见 §12）
  if (fi) this.model.filter = normalizeFilterInit(fi); // {字段:{op,value}} 或 {字段:裸值} → 统一 DSL
  this.loadData();                                   // 只发一次首屏请求，避免空查+条件查竞态
}
```

请求体固定：`{ table, page, size, filter, project }`（POST search）。

## 7. Block 协作：实例句柄 __dynBlock

> 实现：`wwwroot/dyn/blocks/dyn-blocks-common.js` 的 `DynBlocks.createBlockHandle(element)`。
> **消息中心（message-center）已整体删除**，现在 Block 间协作只有容器句柄这一种机制。

### 7.1 句柄 API

| API | 方向 | 说明 |
|---|---|---|
| `handle.reg(cmd, fn)` | Block 内 | 注册命令处理器，fn 可以返回 Promise |
| `handle.send(cmd, payload)` | 编排方 → Block | 下命令；未注册/已销毁返回 rejected Promise |
| `handle.on(evt, fn)` | 编排方订阅 | 返回注销函数 |
| `handle.emit(evt, payload)` | Block 内 → 外 | 分发给所有订阅者 |
| `handle.destroy()` | 卸载 | 清空命令/订阅，之后全部静默（防悬垂） |
| `DynBlocks.scan(container)` | 编排方 | 扫描容器内已挂载 Block，返回 `{role: handle}`（容器自身是 Block 也算） |

## 9. 统一参数上下文 ParamContext

> 实现：`wwwroot/dyn/dyn-params.js`。一套取值语法、多来源合并、就近优先。
> Block 脚本里用 `var P = dyn.params(element); P.get('rowId')`；模板里用 `{{$params.rowId}}`。

### 9.1 层级（数字小优先级高）

| 层 | 来源 | 典型内容 |
|---|---|---|
| **L0 显式入参** | fork 时传入的 local / `ctx.set` 运行时覆盖 | 弹窗 fork 的 `{rowId, preFill}` |
| **L1 本地静态** | 容器 `data-dyn-params` 属性 / 直接子级 `<script tag="dynparams">` / Block 的 `data-blk-config` 适配 | 模板服务端烘焙的 pageParams、Block 自配置 |
| **L2 本地 Model** | `el.__dynModel`（业务数据层，按 key 命中才取） | form 字段、列表 rows |
| **L3 上层继承** | 父 ParamContext（片段注入/嵌套 App 链 + 共享实体层） | 宿主 tabs 的 rowId、跨页签 shared |
| **L4 URL query** | `window.location.search`，**只在链根查一次** | `?id=19` |

另有独立的 **shared 共享实体层**：一条 fork 链共享同一个 reactive 对象，`ctx.commit(key,val)` 写入，兄弟页签立即可见（跨 tab 流动的业务实体，如 tabs-basic 的 `rowId`）。

### 9.2 解析顺序伪代码（resolveOne）

```js
ctx.resolveOne = function (path, explicit) {
  var v;
  if (explicit !== undefined) { v = getPath(explicit, path); if (v !== undefined) return hit(v,'L0:explicit'); }
  v = getPath(runtime, path); if (v !== undefined) return hit(v,'L0:runtime');
  v = getPath(local,   path); if (v !== undefined) return hit(v,'L1:static');   // data-dyn-params/dynparams/data-blk-config
  v = getPath(shared,  path); if (v !== undefined) return hit(v,'shared');
  var m = el.__dynModel; if (m && isPlain(m)) { v = getPath(m, path); if (v !== undefined) return hit(v,'L2:model'); }
  if (ctx.parent) { var r = ctx.parent.resolveOne(path); if (r && r.value !== undefined) return r; } // L3
  if (!ctx.parent) { v = getPath(urlQuery(), path); if (v !== undefined) return hit(v,'L4:url'); }    // 仅链根
  return { value: undefined, layer: null };
};
```

### 9.3 常用 API

```js
var P = dyn.params(el);                 // 取元素所属 ctx（没有则挂页面根）
P.get('rowId', 0);                      // 取值+默认值
P.require(['rowId']);                   // 必需键缺失告警
P.fork(holderEl, { rowId: 12 });        // 为片段/弹窗挂载点派生子上下文（L0 local）
P.commit('rowId', 12);                  // 发布到共享层（兄弟 fork 可见）
P.watch(['rowId'], function(k,nv,ov){});// 跟随型监听，返回注销函数
P.resolveValue('$params.rowId');        // token 解析（整串保留类型）
P.resolveValue('/x?id={{$params.rowId}}'); // 行内插值（字符串化，自动 encode 由调用方决定）
```

`$params` 响应式视图：模板中 `{{$params.xxx}}` 会被 Vue 收集依赖，shared/local/model 任一层变化即自动更新。

### 9.4 片段容器的 L1 声明必须被补建（重要，曾出严重串表 Bug）

服务端片段（如 filterlist-crud 页签）会在自己的根节点烘焙 `data-dyn-params`（L1），声明「本片段的 tableName/filterInit」。片段被注入宿主后，建链时**路径上每个声明节点都必须实例化并插进 ctx 链**，否则片段 L1 会被宿主 L3 遮蔽。详见 §15 坑 1。

### 10.1 双形态布局

同一视图两种输出，靠请求头 `X-Requested-With: XMLHttpRequest` 判别（`fetchPartial` 必带该头）：

- **片段拉取**（有该头）→ `_AjaxLayout`：只有 `RenderBody()` + scripts section + dyn-actions 渲染。

```csharp
         && xrw == "XMLHttpRequest" ? "_AjaxLayout" : "_Layout";
```

### 10.2 弹窗注入标准流程（filterlist-crud → detail-modal）

```js

  holder.className = 'dyn-modal-host dyn-layer-fragment';
  document.body.appendChild(holder);

  // ① 参数链 fork：rowId/preFill 作为 L0 入参层（片段内 DetailApp 用 P.get('rowId') 取）
  lEl.__dynParams.fork(holder, { rowId: rowId || '', preFill: preFill || null });

  layer.open({
    type: 1, content: holder,
    success: function () {
      // ② 拉片段（自带 X-Requested-With → _AjaxLayout 无外壳）
      var q = '/Platform/Page/DetailModal?id=' + MODAL_PAGE_ID + '&rowId=' + (rowId||'')
            + '&project=' + encodeURIComponent(PROJECT)
            + (preFill ? '&prefill=' + encodeURIComponent(JSON.stringify(preFill)) : '');
      dyn.fetchPartial(q, {}, 'GET').then(function (html) {
        // ③ boot=false 注入：搬运节点 + 执行内联 script；createApp 由下面显式挂载
        dyn.html(holder, html, false);
        var apps = holder.querySelectorAll('[data-dyn-mode="createApp"]');
        var chain = Promise.resolve();
        apps.forEach(ae => { chain = chain.then(() => dyn.mount(ae)); });
        chain.then(function () {
          // ④ 关窗权在模板：订阅 DetailApp 的 saved/cancel
          var detail = DynBlocks.scan(holder).detail;
          detail.on('cancel', () => layer.close(idx));
          detail.on('saved',  () => layer.close(idx));
        });
      });
    },
    end: function () {
      // ⑤ 单通道刷新：保存关窗 / X / 取消都走 end → 卸载弹窗 → reload 列表
      holder.querySelectorAll('[data-dyn-mode="createApp"]').forEach(ae => dyn.unmount(ae));

      lEl.__dynBlock.send('reload').catch(()=>{});
    }
  });
}
```

要点：

- `dyn.html(el, html, boot)`：会先 `unmount(el)` 释放旧内容、接入参数链（`parentCtx` 显式指定时用之）、搬运 DOM、执行**无 tag 属性**的内联 `<script>`（带 `tag="dynconfig/dynmodel/dynconfig-ext"` 的不执行，交给 mountCore）。
- 弹窗片段是 iframe 还是内联？——**内联 DOM 注入**，不是 iframe；因此宿主 location.search 会污染片段的 L4，服务端烘焙必须放 L1（见 §12）。

## 12. filterInit 预置筛选完整链路

```js
reset: function () {
  this.filterModel = clone(this.initModel);      // 恢复【初始基线】（含预置值）
  __handle.emit('changed', this.buildSubmit());  // 无预置时 buildSubmit() 返回 {}，等价旧「重置即无条件」
}
```

**③ ListApp 首屏一次请求**：mounted 读链 filterInit，规范成 DSL 后作为 `model.filter` 直接发首屏请求（不要先空查再等 changed，两次响应会竞态覆盖）。

**④ 新增预填（模板编排）**：

```js
function presetPreFill() {
  var pf = {};
  var fi = fEl.__dynParams.get('filterInit');
  if (fi && typeof fi === 'object') {
    Object.keys(fi).forEach(k => {
      var v = fi[k];
      pf[k] = (v && typeof v === 'object') ? v.value : v;   // {op,value} 取裸值
    });
  }
  return pf;                                                 // → openDetailModal(null, pf)
}
list.on('add', function () { openDetailModal(null, presetPreFill()); });
```

### 12.3 验收点

- tabs 弹窗「关联页面」首屏**只**出现 TemplateId=当前模板的行；筛选区模板下拉回显模板名。
- 点「重置」后仍只出现预置条件的行（基线恢复，不是全量）。
- 在该页签内点「+ 新增」，DetailApp 表单 TemplateId 已预填；若预填的模板恰好挂了条件显隐的扩展卡（如 §13 的 tabs 专用卡），卡片应自动出现。
- 无 filterInit 的普通入口行为与旧版完全一致（首屏全量、重置无条件、新增不预填）。

## 13. 页面扩展插槽（DynExtSlots）

> 当通用组件/生成器产不出某种专用编辑 UI（典型：tabs-basic 的「字符串套 JSON」复合参数），不要硬塞进 PageSetting 组件树，而是在**页面实例的扩展视图**里用插槽解决。
> 文件：`Core/DynPageExt.cs`（字典 + HtmlHelper）、`Services/DynPageExtService.cs`（白名单 + 骨架生成）。

### 13.1 机制总览

1. `DynWebPage.ExtViewPath` 指向 `~/Views/DynPages/Ext/{code}.ext.cshtml`（PageGen 自动生成骨架，已存在则永不覆盖）。
2. 模板渲染前 `await Html.LoadPageExtAsync(Model)`：执行该视图，视图自身标记输出**被丢弃**，只把 Razor 模板委托填进 `ViewData["DynExtSlots"]` 字典。
3. 各 Block 视图在锚点处 `@(extSlots?.Render("key"))` 输出 HTML；`<script tag="dynconfig-ext">` 由 mountCore 的 `readExtConfigs` 读出并 `mergeExtOptions` 合并进该 Block 的 VueApp。
4. 安全：路径必须在 Ext 目录内、无 `/`、无 `..`、白名单字符 + `.cshtml` 后缀（`IsValidPath`），杜绝路径穿越。

### 13.2 槽位白名单

| 槽位 key | 位置 | 用途 |
|---|---|---|
| `list:toolbar` | 列表「+ 新增」之后 | 追加工具按钮 |
| `list:row-actions` | 行操作列（编辑/+子/删除之后） | 追加行按钮 |
| `list:app-ext` | 合并进 ListApp 的脚本 | 访问 this.model.rows/this.table/loadData() |
| `filter:actions` | 查询/重置之后 | 筛选区按钮 |
| `filter:app-ext` | 合并进 FilterApp 的脚本 | — |
| `detail:body-extra` | **动态表单树之后**的自定义表单区 | 与 DetailApp 同 VueApp，**可直接绑 this.form**（专用字段编辑器） |
| `detail:footer` | 取消/删除/保存之后 | 底部自定义按钮 |
| `detail:app-ext` | 合并进 DetailApp 的脚本 | 读写 this.form、覆盖/新增 methods、挂 watcher |
| `tree:tools` / `tree:app-ext` | 树形页 | — |

### 13.3 脚本合并规则（mergeExtOptions）

- `methods/computed/watch/components/directives`：按键合并，**扩展同名覆盖**（允许深度定制）。
- `data`：基础与扩展各自求值后**浅合并**，扩展键覆盖。
- 生命周期（created/mounted/…）：按 **基础 → 扩展** 顺序串联，扩展钩子异常不阻断基础。
- `setup/template` 不允许扩展覆盖。
- 只读 **App 根直接子级**的 `script[tag="dynconfig-ext"]`（嵌套 App 的不会误读）。

### 13.4 实战：tabs-basic 参数专用编辑器（page-mgmt.ext.cshtml）

场景：page-mgmt（DynWebPage 管理页）的详情表单里，当 TemplateId=tabs-basic 时出现一个页签编辑卡，直接编辑 form.ParamsJson 里的 TabsJson，保存仍走 DetailApp 原生 onSave（零重复保存逻辑）。

```cshtml
@model VueLibV4.Platform.Models.DynWebPage
@using VueLibV4.Web.Core
@using VueLibV4.Platform.Services
@inject IDynTemplateService TemplateSvc
@{
    var Slots = ViewData["DynExtSlots"] as DynExtSlots ?? new DynExtSlots();
    // SqlSugar Queryable 没有 FirstOrDefault：用 .First()（见 §15 坑 8）
    var tabsTplId = TemplateSvc.Query(t => t.Code == "tabs-basic").First()?.Id ?? 0;

    // ① HTML 插槽：v-if 控制仅 tabs-basic 实例可见
    Slots["detail:body-extra"] = @<div v-if="tbsVisible" class="pmg-tbs">
        <button type="button" class="el-button el-button--primary el-button--small" @@click="tbsAdd()">+ 添加页签</button>
        <table>
          <tr v-for="(t,i) in tplTabs" :key="i">
            <td><el-input v-model="t.title" size="small" @@change="tbsSync()"></el-input></td>
            <td><el-switch v-model="t.lazy" @@change="tbsSync()"></el-switch></td>
            <td><button type="button" class="el-button el-button--small is-link" @@click="tbsRemove(i)">移除</button></td>
          </tr>
        </table>
    </div>;

    // ② 脚本插槽：合并进 DetailApp
    Slots["detail:app-ext"] = @<script type="text/plain" tag="dynconfig-ext">
    var TBS_TPL_ID = @tabsTplId;
    var dynConfigExt = {
      data: function () { return { tplTabs: [], __tbsStop: null }; },
      computed: {
        tbsVisible: function () { return TBS_TPL_ID > 0 && Number(this.form && this.form.TemplateId) === TBS_TPL_ID; }
      },
      methods: {
        tbsLoad: function () {                         // 字符串套 JSON：parse 两层
          var pj = JSON.parse(this.form.ParamsJson || '{}');
          this.tplTabs = JSON.parse(pj.TabsJson || '[]');
        },
        tbsSync: function () {                         // 保留 ParamsJson 其它键，只覆盖 TabsJson
          var pj = JSON.parse(this.form.ParamsJson || '{}');
          pj.TabsJson = JSON.stringify(this.tplTabs);
          this.form.ParamsJson = JSON.stringify(pj);
        }
        // tbsAdd/tbsRemove：数组 push/splice 后 tbsSync()
      },
      mounted: function () {
        // 关键时序：扩展 mounted 在基础 mounted 之后跑，而编辑行是基础 mounted 里【异步拉回】
        // 后整体替换 form 的——此刻直接 tbsLoad 读到的是骨架。必须 $watch 主键/模板变化：
        var self = this;
        this.__tbsStop = this.$watch(
          function () { return [self.form.Id, self.form.TemplateId]; },
          function () { if (self.tbsVisible) self.tbsLoad(); }
        );
        if (this.tbsVisible) this.tbsLoad();          // 新增态预填 TemplateId 也会触发 watcher
      },
      beforeUnmount: function () { this.__tbsStop && this.__tbsStop(); }
    };
    </script>;
}
```

### 13.5 扩展视图 Razor 纪律

- cshtml 内联 JS 的 `@` 一律写 `@@`（`@@click`、`@@change`），否则被 Razor 当 C# 解析。
- Vue 插值 `{{ }}` 在普通文本里可原样输出；但若出现在**会被 Vue 当模板编译的节点**（如表头 `<th>`）且就是想显示字面量，加 `v-pre` 跳过编译：
  `<th v-pre>支持 $params.xxx 或 {{$params.xxx}} 占位</th>`。
- 需要服务端数据（如模板 Id）直接 `@inject` 服务查库烘焙成 JS 常量，不要让前端多发请求。
- 不需要 JS 的简单按钮，也可用声明式动作链：`data-dyn-click-open="…" data-dyn-click-mode="fragment"`（零脚本）。

## 16. 关键约束与踩坑录

> 每条都是实际花过代价的。新功能开发前先扫一遍。

### 16.1 架构与编码约束

1. **model 由 dynmodel script 承载**：共享上下文/骨架写 `<script type="application/json" tag="dynmodel">`；`dynConfig.data()` 里的是组件普通属性。
2. **dynconfig 必须顶层 `var dynConfig`**：mountCore 用 `new Function('element','dyn', text)(el, dyn)` 取回；script 加 `type="text/plain"` 防浏览器原生执行报 `element is not defined`。扩展脚本对应顶层 `var dynConfigExt` + `tag="dynconfig-ext"`。
3. **按钮用原生 `<button class="el-button ……">`**：el-button 会拦截冒泡影响 dyn 委托。
4. **不要调 `dyn.rebindActions`**：动作注册即生效，重复 rebind 导致 document 监听叠加（一次点击触发多次）。
5. **改 C# 必须 build + 重启**；cshtml（Razor RuntimeCompilation）/ sqlite 改动即时生效；wwwroot/dyn/*.js 由内容哈希自动失效（§15.3）。build 前先停运行中的站点（dll 被锁会 MSB3027）。
6. **Block 不自查 PageSetting、不自带 URL**；Block 不发 window 事件、不自己关窗——全部经句柄 + 模板编排。

### 16.2 本期重点 Bug 记录（高优先级，避免重踩）

**坑 1：片段 L1 声明被宿主 L3 父链遮蔽 → 串表 + 预置筛选丢失**

- 现象：tabs 页签内嵌 filterlist-crud 片段，片段配的是 DynWebPage 表，列表却查了宿主的 DynTemplate 表；服务端烘焙的 `filterInit` 也读不到。
- 根因：片段根节点 `.flc-root[data-dyn-params]` 在建 ctx 时，`findHangingContext` 沿 parentNode 上行**先碰到了已存在的宿主 ctx 就直接返回**，路径上片段自己的声明节点没有被实例化；于是 Block 沿 L3 父链上溯，`table` 命中宿主 blk-config 的 DynTemplate（片段 L1 只有 tableName 没有 table），filterInit 哪层都没有。
- 修复（`dyn-params.js`）：上行时收集路径上**所有**未实例化的声明节点，遇到 live ctx 后，自顶向下把它们**逐个 createContext 插进链里**再返回：

```js
function materializeDeclarers(declarers, ancestor) {
  var parent = ancestor || null;
  for (var i = declarers.length - 1; i >= 0; i--) {     // 远 → 近 自顶向下补建
    parent = declarers[i].__dynParams || createContext(declarers[i], { parent: parent });
  }
  return parent;                                         // 最近声明节点的 ctx
}
```

- 教训：**L1 容器声明的优先级必须高于 L3 父链**；任何「沿 DOM 找最近 ctx」的实现都不能跳过路径上的声明节点。调试用 `el.__dynParams.inspect(['table','filterInit'])` 看每个键的获胜层。

**坑 2：mountCore 里 dynconfig 执行早于参数 ctx 建立**

- 现象：坑 1 修完链路仍串表——Block 脚本顶层 `var __P = dyn.params(element)` 捕获到的是中间片段容器（flc-root）的 ctx。
- 根因：`dyn.params(el)` 走 `DynParams.fromEl`（只找**已就绪** ctx）；而 mountCore 原先先执行 dynconfig 脚本、后 `DynParams.ensure(el)`，Block 自身 ctx（含 data-blk-config 的 L1）此刻还不存在，脚本闭包就绑到了中间容器，`table` 继续上溯漏到宿主。
- 修复（`dyn-core.js mountCore`）：把 `DynParams.ensure(el, parentEl)` **提到执行 dynconfig 之前**（同时仍保证在 maskNested/删 script 之前）。
- 教训：**凡是脚本内会立即 `dyn.params(element)` 的，ctx 必须先于脚本执行就绪**；排查时区分「ctx 链不对」与「脚本闭包捕获了旧 ctx」两个层面。

**坑 3：改了 wwwroot/dyn/*.js 但浏览器永远跑旧代码（已根治，见 §15.3）**

- 现象：服务端文件已是新逻辑，页面行为不变。
- 根因：dyn 模块经 `dyn-lib.js` 按固定 `?v={DynLib.version}` 加载，浏览器磁盘缓存长期有效。
- 修复：已上线**内容哈希清单**（`window.DYN_ASSET_HASHES` + `DynAssetManifestService`），改 js 保存即自动失效，**不再需要手工 bump version**；dyn-blocks-common.js 用 `asp-append-version`。固定 version 仅作清单缺失时的回退。

**坑 4：嵌套筛选模型预置值不回显 / 重置变无条件**

- FilterApp 初版把嵌套值 `{op,value}` 的 initModel 置成 null，预置筛选无法经控件 `modelname=字段.value` 回显；reset 无条件 emit `{}`，把 tabs 透传的预置基线丢了。
- 修复：`__buildInit` 保留同构对象；reset 恢复 initModel 基线后重新 emit buildSubmit（无预置时自然等价无条件）。

### 16.3 Razor / 组件 / 数据类小坑

5. **cshtml 内联 JS 的 `@` 写 `@@`**：漏一个就是 Razor 编译错误（Internal Server Error 页会指出具体行）。
6. **Vue 字面量 `{{}}` 要 `v-pre`**：在会被 Vue 编译的节点里展示 `{{$params.x}}` 文案，不加 v-pre 会被当表达式解析报错/变空。
7. **el-switch 整数布尔**：数据库 1/0 必须配 `comoptions:{activeValue:1,inactiveValue:0}`，否则回显/保存全错。
8. **SqlSugar Queryable 无 FirstOrDefault**：扩展视图/服务里用 `.First()` / `.ToList()` 物化；`Query(predicate)` 结果是 ISugarQueryable，不能直接当集合用。
9. **数据端点只有一套**：全部走 `/api/dyndata/*`，操作平台表必须显式声明 `Project="__platform__"`（实例参数）或 `provide.project="__platform__"`（壳规格）；旧的 biz/plat 分域端点已删除，禁止在新代码/配置里出现其 URL。
10. **filter op 白名单**：合法 eq/neq/gt/ge/lt/le/like/notlike/in/between；写错（如 `contains`）或列不存在现在会 warnings 回流（§15.2），但条件依然不生效——告警是提醒你改配置，不是兜底；前端仍务必剔除空值条件。
11. **filterlist-crud 显式设了 Layout**：`_ViewStart` 对它不生效，双形态必须在视图内自己判 `X-Requested-With`（tabs-basic 不设 Layout 才交给 _ViewStart）。
12. **扩展 mounted 早于编辑行回填**：DetailApp 编辑行是 mounted 内异步 GET 回来后整体替换 form；app-ext 里要读 form 的初始化逻辑必须用 `this.$watch(() => [form.Id, form.TemplateId], …)`，beforeUnmount 注销（§13.4）。
13. **tabs 弹窗里宿主 scan 接不到懒加载页签内的 Block**：由 tabs 在注入后自己 `DynBlocks.scan(host)` 补接 saved/cancel（wireDetailClose），关窗定位本层 `.layui-layer`。
14. **首屏不要发两次列表请求**：ListApp 有预置筛选时直接以条件发一次首屏；先空查再等 changed 会产生响应竞态（后返回的覆盖新的）。
15. **dyndata 信封曾经双形态（已统一，勿回退）**：平台端点旧形态是 query `?table=&id=` + 扁平实体 body，业务是 `{table,data}` / `{table,keys}` 包裹体——客户端要维护 savePayload/saveUrl/deleteRequest 三套分支。2026-10 起平台端点改为与业务**完全同形**（§8.1），客户端只剩"库从哪来"一个差异。旧管理页（crud-basic/tree-basic/DesktopShortcut 等）仍调旧形态，**已随旧页面冻结不再维护**，新代码严禁模仿。
16. **update 空字段集合会生成裸 SQL**：data 除主键外没有任何列时 SqlSugar 生成 `UPDATE t SET WHERE …` 语法错（曾以 HTML 异常页形式冒出）。服务端已前置校验为友好 JSON 错误（§15.2）；自定义写路径也要防"空 SET"。

## 18. 布局壳模型 v1（Layout Shell）

> 实现：[dyn-layout-engine.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/layouts/dyn-layout-engine.js)（壳运行时）+ `Views/DynLayouts/*.cshtml`（壳定义，真代码）。
> 首个壳：[TreeMasterDetail.cshtml](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/Views/DynLayouts/TreeMasterDetail.cshtml)，演示页 PAGE 21（SysMenu / `__platform__`）。

### 18.1 概念三分

| 角色 | 是什么 | 职责 | 不允许做什么 |
|---|---|---|---|
| **壳 shell** | 数量收敛的真代码（主从/堆叠/页签/弹窗…），cshtml + `DynLayouts.register` | 布局 DOM、槽位角色契约 `slots`、壳内置连线 `defaultWires`、壳自身端口 `commands`、壳自己的 UI 状态机（`onMount`，回传 `dispose`） | 不写业务数据请求、不知道槽内 Block 的内部实现 |
| **Block** | 标准 BlockApp（filter/list/detail/tree…） | 一块完整交互 + `__dynBlock` 句柄端口（commands/events） | 不知道自己被放在哪个壳里、不引用别的 Block |
| **页面规格 spec** | `DynWebPage.ParamsJson` 里一段纯数据 | 声明用哪个壳、provide 什么、每个槽放什么 Block/settingId/model、追加什么 wires | 不出现任何 `*Url` |

Block 挂载约定不变：**mounted 只做自身初始化、不 emit 对外事件**，所以壳运行时可以 `Promise.all` 并发挂载全部 Block 之后再统一接线。

### 18.2 页面规格 spec 结构

```jsonc
{
  "layout": "tree-master-detail",       // 壳名（对应 DynLayouts.register 的名）
  "layoutProps": { "leftWidth": 30 },   // 壳私有外观参数
  "provide": {                          // 全槽共享的数据域/维度
    "table": "SysMenu", "keyField": "Id", "project": "__platform__"
  },
  "slots": {
    "master": { "block": "tree", "model": {                  // model = 该 Block 私有参数
      "parentField": "ParentId", "titleField": "Name",
      "iconField": "Icon", "sortField": "SortNo", "enableDrag": true
    } },
    "detail": { "block": "detail", "settingId": 51 }        // detail 表单 UI 树仍来自 PageSetting
  },
  "wires": [ /* 可选：页面追加连线 */ ],
  "replaceDefaultWires": false            // true 时只认页面 wires，不挂壳默认连线
}
```

### 18.3 端口契约与默认连线

四角色端口表登记在 `DynBlocks.CONTRACTS`（壳运行时据此对未声明端口告警，不阻断）：

| 角色 | commands | events |
|---|---|---|
| filter | submit | changed |
| list | loadData, reload | add, edit, addChild |
| detail | newForm, editForm | saved `{action,row}`、cancel |
| tree | reload | nodeClick `{row}`、addRoot `{}`、addChild `{preFill}` |

tree-master-detail 的 4 条默认连线（页面不写 wires 即采用）：

```text
master.nodeClick → detail.editForm   with {row:'$event.row'}
master.addRoot   → detail.newForm    with {preFill:{}}
master.addChild  → detail.newForm    with {preFill:'$event.preFill'}
detail.saved     → master.reload
```

wire 形态：`{from:'节点.事件', to:'节点.命令'|['a.b'], with?:模板, origin?}`；节点名 = 槽位名或 `'shell'`。`with` 支持：`'$event'`（整包透传）、`'$event.x'`、`'$provide.x'`、对象深拷贝逐键替换、其余按字面量。

### 18.4 运行时挂载流程（DynLayouts.mount）

1. 读根容器 `data-dyn-page-spec`，按 `spec.layout` 找已注册壳定义；
2. 并发 `dyn.mount` 壳内全部 `[data-dyn-mode="createApp"]`；
3. 扫描 `[data-layout-slot]` → 槽名映射 Block 句柄（`handles.shell` 是壳自身的 makeShellHandle）；槽缺 Block / 槽位 block 与壳 `expect` 不符 → 收集 warning；
4. 调壳 `onMount(root, spec, handles)`：壳在这里自建 UI 状态机（如分隔条），返回 `{dispose}`；**engine 不内置任何具体 UI 行为**（拖拽/双击复位由 TreeMasterDetail 自己内联实现）；
5. 接线：`defaultWires` + `spec.wires`（`replaceDefaultWires` 时只用页面连线）；
6. `console.info` 输出就绪报告，warning 同时 `console.warn` + `DynDebug.note`；句柄挂 `root.__dynLayout`（含 handles/wires/warnings/destroy，重入保护 `__dynLayoutMounted`）。验收时浏览器看 `window.__shell`。

### 18.5 新增一个壳的步骤（下一个壳照抄）

1. 建 `Views/DynLayouts/XxxShell.cshtml`：`@model DynWebPage` + `Layout="_Layout"`；服务端只做把 spec 烘焙成各槽 Block 的 `data-blk-config`（零 URL，project 来自 `provide`），DOM 用 `[data-layout-slot="槽名"]`；
2. `DynLayouts.register('xxx', { slots, defaultWires, commands, onMount })`，壳自己的 UI 交互全部写在本视图（引擎不管）；
3. PageController 模板白名单加该 code（透传 DynWebPage）；
4. DynTemplate 插一行（Code=壳名、ViewPath 指向壳视图、DefaultJson 放 spec 骨架）；
5. 建页面实例，ParamsJson 写 spec；验收 `__shell.wires / warnings`。
