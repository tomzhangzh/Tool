# VueLibV4 动态页面体系 · 四层模型规范与使用指南

> 适用版本：`triscreen-blocks` 三屏积木架构 + `crud-basic` 基础 CRUD 模板。
> 目标读者：在 VueLibV4 上配置/开发动态页面的工程师。本文讲「每个概念是什么、规范怎么写、实际怎么用、易踩的坑」。

---

## 1. 总览：四层模型与职责划分

系统把「动态页面」拆成四个独立概念，各管一件事，互不越界：

| 层 | 实体/文件 | 职责 | 一句话 |
|---|---|---|---|
| **PageSetting**（页面区块） | 库表 `PageSetting` | 定义**一个区块**长什么样（组件树 + 数据骨架） | “筛选区/列表区/详情区”各自存一份 |
| **DynTemplate**（模板） | 库表 `DynTemplate` + `Views/DynTemplates/*.cshtml` | 定义**外观与积木之间如何流转**，接收实例参数 | 把若干 Block 串成一个整体 |
| **DynWebPage**（页面实例） | 库表 `DynWebPage` | 模板的**实例**，填了参数就能跑 | 一个页面 = 一个模板 + 一份参数 |
| **Block**（积木） | `Views/DynBlocks/{Filter,List,Detail}Block.cshtml` | 独立、可复用的功能单元 | 拼积木的最小模块，自带 createApp |

**边界铁律**：
- PageSetting 只存「组件树 config + default 骨架」，**不存 URL、不存项目**（ProjectId 仅作归属标记）。
- URL（save/list/filter）属于**模板实例参数**，由 DynWebPage.ConfigJson 提供。
- Block 不自查 PageSetting、不自带 URL，只读模板传下来的配置。
- 模板是树根，是唯一知道「我里面有哪几个 Block、各自参数是什么」的人。

## 2. 渲染入口与整体数据流

**入口**：`GET /Platform/Page/DynWebPage?id={DynWebPageId}` → `PageController.DynWebPage`。

```
DynWebPage(id)
   │  读实例 + 读其绑定的模板
   ├─ 模板 Code = "crud-basic"  → 控制器预组装 DynSharedModel（RawParams/EffectiveParams/三屏PageSetting…）→ 渲染
   └─ 模板 Code = "triscreen-blocks" → 直接把 DynWebPage 实例透传给模板 View，模板自己干活：
           ① ClayHelper 读实例 ConfigJson（TableName / URLs / 三个 PageSettingId / ChildFkField）
           ② PageSettingService 读 Filter / List / Detail 三个 PageSetting
           ③ 用 JObject 拼根 model（业务 key 由模板自定义）
           ④ 根 model 经 <script type="application/json" tag="dynmodel"> 注入根 app
           ⑤ 挂载顺序：先 mount 根 app → 再 mount 三个 Block（经 dyn.getApp 读根 model）
```

**关键机制**：组件的 `model` 由 **dynmodel script**（`<script type="application/json" tag="dynmodel">`）承载，**不是 `dynConfig.data()`**。`dynConfig.data()` 返回的是组件普通属性（`this.xxx`），不是 `this.model`。模板拼出来的共享上下文必须写进 dynmodel script，否则 Block 读不到。

## 3. PageSetting（页面区块配置）

### 3.1 字段

| 字段 | 说明 |
|---|---|
| `Id` | 自增主键 |
| `Code` | 业务编码，如 `blk-filter` |
| `Name` | 名称 |
| `SettingType` | `Filter`=筛选区 / `List`=列表区 / `Detail`=详情区 |
| `ProjectId` | 归属项目（DynProject.Id），可为空 |
| `TableName` | 关联业务表名（本区块操作哪张表），可为空 |
| `ConfigJson` | **组件树**：动态组件（DynCom）树，与设计器 PageJson 同构 |
| `RenderMode` | `Front`=前端 DynCom 动态控件 / `Back`=后端 Razor 局部视图 |
| `PartialPath` | RenderMode=Back 时的局部视图路径 |
| `DefaultJson` | **数据骨架 / 初始值**（按类型含义不同，见 3.3） |
| `SortNo` / `IsActive` | 排序 / 启用 |

### 3.2 三种类型的 ConfigJson 各存什么

| 类型 | ConfigJson（组件树） | DefaultJson（骨架） |
|---|---|---|
| **Filter** | 筛选区控件树（如课程名输入框） | 默认查询条件 `{ "字段": {"op":"like","value":null} }` 或 `{ "字段": 默认值 }` |
| **List** | 必须是 `{ "columns": [{field,label,width,...}, ...] }` | 一般不用（可空） |
| **Detail** | 表单控件树（输入框/下拉/文本域…，可带校验） | 新增时的初始骨架 `{ 字段: null/默认 }` |

### 3.3 ConfigJson 组件树结构（Filter / Detail 同构）

```json
{
  "component": "DynElContainer",
  "modelname": "",
  "options": {
    "comoptions": { "direction": "vertical" },
    "labeloptions": { "label": "", "required": false, "show": false }
  },
  "validators": [],
  "childrenctrls": [
    {
      "component": "DynElInput",
      "modelname": "Name",
      "options": {
        "comoptions": { "placeholder": "请输入课程名", "clearable": true },
        "labeloptions": { "label": "课程名", "required": false, "show": true }
      },
      "validators": []
    }
  ],
  "slots": {},
  "extendinfo": {}
}
```

- `component`：动态组件名（DynElInput/DynElSelect/DynElInputNumber/DynElContainer…）。
- `modelname`：绑定到 model 的字段名。
- `options.comoptions`：控件本身配置（placeholder/clearable/size…）。
- `options.labeloptions`：标签配置（label/required/show…）。
- 校验写在 `validators`（如 `{"type":"required","message":"不能为空"}`）。
- Detail 若含 `textarea` 或 json 选择器，向导默认让它占两列。

## 4. DynTemplate（模板）

### 4.1 字段

| 字段 | 说明 |
|---|---|
| `Id` | 自增主键 |
| `Code` | 模板编码，如 `crud-basic` / `triscreen-blocks` |
| `ViewPath` | 渲染用 Razor 视图，如 `~/Views/DynTemplates/TriScreenBlocks.cshtml` |
| `TemplateJson` | 模板自身的页面结构（外壳可选用的页面树） |
| `ConfigJson` | **实例参数 UI 定义**：描述这个模板接收哪些参数（含顶层 `mPassThrough` 透传） |
| `Category` / `Icon` / `SortNo` / `IsActive` | 分类、图标、排序、启用 |

### 4.2 实例参数 UI 由 ConfigJson 定义

模板的 `ConfigJson` 用动态组件树描述「该模板接收的参数面板」。用户建页面实例时按这个面板填参数，结果存进 DynWebPage.ConfigJson。

```
ConfigJson = {
  "type": "form",
  "mPassThrough": { "comoptions": { "labelWidth": "140px", "labelPosition": "right" } },
  "childrenctrls": [
    { "field": "TableName", "type": "input", "labeloptions": {"label": "数据表名", ...} },
    { "field": "ListUrl",   "type": "input", "labeloptions": {"label": "列表接口Url", ...} },
    ...
    { "field": "FilterPageSettingId", "type": "settingSelect", "labeloptions": {"label": "筛选配置Id", ...} },
    { "field": "ListPageSettingId",   "type": "settingSelect", "labeloptions": {"label": "列表配置Id", ...} },
    { "field": "DetailPageSettingId", "type": "settingSelect", "labeloptions": {"label": "详情/编辑配置Id", ...} }
  ]
}
```

**三屏模板（triscreen-blocks）的实例参数分类**（按区块分组，便于阅读）：
- **公共**：`TableName`（业务表名）。
- **List 相关**：`ListUrl`、`DeleteUrl`、`ListPageSettingId`。
- **Detail 相关**：`AddUrl`、`EditUrl`、`DetailPageSettingId`、`ChildFkField`（主子预填用）。
- **Filter 相关**：`FilterPageSettingId`。

其中 `FilterPageSettingId / ListPageSettingId / DetailPageSettingId` 是**系统表选择**（从 PageSetting 表选，不是手填数字）。

### 4.3 crud-basic vs triscreen-blocks

| | crud-basic | triscreen-blocks |
|---|---|---|
| 定位 | 免 Model CRUD 外壳 | 三屏积木组合（积木化） |
| 渲染参数 | 控制器组装 DynSharedModel 传入 | 直接透传 DynWebPage，模板自行拼 |
| 是否用 Block | 否 | 是（Filter/List/Detail 三块） |
| 通信 | 无（单屏） | 消息中心 + 手写订阅转发 |
| 项目维度 | URL 自动推导 | 请求体带 project（见 §8） |

### 5.1 字段

## 6. Block（积木）

### 6.1 三种积木

| Block | 视图 | 做什么 |
|---|---|---|
| FilterBlock | `Views/DynBlocks/FilterBlock.cshtml` | 筛选区：读 filterCfg 渲染控件，查询/重置时发 `filter.changed` |
| ListBlock | `Views/DynBlocks/ListBlock.cshtml` | 列表区：读 listCfg 渲染列，收 `loadData/reload` 命令，发 add/edit/addChild 事件 |
| DetailBlock | `Views/DynBlocks/DetailBlock.cshtml` | 详情/表单区：读 detailCfg 渲染表单，收 `newForm/editForm` 命令，保存后发 `detail.saved` |

### 6.2 双模式

每个 Block 都支持两种运行模式，靠**是否传 `data-root-ext-id`** 区分：

**组合模式（三屏模板用）**——Block 读模板根 app 的 model：

```html
<div id="…" data-dyn-mode="createApp"
     data-root-ext-id="Tsb{guid}-root"
     data-model-key="listCfg"
     data-msg-center-key="msgCenter" class="lb">
```

dynconfig 里：
```js
var __rid = element.getAttribute('data-root-ext-id');
var __rootApp = __rid ? dyn.getApp(document.getElementById(__rid)) : null;
var __ctx = __rootApp ? (__rootApp.model[element.getAttribute('data-model-key')] || {}) : {};
__ctx.msgCenter = __rootApp ? (__rootApp.model[element.getAttribute('data-msg-center-key')] || null) : null;
```

- `data-model-key` 决定读根 model 的哪个 key（模板自定义，Block 不预设固定 key）。
- `data-msg-center-key` 决定消息中心 key（约定缺省 `msgCenter`）。

**独立模式（脱离模板单独跑）**——Block 从自身属性读配置，自建消息中心：

```html
<div id="…" data-dyn-mode="createApp"
     data-blk-config="{...}" data-blk-default="{...}" data-blk-table="Course"
     data-blk-loadurl="…" data-blk-deleteurl="…" data-blk-project="…"
     data-blk-addurl="…" data-blk-editurl="…" class="lb">
```

### 6.3 根 model 的 key（由模板决定）

根 model 里**唯一固定的是 `msgCenter`**（通信基础设施，底层约定）；业务 key（`filterCfg / listCfg / detailCfg / childFkField`）由模板决定，Block 按传入的 `data-model-key` 动态读取。这样 Block 与具体模板解耦，可放在任何容器/弹窗/行展开里。

## 7. 消息中心（msgCenter）

> `wwwroot/dyn/blocks/message-center.js`，全局 `createMessageCenter()`。

**两种通信原语**：
- **Command（命令）**：定向发给指定 Block，一对一，返回 Promise，可捕获成功/失败。
- **Event（事件）**：广播发布，一对多，只读通知，不要求响应。

### 7.1 API

| API | 说明 |
|---|---|
| `createMessageCenter()` | 创建一个消息中心实例 |
| `registerBlock(blockId, handler)` | Block 注册自己可接收命令；返回注销函数 |
| `sendCommand(blockId, {cmd, ...payload})` | 发定向命令（下发给 `handler(cmd, payload)`） |
| `subscribeEvent(event, fn)` | 订阅广播事件；返回取消订阅函数 |
| `emitEvent(event, payload)` | 发布广播事件 |
| `destroy()` | 销毁：一次清空所有订阅/接收者（防泄漏） |

### 7.2 约定事件（Event）

| 事件 | 载荷 | 含义 |
|---|---|---|
| `filter.changed` | `{params: {字段:{op,value},…}}` | Filter 查询/重置 |
| `list.add` | `{}` | List 点新增 |
| `list.addChild` | `{row}` | List 点“+子”（主子） |
| `list.edit` | `{row}` | List 点行编辑 |
| `detail.saved` | `{action:'add'/'edit', row}` | Detail 保存成功 |

### 7.3 约定命令（Command）

| 目标 Block | 命令 | 载荷 | 含义 |
|---|---|---|---|
| list | `loadData` | `{filter}` | 带筛选重新加载（page 复位 1） |
| list | `reload` | — | 刷新当前 |
| detail | `newForm` | `{preFill}` | 新增（默认骨架 + preFill 浅合并） |
| detail | `editForm` | `{row}` | 编辑回填 |

### 7.4 模板手写订阅转发（树根接线）

积木之间**不直接通信**，一律经根 app 的消息中心，由模板**手写订阅转发**（模板知道里面放的是哪些 Block）：

```js
mounted() {
  var msg = this.model.msgCenter; // 根 app mounted 时实例化 createMessageCenter()
  this.__unsubs = [];
  this.__unsubs.push(msg.subscribeEvent('filter.changed', p => msg.sendCommand('list', {cmd:'loadData', filter:p.params})));
  this.__unsubs.push(msg.subscribeEvent('list.add', () => msg.sendCommand('detail', {cmd:'newForm', preFill:{}})));
  this.__unsubs.push(msg.subscribeEvent('list.addChild', p => msg.sendCommand('detail', {cmd:'newForm', preFill: preFillChild(p.row)})));
  this.__unsubs.push(msg.subscribeEvent('list.edit', p => msg.sendCommand('detail', {cmd:'editForm', row:p.row})));
  this.__unsubs.push(msg.subscribeEvent('detail.saved', () => msg.sendCommand('list', {cmd:'reload'})));
}
beforeUnmount() { this.__unsubs.forEach(f => f()); this.model.msgCenter.destroy(); }
```

### 7.5 主子预填

模板实例参数配置了 `ChildFkField`（如 `SourceId`）时，根 app 在 `list.addChild` 转发时把当前行主键预填到表单该字段：

```js
childPreFill(row) { const fk = this.model.childFkField; if (!fk) return {}; const pf = {}; pf[fk] = row ? row.Id : null; return pf; }
```

## 8. 数据接口与项目维度

### 8.1 dyndata 免 Model 接口

只要知道表名即可增删改查分页过滤（列全 nvarchar，无需实体类）：

| 路由 | 方法 | body |
|---|---|---|
| `/api/business/dyndata/search` | POST | `{table, page, size, filter, project}` |
| `/api/business/dyndata/insert` | POST | `{table, data, project}` |
| `/api/business/dyndata/update` | POST | `{table, data, project}` |
| `/api/business/dyndata/delete` | POST | `{table, keys:{Id}, project}` |
| `/api/business/dyndata/save` | POST | `{table, data, project}`（有主键→更新，无→新增） |

另有 `/api/platform/dyndata/*`（固定操作平台库 PlatformDb），与业务接口共用 `DynamicCrudService`。

### 8.2 项目维度：请求体 `project`（关键）

**项目定位走请求体 `project` 字段，不走 URL**：`req["project"]` → `ProjectDbResolver.Resolve(project)`，支持项目 **Code 或数字 Id**，缺省用 BusinessDb。

- 模板从 `DynWebPage.ProjectId` 读取，注入根 model：
  - `listCfg.project = Model.ProjectId?.ToString()`
  - `detailCfg.project = Model.ProjectId?.ToString()`
- ListBlock 的 `loadData`/`onDelete`、DetailBlock 的 `onSave` 请求体都会带上 `project`。
- 页面未绑定项目（ProjectId 为空）→ `project` 为空 → 接口走缺省 BusinessDb。

> **多项目务必绑定 ProjectId**，否则会串库。URL 本身不需要拼 project。

### 8.3 统一网络封装（DynCall）

所有 Block 请求统一走 `DynCall.post(url, body, {scopeEl})`（`wwwroot/dyn/dyn-call.js`）：
- 自动解包 `{code,data,message}` 信封；
- 按 `scopeEl` 显示 loading；
- 失败统一 toast，不逐处手写错误处理。

## 9. 关键技术约束（易踩坑）

1. **model 由 dynmodel script 承载**：模板/Block 的共享上下文、骨架必须写 `<script type="application/json" tag="dynmodel">…</script>`。写在 `dynConfig.data()` 里的是组件普通属性，不是 `this.model`。这是三屏曾经读不到配置的根因。
2. **dynconfig 必须顶层 `var dynConfig`**：mountCore 用 `new Function('element','dyn', scriptText)(el, dyn)` 执行，靠顶层 `dynConfig` 取回配置；且 script 建议加 `type="text/plain"`，避免浏览器原生执行裸 JS 抛 `element is not defined`。
3. **el-button 会拦截冒泡阻断 dyn 委托**：按钮用「原生 `<button>` + `el-button` 样式类」，保持视觉一致。
4. **不要调用 `dyn.rebindActions`**：generateSelector 每次点击动态生成，动作注册即生效；多次 rebind 会让 document 监听叠加（一次点击触发多次）。
5. **改静态 js / cshtml 后要强刷**：浏览器可能缓存，验证时加 `&nc=时间戳` 或开新 tab。
6. **改 C# 必须重新编译 + 重启服务**：cshtml / sqlite / js 改动即时生效，C# 改动需 `dotnet build` 后重启（Production exe 锁定 dll，build 前先停进程；工作目录要用项目根 `src/VueLibV4.Web`，否则 WebRootPath 找不到）。
7. **Block 不自查 PageSetting、不自带 URL**：配置一律由模板下发，保持积木可复用。
8. **Schema 校验暂未做**：后期再加；前期靠约定与模板拼装容错。

## 10. 从零做一个三屏页的步骤

1. **准备三个 PageSetting**（各一块）：
   - Filter 屏：ConfigJson = 筛选控件树，DefaultJson = `{字段:{op,value}}`。
   - List 屏：ConfigJson = `{columns:[…]}`。
   - Detail 屏：ConfigJson = 表单控件树，DefaultJson = 新增骨架。
2. **选模板**：用 `triscreen-blocks`（若页面是 Block 组合型）或 `crud-basic`（单屏 CRUD）。
3. **建页面实例 DynWebPage**：填模板参数面板 → `TableName`、三个 PageSettingId（系统表选择）、URLs、`ChildFkField`（主子预填用）；**绑定 ProjectId**。
4. **渲染**：访问 `GET /Platform/Page/DynWebPage?id={实例Id}`。
5. **验证**：强刷页面，确认根 model 的 `filterCfg/listCfg/detailCfg` 都在、List 能拉到数据、Filter 查询/重置能联动、Detail 新增/编辑/保存能回写。
