## 一、第一批：打通断链 + 统一内核（原则总纲/1/2/4/5）

### 1.1 去除 dyn-render.js，统一 DynDynamicCom

**现状核实**：

- [dyn-render.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-render.js)（V3 h() 内核）的实际引用只有 [dyn-com.js:51-52](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-com.js#L51-L52) 借用了 `DynRender.setPath`；其余只被死代码 dyn-designer.js 引用

**任务**：
1. 把 `getPath/setPath` 迁入 dyn-core.js（lodash 优先 + 自带降级实现，dyn-render 里已有现成代码）
2. dyn-com.js 改调 `dyn.setPath`

5. WebPageRender.cshtml 中的 `DynCore.normalize` 确认归一化逻辑归属（normalize 应在 dyn-core 或 DynDynamicCom 的 _BaseLayout 中，保证设计器/运行时同一份）

### 1.2 动作系统：字符串管道语法 + updateEl + 动作扩充（原则 1/2）

**新增语法（与现有分散属性语法并存）**：

```html
<button dyn-click="ActionHelper.Submit|ActionHelper.CloseWindow|ActionHelper.Toast('保存成功')">
  保存
</button>
```

- `dyn-click` / `dyn-change` / `dyn-init` 属性，值为 `|` 分隔的动作管道
- 每个动作：`ActionHelper.Name` 或 `Name`，支持括号内 JSON/字面量参数，且可与属性上的 `data-url`、`data-params` 合并
- 管道按序 await；某步返回 false 中止（与 chain 动作语义统一，chain 可保留作为"入库的可复用管道"）

**新增/补齐动作（全部加到 dyn-action.js，静态常量集中到文件头部）**：

| 动作 | 行为 |
|------|------|
| `updateEl` | `dyn-click-updateEl="#panel" data-url="/Xxx/Block"`：POST 提交 scope model → 取回 HTML 片段 → 替换 `#panel` innerHTML → 对新区块 `dyn.mount`（复用 dyn-core 已有的 fetchPartial + mount） |
| `submit` | updateEl 的语义化别名（提交表单到 data-url，成功后执行响应 dyn-actions） |
| `closeWindow` / `openWindow` | layui layer 关/开窗（替代现有 el-dialog 版 open/close，见 1.4） |
| `toast` | 已有，补 `showmessage` 作为别名，文档统一命名 |
| `setDynCom` | 运行时按选择器修改某 dyn 组件 cfg（V1 有） |
| `grid` | 列表区块刷新/翻页/查询（三屏模板落地后做，见第三节） |

### 1.3 后端 dyn-actions 通道（原则 1）

**现状**：前端 [postback](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-action.js#L339-L341) 和 [reload](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-core.js#L506-L508) 都已在响应 JSON 中找 `dyn-actions` 数组并执行；[DynJavaScript.cs](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/Infrastructure/DynJavaScript.cs) 已有 FlashMessage/Reload/Eval/Redirect/CloseDialog 五类。

**任务**：
1. [ApiResult.cs](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/Core/ApiResult.cs) 增加 `[JsonProperty("dyn-actions")] List<object> DynActions`
2. 增加 Controller 便捷写法：`ApiResult.Ok(data).WithActions(new FlashMessageJavaScript{...}, new ReloadJavaScript{...})` 或直接接收 params DynJavaScript[]
3. 统一前端执行器：runJsonActions 已在 postback 路径，确认 reload/updateEl/片段渲染路径全部覆盖
4. 示例范式（保存学生→刷新列表→关窗→提示，**控制器零前端 JS**）：

```csharp
[HttpPost]
public IActionResult SaveBlock(StudentForm form)
{

    return Ok(ApiResult.Ok(null, "保存成功")
        .WithActions(new ReloadJavaScript{ Selector = "#listPanel" },
```

### 1.5 数据库型组件后端：新建 DynCommonController 🔴（原则 4）

前端已有 8 处调用约定，按调用点反推接口（路径以现有 .cshtml 为准）：

| 接口 | 调用组件 | 实现要点 |
|------|---------|---------|
| `GET /api/dyncommon/options?projectId=&table=&valueField=Id&textField=Name` | ComDbSelect / ComSelect / DynSelect / ComRadio / ComCheckboxGroup / DynRadioGroup / DynCheckboxGroup | DynamicCrudService 查表，`SELECT valueField, textField`，返回 `{success,data:[{value,label}]}`（注意这些组件按 `res.success` 判断，信封用 success 格式或前端改适配） |
| `GET /api/dyncommon/dicts?type=xxx` | ComSelect / ComRadio / ComCheckboxGroup / DynSelect / DynRadio/CheckboxGroup | 平台 DynDict（type+code+name），返回相同 {value,label} 结构 |
| `GET /api/dyncommon/tablelist?projectId=` | ComLookup | 表+列元数据（已有 /api/business/dyndata/tables、columns，可内部转发或直接让前端改调） |
| `POST /api/dyncommon/upload` | ComUploadImage | 保存到 wwwRoot/upload 或配置目录，返回 url |

**DynSelect 能力增强**（原则明确点名）：comoptions 支持三种数据源
- `dictType`：字典
- `{table, valueField, textField, where, projectId}`：SQL 表查询（where 走参数化，禁止拼裸 SQL）
- `{url, labelKey, valueKey}`：ajax 请求
返回结构统一 `{value,label}`，并支持联动过滤参数（如 `parentValue: "{{model.DeptId}}"` 模板变量，复用动作系统的模板替换函数）。

## 三、第三批：模板三屏 + 页面生成（原则 7/8，本平台核心业务）

### 3.1 数据模型

新增 **PageSetting** 表（V1 概念，V4 重建）：

```
PageSetting: Id, Code, Name, SettingType(Filter/List/Detail),
             ProjectId, TableName, ConfigJson(组件配置树 JSON),
             ColumnDefsJson(字段级定义), SortNo, IsActive
```

DynTemplate 改造：
- TemplateJson 保留，但**模板首先是一个固定 MVC View**（如 `Areas/Business/Views/Templates/FilterListDetail.cshtml`），内部用 `data-dyn-init-createapp` 划三个区块 + 预置动作管道：
  - 查询按钮：`dyn-click="ActionHelper.UpdateEl('#listPanel')"` data-url 指向 List 片段
  - 列表行点击：打开 layer Detail 窗 / 或跳转 detail 区块
  - 保存：submit → 后端 dyn-actions 驱动 listPanel 刷新 + 关窗 + toast
- ConfigJson 存模板参数 schema（需要几个区块、各区块 PageSetting 选择器）
- 内置模板：`filter-list-detail`（三屏）、`list-detail`（两屏）、`list`、`single-form`、`tree-list`、`home`

DynWebPage 绑定关系（原则 7）：
```
DynWebPage: TemplateId + FilterPageSettingId + ListPageSettingId + DetailPageSettingId + Url + ConfigJson
```
渲染：DynWebPageController.Render 返回固定模板 View，模板内按三个 PageSetting 的 ConfigJson 用 DynDynamicCom 渲染各区块。也支持 WebPage 直接配 Url 走自定义页面（先做 DynWebPage 定义模式）。

### 3.2 从数据库表/字段生成页面配置（原则 8，重点功能）

新建"页面生成向导"（管理页内的 layer 弹窗，全部 dyn 组件搭建）：

1. 选项目（DynProject）→ 选表（/api/business/dyndata/tables）→ 加载列（/columns）
2. 字段列表勾选，每字段配置用途（复用 ColumnDefs 思路）：

| 生成目标 | 字段映射规则 |
|---------|-------------|
| **Detail** | 每个选中字段 → 一个表单项 DynElInput/Select/Date/Switch（按 DataType 选控件），label=列 Description/Name，modelname=列名 |
| **Filter** | 勾为查询条件的字段 → 过滤组件；生成的提交 model 形如 `{"ClassName":{"op":"like","value":"一"}}`——**界面上只出现 value 输入框，op 由字段配置决定、不显示**；提交时前端把 `model.FieldName.value` 包装成 filter 结构（op 在 PageSetting 配置中） |
| **Summary** | 勾选字段 → 表格列；行点击动作打开 Detail（新增带上行 Id） |

3. 输出三份 ConfigJson → 存三个 PageSetting → 自动创建 DynWebPage 绑定模板 → 给出生成的 Url

实现位置：`Areas/Business/Controllers/PageGenController.cs`（API：表字段→生成 cfg），UI 用设计器弹窗（3.3）或独立管理页。

### 3.3 DataTable 组件（原则 8 点名"做好了就太好了"）

- 优先把 **DynTable 做成真正可用的数据表格**：props 接 `{url/project/table/columns/pageSize}`，内部调免模型 page 接口；支持分页、排序（__orderby 白名单）、loading、空数据、行操作插槽、行点击事件
- 查询条件通过外层 scope model 传入（与 Filter 区块共享 scope，正是原则 2 的分块模型）
- 若周期紧，降级方案：生成器直接产出 **MVC View**（原则 8 允许）：后端按字段生成 cshtml 片段（List/Detail/Filter 三个 PartialView），模板直接引用——两条路线共用 PageSetting 元数据

### 3.4 设计器弹窗化（原则 4）

把现有整页设计器封装为一个**可嵌入 layer 的组件/页面**：

```
DynDesignerDialog.open({
  configJson: {...},      // 入参：组件配置树
  defaultModel: {...},    // 入参：数据模型示例
  title: '编辑配置'
}).then(({ configJson, defaultModel }) => { ... })  // OK 返回两个 JSON
```

- 内部就是现在的 LeftPanel/Canvas/RightPanel 四区（scope 共享模型已具备）
- 打开方式：layer.open type:1 内嵌，或 /Platform/Page/Designer?embed=1 作为 iframe
- 用途：PageSetting 编辑、组合组件编辑、任意 ConfigJson 字段配置——"所有 ConfigJson 都能在设计器配置"落地
- 顺带完成第一批遗留：TopBar 保存/新建/预览接线、dyn-designer.js 去留决策（能力并入 ops 后删除死代码）

4. 新页面一律 `data-dyn-init-createapp` 初始化；区块间通信用 shared scope 或 bus，不写全局函数
5. 后端片段端点约定：返回 PartialView（HTML 片段）或带 dyn-actions 的 ApiResult；路径与区块 id 在属性上声明
6. 信封统一问题（ComponentController 用 success、其余用 code）在 DynCommon 新建时一并决策——建议 dyncommon 内部也转 ApiResult，前端数据组件适配 code===0，最终全平台统一
7. SQL 数据源只走 DynamicCrudService 参数化，where 条件不允许裸拼接（__orderby 白名单顺带修复）
