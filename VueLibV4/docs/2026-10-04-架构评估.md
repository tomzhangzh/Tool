# VueLibV4 低代码平台 技术架构评估文档

> 评估日期：2026-10-04
> 评估对象：VueLibV4（ASP.NET Core 8 + SQLite + 自研动态 Block 引擎）
> 路线定位：**面向 .NET 开发者的混合式低代码快速开发平台**（不是零代码，不是全 JSON Schema）

---

## 一、项目概述

### 1.1 技术栈
- **后端**：ASP.NET Core 8 (Razor MVC)，SQLite，原生 SqliteClient
- **前端**：原生 JS 动态加载 partial cshtml，自研 DynKernel 插件内核
- **存储**：SQLite 双库（平台库 Platform.db + 业务库 Business.db）
- **UI**：Element Plus 风格，自研 Dyn* 组件 58+

### 1.2 核心路线
**不采用全 JSON Schema 驱动。** JSON 只存组件局部配置，页面主体靠 Razor 渲染；配置化搭建和手写原生代码可以在同一个页面共存。支持 Razor / Vue / HTML / jQuery 多种形态组件接入。

### 1.3 目录结构
```
src/VueLibV4.Web/
├── Areas/Platform/Controllers/   16 个 API 控制器
├── Core/                        ApiResult/中间件/Seeder/ViewHelper
├── Services/                     RazorComponentRenderer / ComponentService
├── Views/
│   ├── Platform/Page/           12 个业务页面
│   ├── DynBlocks/Apps/          6 个 Block（Filter/List/Detail/Tree/Tabs/Kanban）
│   ├── DynLayouts/              2 个布局
│   ├── DynTemplates/            13 个页面模板
│   ├── DynPages/Ext/            7 个页面扩展 partial
├── wwwroot/dyn/                 前端引擎 16 个 JS 文件
└── Data/                        SQL 初始化脚本
```

## 二、核心架构亮点

> ✅ = 强差异化亮点；⚠️ = 功能好但自带隐患，需工程化补齐

### 2.1 ✅ 拒绝全 JSON Schema，混合渲染模型
主流低代码把整个页面塞进 JSON，复杂场景 JSON 臃肿、排错困难。
本平台：JSON 只存组件参数，不作为页面完整描述。组件载体不限：Razor / Vue / HTML / jQuery 都能接入；DynSlotHost 插槽预留点位动态注入。
**配置化和原生手写代码在同一个页面共存。**

### 2.2 ✅ Block 契约 + Layout 主板式架构
Layout 是主板，管控时序、挂载、Pending；Block 是可插拔业务组件，继承统一基类，通信/事件/Payload 有固定规范。配套 BlockContractValidator 提前校验。

### 2.3 ✅ DynKernel 阶段化插件内核
`dyn-kernel.js`：core → components → params → services → actions → blocks → layout → designer → debug 九阶段装配。插件显式声明 requires，缺依赖直接报错；boot 后热装配；PENDING 队列防竞态。比多数自研低代码的 script 顺序加载干净得多。

### 2.4 ✅ JS Bridge 前后端双向通信
前端（Vue/jQuery/原生）可调后端 C#；后端也可推送事件给前端 Block。第三方 UI 库接入后不是孤立 iframe，而是纳入平台体系参与交互。

### 2.5 ⚠️ Vue Application 多层嵌套 + 标签自动挂载
打一个标记标签自动创建 Vue 实例；支持多层嵌套，实例隔离作用域，通过 JS 桥互通。
**隐患**：多层嵌套导致生命周期管理复杂，Tab 切换/页面关闭时必须逐层销毁，否则内存泄漏。

### 2.6 ⚠️ WithAction：后端主动下发 UI 指令
打破"前端请求、后端响应"模式。C# 可主动下发：打开窗体、关闭窗体、切 Tab、刷新组件。业务逻辑收敛在后端。
**隐患**：缺指令队列、幂等、白名单、审计日志。

### 2.7 ⚠️ DynDiv Debug 嵌入式调试面板
运行时查看组件清单、当前参数、绑定数据；在线临时改参数即时预览；检索按钮绑定的 ActionHelper。面向业务配置人员，不用看 JS 源码。
**隐患**：生产环境必须可关闭；调试修改和正式元数据要隔离。

### 2.8 ✅ ActionHelper 动作复用引擎
动作封装成可复用单元，页面/Block/Vue 实例都能调。C# 标记即暴露给前端。

### 2.9 ✅ 插件化组件体系，兼容第三方 UI 库
ElementUI / Ant Design / 自研 Vue 组件只要符合契约就能注册进平台，统一管理元数据、属性、事件、插槽。

### 2.10 ✅ PageGen 三屏生成器
读表结构 + 外键 + DynSchemaLabel 中文标签 → 一键生成 Filter+List+Detail 联动页面 + Wire 连线 + PageSetting。比竞品"生成孤立 CRUD"高一个层级。

### 2.11 ✅ 全套可视化调试工具链
- **PageGraphDemo**：Block 消息链路图（X6+Dagre 自动布局）
- **DbErGraph**：数据库 ER 图（字段级连线、在线编辑中文注释）
- **ComponentCheck**：组件单测预览

### 2.12 ✅ 多风格桌面工作台
Windows / macOS 风格桌面 Shell，窗口拖拽、任务栏、快捷方式，业务页面作为窗口嵌入。演示效果强。

### 2.13 ✅ FormItem Diff 红三角标记
表单改值后标签左上角红点，hover 看新旧值。单据场景实用。

### 2.14 ✅ DynSlotHost 插槽占位
固定 ID 占位容器，运行时动态注入 Block。支撑 TabsBlock 嵌套页面。

## 三、当前状态（P0+P1 已修复）

### 3.1 架构取舍（路线自带，不变）
1. 渲染依赖后端，交互实时性略弱（可用缓存缓解）
2. 设计器与运行时分离，实时预览难度高
3. 新 Block 需写 C#+Razor，纯业务人员不能从零造 Block

### 3.2 已修复（2026-10-04）
- ✅ **生命周期**：Layout destroy 级联销毁 Block 句柄 + dyn.unmount 销毁全部 Vue 实例
- ✅ **时序**：Ready 顺序显式定义（filter→master→detail→tree），不再依赖 DOM
- ✅ **看板**：BoardId 过滤、防重复加载、串行写 SQLite、去 Vue2 语法
- ✅ **Tabs**：动态 disabled、tab-change 绑定、openEdit 预标记子 tab
- ✅ **契约**：blocks-common requires 声明完整
- ✅ **数据库元数据**：FkList 空引用防护、表名转义

### 3.3 剩余工程短板（待补）
1. **P1 权限**：Block/字段级权限缺失，DynDiv/WithAction 无管控
2. **P1 异常处理**：Block 通信失败友好提示不足
3. **P1 缓存**：元数据每次查库，无 IMemoryCache
4. **P1 WithAction**：缺指令队列/幂等/白名单/审计
5. **P1 DynDiv**：调试修改与正式元数据隔离
6. **P2 测试**：无单元测试
7. **P2 样式隔离**：多前端栈共存 CSS 污染

## 六、一句话总结
