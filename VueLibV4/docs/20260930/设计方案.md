# VueLibV4 设计方案

> 文档版本：2026-09-30 · 对应代码库当前状态
> 阅读对象：需要理解平台整体架构、在其上二次开发或排障的工程师。

---

## 1. 总体目标与技术选型

在 V1 / V3 的经验上融合出 V4：**后端一个能跑的单体，前端一套无打包的 Vue UMD 体系，元数据驱动一切页面**。

| 层 | 选型 | 备注 |
|----|------|------|
| 后端框架 | ASP.NET Core 8 MVC（Areas） | 页面全部由 Razor View 返回，便于服务端注入配置 |
| ORM | SqlSugarCore 5.1.4.221 | 免模型 CRUD 用 `DbMaintenance` + `InsertableByObject` |
| 数据库 | SQLite（默认双库）/ SQL Server 可切 | Microsoft.Data.Sqlite 10 |
| JSON | Newtonsoft.Json（JObject 绑定） | 日期统一 `yyyy-MM-dd HH:mm:ss`，忽略循环引用与 null |
| Razor | **运行时编译**，视图不进 dll | `AddRazorRuntimeCompilation` + 三个 RazorCompile* 关闭项 |
| 前端框架 | Vue 3.5 UMD 全局构建（`vue.global.prod.js`） | h() 渲染配置树，无 SFC、无 vite/webpack |
| UI 库 | Element Plus（UMD）+ Tailwind + Layui | 均可由 DYN_LIB_CONFIG 开关 |
| 拖拽 | SortableJS + vue-draggable-plus（forceFallback） | 统一设计器/容器拖拽 |
| 其他前端 | CodeMirror、ECharts、lodash、axios、markdown-it | 本地 `wwwroot/lib`，无 CDN 依赖 |

## 2. 解决方案分层

三个项目，依赖方向单向向下：

```
VueLibV4.Web  ──→  VueLibV4.Platform  ──→  VueLibV4.Services
```

### VueLibV4.Services（基础层）

- `Data/Sugar/`：`ISugarService<T>` / `SugarService<T>` 泛型仓储，`DbFactory` 双库工厂、`ProjectDbResolver` 项目库解析。
- `Data/DynamicCrudService.cs`：**免模型动态 CRUD 核心**（建表/读元数据/分页/过滤/增删改）。
- `Emoji/`：`EmojiService` + 嵌入资源 `emoji-data.json`（1914 个 Emoji，中英名/分组）。
- `Dependency/`：标记接口 `IScopeDependency / ISingletonDependency / ITransientDependency` + 程序集扫描自动注册。
- `Extensions/`：Clay（JObject 动态取值）、JSON/List/Object/String 扩展。

### VueLibV4.Platform（平台层）

- `Models/`：11 张平台表模型 + Desktop / Menu 模型。
- `Services/PlatformServices.cs`：每个平台表一套 `IXxxService : ISugarService<T>`（桌面、菜单、字典、项目、模板、网页、页面设置、组件元数据、动作……）。
- `Services/PageGenService.cs`：页面生成向导的业务规则（读表 schema → 生成 Filter/List/Detail 三屏组件树 + DynWebPage）。
- `Data/PlatformServiceCollectionExtensions.cs`：`AddVueLibPlatform()` 一站式装配（双库、CRUD、项目解析、平台 ISqlSugarClient、DI 扫描）。

### VueLibV4.Web（站点层）

- `Areas/Platform/`：平台页面与 API（PageController、各元数据 Controller、Mgmt 后台）。
- `Areas/Business/`：业务域（DynData 免模型 CRUD、PageGen、Templates、业务字典）。
- `Areas/Component/Views/`：**所有动态组件的 Razor 定义**（ElementUI / Common）。
- `Controllers/`：`ComponentController`（组件定义拉取）、`DynCommonController`（emoji/options/dicts/upload 等通用接口）。
- `Core/Seeder.cs`：启动初始化与增量迁移；`Core/ApiResult.cs` 统一信封；`Core/DynSharedModel.cs` 三屏共享模型。
- `wwwroot/dyn/`：前端内核（见第 6 节）。

## 3. 启动管线

`Program.cs` 极简：

```csharp
builder.Services.AddControllersWithViews()
    .AddRazorRuntimeCompilation()        // ① .cshtml 运行时编译
    .AddNewtonsoftJson(...);             // ② JObject 绑定/统一日期
builder.Services.AddVueLibPlatform();    // ③ 平台层一站式装配
builder.Services.AddScoped<RazorComponentRenderer>();
builder.Services.AddScoped<ComponentService>();

new Seeder(builder.Configuration, app.Logger).Run();   // ④ 建库 + 种子 + 迁移
app.MapGet("/", () => Results.Redirect("/Platform/Page/Desktop"));
// Areas 路由 + 默认路由
```

### 3.1 Razor 视图不进 dll（当前明确的开发约定）

csproj 关键项：

```xml
<UseRazorSourceGenerator>false</UseRazorSourceGenerator>
<RazorCompileOnBuild>false</RazorCompileOnBuild>
<RazorCompileOnPublish>false</RazorCompileOnPublish>
<PackageReference Include="Microsoft.AspNetCore.Mvc.Razor.RuntimeCompilation" Version="8.0.11" />
```

效果：构建/发布产物中**没有 `*.Views.dll`**，`.cshtml` 以源文件形式输出，运行时编译；改组件视图刷新即生效。

### 3.2 Seeder 与增量迁移

- 双库独立初始化：`Platform.db`（平台）与 `Business.db`（业务）。
- 平台库脚本链：`platform.sql` → `component-meta.sql` → `seed-extra.sql` → `update-property-config.sql` → 代码内 `MigrateSchema()`。
- 幂等策略：`CREATE TABLE IF NOT EXISTS` / `WHERE NOT EXISTS` 补种子 / `PRAGMA table_info` 检查后 `ALTER TABLE ADD COLUMN` / 列 RENAME 保留数据。
- 自愈：检测到组件代际更新（如旧 `ElFormItem` 已不存在而新 `DynElContainer` 缺失）时清空 ComponentMeta 重跑种子。

## 4. 数据库设计

### 4.1 双库

| 库 | 连接串（appsettings.json） | 内容 |
|----|--------------------------|------|
| PlatformDb | `Data Source=App_Data/Platform.db` | 平台元数据 11 表 |
| BusinessDb | `Data Source=App_Data/Business.db` | 业务演示 3 表；真实项目可按 DynProject 挂多库 |

相对路径的 SQLite 文件基于 `AppContext.BaseDirectory` 解析，目录不存在自动创建。

### 4.2 平台 11 表

| 表 | 职责 |
|----|------|
| `ComponentMeta` | 组件元数据：命名/分类/LoadUrl/ViewPath/AllowDrop/PropsMeta/DefaultConfigJson 等 |
| `DynCom` | 可复用组件（组合件） |
| `DynTemplate` | 页面模板（外壳视图 ViewPath + DefaultJson + ConfigJson 参数表单定义） |
| `DynWebPage` | 页面实例（绑定 TemplateId + ConfigJson 实例参数） |
| `PageSetting` | **三屏区块配置**：Filter/List/Detail，ConfigJson=组件树或列定义，DefaultJson=model 骨架 |
| `DynProject` | 业务项目（独立连接串，免模型 CRUD 可按项目路由到不同库） |
| `DynDict` | 数据字典 |
| `DynActionHelper` | 入库动作（script/url/api/chain） |
| `DesktopSolution` / `DesktopShortcut` | 桌面方案分组 / 桌面快捷方式 |
| `SysMenu` | 系统菜单（树形 ParentId，桌面/开始菜单数据源，TargetType=Iframe/FullScreen） |

业务 3 表：`Student` / `Course` / `BusinessDict`（均带演示数据）。

## 5. 组件双定义源

### 5.1 设计原则

组件**代码优先落 Razor View**（可版本化、IDE 高亮、可调试），数据库只存"在设计器里如何展示与配置"的元数据；运行时拉定义。

| 源 | 位置 | 内容 | 优先级 |
|----|------|------|--------|
| ① Razor View | `Areas/Component/Views/{ElementUI,Common}/*.cshtml` | TEMPLATE / SCRIPT / STYLE 三段标记 | **高** |
| ② 数据库 | `ComponentMeta` 表 | 元数据 + 可选内容列（回退） | 低 |

解析顺序：View 有定义 → 用 View；否则回退 DB。列表接口合并 DB 行与文件扫描结果。

### 5.2 命名规范（当前代际）

| 体系 | 前缀 | 示例 |
|------|------|------|
| Element UI | `DynElXxx` | DynElInput / DynElSelect / DynElContainer / DynElButton |
| 公共 | `DynXxx` | DynForm / DynText / DynTable / DynCrudPage |
| NutUI（预留） | `DynNXxx` | — |

当前种子 31 个组件（容器 7 / 表单 13 / 基础 6 / 通用 5），加上 Razor 文件扫描补全，运行时注册表约 45 个组件。

### 5.3 装配链路

```
_Layout.cshtml
  ├─ @await Component.InvokeAsync("DynComRegistry")
  │     → ComponentService.GetEnabledListAsync()（DB + View 扫描合并）
  │     → <script id="dyncom-registry" type="application/json">[...]</script>
  ├─ dyn-lib.js（按序加载 Vue/EP/Sortable/... 与 11 个 dyn 模块）
  └─ @Html.RenderDynActions()（服务端注册的 data-dyn-init-* 隐藏 div）

GET /api/component/define/{name}
  → RazorComponentRenderer：IRazorViewEngine 渲染 cshtml 为字符串
  → 正则提取 TEMPLATE/SCRIPT/STYLE 三段 → { success, data: { templateContent, scriptContent, ... } }
前端 dyn-load-com.js：new Function 解析 export default → 注册 Vue 组件并缓存
```

### 5.4 组件树（cfg）结构

```jsonc
{
  "component": "DynElContainer",      // 组件名
  "__uid": "dyn-xxxx",               // 设计器内唯一标识
  "modelname": "name",                // v-model 绑定字段
  "options": {
    "comoptions": { },                // 组件业务属性
    "labeloptions": { "show": true, "label": "名称" },
    "itemoptions": { "class": "", "style": { } },
    "comlisteners": { "change": "actionCode" }
  },
  "childrenctrls": [ ],               // 子组件树（容器）
  "validators": [ ],                  // 校验规则
  "slots": { },                       // 命名插槽
  "extendinfo": { "vif": "", "vfor": "", "ref": "" }
}
```

运行时由 `dyn-core.js` 的 `DynRender` 递归 h() 渲染，每个节点统一经 `DynDynamicCom` 包装（designMode 钩子、overlay、选中、scope 继承都在这一层）。

## 6. 前端架构（无打包 UMD 体系）

### 6.1 dyn-lib.js 资源控制器

页面只需引一个 `dyn-lib.js`（当前版本 4.2.14），它串行加载：

```
Vue → jQuery → lodash → Element Plus(+icons) → Layui → Tailwind
→ SortableJS → vue-draggable-plus → CodeMirror → axios
→ dyn-load-com → dyn-com → dyn-core → dyn-call → dyn-validator
→ dyn-designer-ops → dyn-designer-sortable → dyn-action
→ dyn-designer-dialog → dyn-template → dyn-dsl
```

`window.DYN_LIB_CONFIG`（必须在 dyn-lib.js 之前赋值）可开关各库、关闭 evaljs。模块 JS 自带 `?v=` 版本号；样式表用 `asp-append-version` 哈希防缓存。

### 6.2 scope 共享模型（多 App 嵌套）

- 根元素 `data-dyn-shared-scope="designer" data-dyn-scope-json='{...}'` 声明一份 reactive model；
- 各分区 `data-dyn-use-scope="designer"` 挂独立 createApp，共享同一份 model（设计器的左栏/画布/右栏即如此通信）；
- 运行时 `window.dyn.getScopeModel(el)` 可反查 model，三屏 Block 之间通过 `dyn.getApp` 读根 model 协作。

### 6.3 设计器拖拽内核

基于 SortableJS（`forceFallback: true`，纯鼠标 fallback，不依赖 HTML5 拖拽）+ vue-draggable-plus（自动同步响应式数组）。

**容器配置要点（`dyn-designer-sortable.js`）：**

- 左侧组件库：`pull: "clone"` / `put: false` / `sort: false`；
- 画布容器：同组 `pull: true, put: true`，允许容器间移动与同容器排序；
- **不指定 `draggable` 选择器**，使用 SortableJS 默认 `">*"`（仅直接子元素）。

**嵌套容器的两个关键修复（本期）：**

1. **选择器穿透问题**：SortableJS 的元素匹配规则中，选择器以 `>` 开头才限定直接子元素；旧配置 `draggable:"[data-dyn-uid]"` 会让外层 Sortable 把内层容器的子组件也当成自己的拖拽项，跨层争抢导致内层拖不动。改为默认 `>*` 后各层只管直接子元素。
2. **透明包装层重复初始化**：`DynDynamicCom`（transparentMode）与真实容器组件挂同一根 DOM、都能看到同一个 `.dyn-children-wrap`。Sortable 初始化必须加 `!comExtra.transparentMode` 守卫，只让真实容器层绑定一次，否则残留的旧 mousedown 监听与内层实例冲突。

**拖拽三态视觉反馈：**

- `onStart` 给 `<body>` 加 `dyn-drag-active`：所有容器显示淡蓝虚线候选框，空容器占位文字隐藏；
- `onMove` 调 `canAccept()`（组件 AllowDrop 白名单 + 禁止放入自身/自身后代）：可放→绿框 `dyn-container-hover`，不可放→红框 `dyn-container-denied` 并 `return false` 拦截；
- `onEnd / onUnchoose` 清状态、刷 overlay。

**选中层不包装 DOM**：悬浮 overlay 是独立的绝对定位层（`pointer-events:none`），只在顶部工具条处开放交互，避免破坏组件自身布局与事件。

## 7. 三屏积木体系（四层模型）

| 层 | 实体/文件 | 职责 |
|----|----------|------|
| **PageSetting** | 库表，SettingType=Filter/List/Detail | 一个区块的组件树（ConfigJson）+ 数据骨架（DefaultJson）+ RenderMode(Front/Back) |
| **DynTemplate** | 库表 + `Views/DynTemplates/*.cshtml` | 外壳：定义区块如何拼装流转，接收实例参数 |
| **DynWebPage** | 库表 | 模板的实例：TemplateId + ConfigJson 参数（TableName / 三个 PageSettingId / URLs） |
| **Block** | `Views/DynBlocks/{Filter,List,Detail}Block.cshtml` | 最小可复用功能单元，自带 createApp，只读模板下发的配置 |

**边界铁律**：PageSetting 不存 URL/项目；URL 属于实例参数；Block 不自查配置；模板是唯一的树根。

**两种运行路径**（`PageController.DynWebPage`）：

- `crud-basic`：控制器预组装 `DynSharedModel`（RawParams → EffectiveParams，TableName 自动推导 dyndata 接口 URL → 三屏 SettingBundle）→ 渲染外壳；
- `triscreen-blocks` / `filterlist-crud` / `tree-detail`：把实例透传给模板，模板自行用 PageSettingService 读三屏、拼 dynmodel、按序挂载根 app 与 Block。

`TableName` 自动推导：实例只填表名时，自动补 `/api/platform/dyndata/search`、`/save?table=`、`/delete?table=`，手填 URL 优先。

> 完整规范见仓库文档 `docs/动态页面与三屏积木体系规范.md`。

### 页面生成向导（PageGen）

`/Platform/Page/PageGen` + `PageGenService`：选项目 → 读 SQLite schema → 按列类型规则一键生成：

- **Filter**：只生成条件控件（主键/时间/长文本不进筛选），DefaultJson 为 `{列:{op,value}}` 条件骨架，按钮归外层；
- **List**：`{columns:[...]}` 列定义，Back 模式走 Razor 局部视图；
- **Detail**：表单控件树 + 校验 + 新增初始骨架；
- 同时创建绑定三屏的 DynWebPage。

## 8. 免模型动态 CRUD

- `DynamicCrudService` 用 `SqlSugar.DbMaintenance` 读主键/列元数据，`InsertableByObject` / `UpdateableByObject` 落库；
- 按列 DataType 自动转换（INT/BIT/DECIMAL/DATETIME2），字符串走 NVARCHAR；
- 过滤规范：`{ "字段": 值 }` 精确匹配，或 `{ "字段": { "op": "like|gt|lt|in|between|eq", "value": ... }, "__orderby": "Id desc" }`；
- 多库路由：`project` 参数（DynProject Code/Id）→ `ProjectDbResolver` 解析连接串；缺省走 BusinessDb；
- 约定：**写操作全 POST**（search/insert/update/delete/save），只读 GET（tables/meta/page/all/get/render）。

## 9. 动作系统与校验

- 动作入库 `DynActionHelper`，前端启动 `/api/platform/dynactionhelper/all` 动态注册；四类：`script / url / api / chain`（chain 支持 when 条件）。
- 内置动作：postback / postdata / confirm-postdata / reload / open / close / updateel / evaljs / load / setVueModel / showmessage / redirect；内置优先、DB 兜底。
- 属性委托：`data-dyn-{event}-{action}` 事件委托 + `data-dyn-init-{action}` 初始化委托，服务端 `@Html.RenderDynActions()` 输出隐藏 div，init 扫描执行。
- script 上下文：`$action / $args / $ctx / $api`，可访问 lodash；另有 `DynBus` 事件总线。
- 校验器 `dyn-validator.js`：required/email/phone/pattern/min/max/length/custom，可转 ElementPlus rules。

## 11. 当前已知取舍

1. **运行时内核沿用 V3 配置树模型**（h() + DynDynamicCom 递归），没有整体换成 V1 的 jQuery partial 模型；V1 的动作语义已在 dyn-action 内补齐。
2. **无前端构建链路是刻意选择**：换取零构建、Razor 改完即刷的开发体验；代价是没有 SFC 与 TS 类型检查，组件靠三段标记约定。
3. **默认 SQLite、无认证**：定位为内网/企业内网低代码平台；运行时设计器入口由 `Dyn:ShowRuntimeDesignEntry` 配置控制显隐；危险动作 evaljs 可全局关闭。
4. **SQL Server 切换需要手工适配种子 SQL**：建表脚本仅维护 SQLite 方言。
5. **组件 filter 策略**：input/textarea/button/img 在设计器中不直接承担拖拽手柄（保留原生交互），排序通过容器外层或结构树完成。
