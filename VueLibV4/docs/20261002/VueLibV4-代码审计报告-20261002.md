# VueLibV4 全量代码审计报告（2026-10-02）

> 审计方式：**只读扫描，未改动任何代码**。以当前代码为准（历史文档/飞书总结可能滞后）。
> 审计范围：`src/VueLibV4.Web`（Controllers/Core/Services/Views/wwwroot/dyn）、`src/VueLibV4.Services`（Data/Rpc/Dependency）、`src/VueLibV4.Platform`。
> 运行库：.NET 8 + SqlSugar + Razor 运行时编译；前端 Vue3 UMD + Element Plus + 自研 Dyn* 内核。

## 一、系统现状画像

```
浏览器
 └─ wwwroot/dyn/
     ├─ dyn-kernel.js        阶段化插件内核（core→components→params→services→actions→blocks→layout→designer→debug）
     ├─ dyn-core.js          App 挂载/台账/嵌套掩码/卸载/片段注入/参数 watch/扩展合并
     ├─ dyn-params.js        统一参数上下文（L0 显式 → L1 静态 → L2 Model → L3 父链 → L4 URL；fork/shared/commit/watch）
     ├─ dyn-blocks-common.js Block 句柄（createBlockHandle reg/send/on/emit/destroy + CONTRACTS 端口声明）
     ├─ dyn-layout-engine.js 布局壳（shell/slot/wire 连线 + 端口静态校验 + 默认连线）
     ├─ dyn-call.js          统一信封 {code,msg,data} + 按元素隔离 loading + silent
     ├─ dyn-rpc.js           JS 直接调 C#（service 代理 + eval 自由代码）
     └─ dyn-com.js / dyn-action.js / dyn-dsl.js / dyn-designer-*  组件渲染/动作链/DSL/设计器

后端
 ├─ /api/dyndata/*           统一免模型 CRUD（DynamicCrudService），数据域由 body.project 决定
 │                            （空=业务库，__platform__=平台库，Code/Id=项目独立库）
 ├─ /api/rpc/*               能力桥：services 目录 / invoke 反射调用 / eval DynamicExpresso 执行 C#
 ├─ /api/platform/dynwebpage/* 页面装配（render / paramschema / ext-skeleton）
 ├─ DbFactory                SqlSugarClient 工厂（SQLite/SqlServer）
 ├─ ProjectDbResolver        project 坐标 → 物理库
 ├─ SugarService<T>          强类型服务基类（IDependency 标记自动注册 DI）
 └─ DynPageExt               页面扩展视图槽位（真实 cshtml 逃逸口，Razor 模板委托）
```

**一句话总结**：这是一个"配置驱动 + 独立 VueApp 积木 + 显式句柄接线 + 统一数据端点"的低代码底座，并且已经长出了两条差异化能力——**JS↔C# RPC 桥** 和 **Razor 扩展视图逃逸口**。架构野心明显，且关键机制（参数链、句柄、布局壳）在代码里是**真做了且自洽的**，不是 PPT。

## 二、亮眼与值得肯定的地方（先说好的）

这些不是客套，是代码里实打实做对的设计，建议作为后续演进的"宪法"保留：

1. **DynKernel 阶段化插件内核**（dyn-kernel.js）：加载期只登记、boot 时按固定阶段顺序装配，依赖缺失在启动期就 console.error 跳过而不是运行时散架；boot 后再 register 的插件立即热装配；`__DYN_KERNEL_PENDING__` 兜底乱序加载。**前端工程化程度在同类低代码里少见。**

2. **DynParams 参数体系设计成熟**（dyn-params.js）：L0–L4 优先级 + 就近覆盖 + fork 子作用域 + shared 跨兄弟共享 + commit 发布 + watch 跟随 + resolveValue 占位（`$params.x` / `$model.x` / `$result.x` / `{{...}}` 行内插值）。这是整套系统最有"统一约定"味道的一块。

3. **Block 句柄显式接线**（dyn-blocks-common.js）：`createBlockHandle` 在 mounted 后静默、destroy 后全部静默防悬垂；命令未注册时把 role/已注册命令/元素位置一起 console.warn（"点了没反应"变成"看得见的报错"）；`introspect()` 运行时排查；CONTRACTS 静态声明端口。**从"隐式广播猜消息"升级成"显式契约"，方向完全正确。**

4. **布局壳三分**（dyn-layout-engine.js）：shell（真代码）/ slot（BlockApp）/ wire（连线）分离；wire 对 CONTRACTS 做端口静态校验，连到不存在的端口立即告警；壳默认连线 vs 页面连线分层；`$event.x` / `$provide.x` 模板参数。**这是把"积木怎么拼"从手写 JS 往声明式又推了一步。**

5. **App 生命周期管得细**（dyn-core.js）：WeakMap 台账 + `__dynChildApps` 级联卸载、嵌套 App 掩码（dyn-host + #dyn-holder）、mount 幂等守卫、并发重入共享（`__dynMounting` 同一个 Promise）、失败 `rollbackMasked` 还原占位符。**嵌套/远程片段这种最容易内存泄漏和孤儿 App 的地方，都有专门处理。**

6. **SQL 注入防护是两道防线**（DynamicCrudService）：表名/列名过 `IdentRx` 白名单正则 + `EnsureTable` 校验表真实存在 + `QuoteIdent` 方括号转义 + `__orderby` 正则白名单（只允许"列名 asc/desc"单字段）。**在"免模型、按表名裸查"这种高风险模式下，防护意识是对的。**

7. **"失败变吵"哲学贯穿全栈**：未知筛选列、不支持的 op、in/between 值格式错，都通过 `PageResult.warnings` 回流前端 console.warn，而不是静默吞掉返回全量。**配置错误尽早暴露，这和你"简单但不捆手脚"的理念一致。**

8. **统一数据端点 + 数据域路由**（/api/dyndata + ProjectDbResolver）：Block 不需要知道任何 URL，`project` 一个坐标决定走业务库/平台库/项目库。**一处数据、多库路由，收敛得干净。**

9. **RPC 能力桥**（RpcController/RpcEvaluator/DynQueryFluent）：前端 `dyn.service('XxxService').Method(...)` 反射调 DI 服务；`dyn.eval(...)` 用 DynamicExpresso 跑 C#，且**参数与代码分离**（args 走 JSON 不拼进代码）；`DynQueryFluent<T>` 把字符串 lambda 编译成表达式树下推 SQL，不全表拉内存。**这是真正打通前后端业务逻辑的一步，且默认数据安全意识在线。**

10. **Razor 扩展视图逃逸口已落地**（DynPageExt.cs + ExtSkeleton）：`DynExtSlots` 字典（`{block}:{区域}` key）+ Razor 模板委托，`LoadPageExtAsync` 克隆 ViewData、`IsValidPath` 防路径穿越、文件已存在不覆盖。**你说的"简单但要足够灵活、给手写留口子"，代码里已经实现了，不是空想。**

11. **统一信封 + 细节防护**：ApiResult 统一 `{code,msg,data}`、异常永远 JSON 不冒 HTML 黄页、`SafeJson` 转义 `</` 防 script 提前闭合、`NullValueHandling.Ignore`。

12. **历史兼容不硬迁移**：`SlotSettingId`/`SlotValue` 新结构优先、旧扁平键（ListUrl/AddUrl…）回退，老数据原样跑。**在"既要统一又不能搞崩历史"这件事上，分寸是对的。**

13. **SugarService<T> 强类型基类**：标准 CRUD/Page/Save，`FillIdentity` 反射回填自增 Id；IDependency 标记接口自动扫描注册 DI。**业务服务写起来很轻。**

## 三、问题清单（按优先级，带文件出处）

### P0 — 安全（你说后置，这里只列风险点，不要求现在做）

| # | 位置 | 问题 |
|---|------|------|
| S1 | `DynDataApiController` | `/api/dyndata/*` **无鉴权、无表白名单**。只要表存在，任何人可 POST search/save/delete 读写删任意表。生产必须先加鉴权 + 表白名单/行级权限。 |
| S2 | `RpcController.cs:116-117` | `Dyn:Rpc:Enabled` 与 `EvalEnabled` **默认都是 true**。`/api/rpc/eval` 可执行任意 C#（文件、进程、读库）。生产必须默认关 eval，只开 invoke。 |
| S3 | `RpcServiceCatalog.GetCallableMethods` | `Describe()`/invoke 暴露服务**全部 public 实例方法**（含 Delete/Save/批量写），无方法白名单。应只暴露标记了 `[RpcCallable]` 的方法。 |
| S4 | `dyn-core.js:434/511/791` | `new Function('element','dyn', code)` 执行 dynconfig/dynconfig-ext/片段内联脚本。这是你"少写 JS"的代价，但意味着**下发什么 HTML 就执行什么 JS**，和 S1/S2 叠加后风险放大。 |

### P1 — 性能（当前小数据没事，上量会疼）

| # | 位置 | 问题 |
|---|------|------|
| F1 | `DbFactory.NewDb` / `PlatformServiceCollectionExtensions:24` | **SqlSugarClient 不池化**：Platform 的 `ISqlSugarClient` 是 Scoped 工厂，每请求 new 一个 client；业务库 `Resolve()` 也 new。SqlSugarClient 本身线程安全可单例复用，反复 new 白白建连接/配置。 |
| F2 | `ProjectDbResolver.Resolve:44-50` | 每次数据请求都**开平台库查一次 DynProject** 解析连接串，无缓存。应缓存 `project→连接串`（失效随项目编辑刷新）。 |
| F3 | `DynamicCrudService.EnsureTable/Page/Columns` | 每个请求都 `GetTableInfoList` + `GetColumnInfosByTableName`（查 information_schema），**元数据无缓存**。一张表的列结构很稳定，应按 `db+table` 缓存几分钟。 |
| F4 | `DynamicCrudService.First:111` | `First` 走 `Query()` 拉**全表再 FirstOrDefault**，单行查询变全表扫描。应直接 `Where(...).Take(1)`。 |
| F5 | `DynamicCrudService:108/206/481` | 查询绕一道 `ToDataTable()` 再手撸 `DataRow→JObject`，比直接动态映射慢一倍。 |
| F6 | `RpcEvaluator.CreateInterpreter:58` | eval **每次 new Interpreter**，DynamicExpresso 的表达式/委托没有编译缓存。同一段代码重复执行会重复编译。可按 code 哈希缓存 Delegate。 |
| F7 | `RpcEvaluator:59-61 / 166-168` | 超时靠 `Task.WhenAny(work, Task.Delay)` **赛跑**，超时即返回但**工作线程不真正取消**（DynamicExpresso/反射同步方法不响应取消）。高并发下慢请求会堆积线程。 |
| F8 | `RpcEvaluator.UnwrapTaskAsync:221-231` | 解包 Task 用 `task.Wait(200)` **轮询 busy-wait**，空转占线程。 |
| F9 | `RpcEvaluator.LastResultTruncated:28` | scoped 服务的**实例字段**，并发请求互相覆盖这个标志位（日志不准）。应放进返回 DTO。 |
| F10 | `TreeApp.cshtml:95` | 树一次 `size:100000` **拉全表到内存**组树，无懒加载。菜单/部门这种几十条没事，上千节点会卡。 |

### P2 — 一致性 / 真实 bug

| # | 位置 | 问题 |
|---|------|------|
| B1 | `TreeApp.cshtml:96` vs `DynamicCrudService.Page` | **前后端契约脱节**：TreeApp 请求体传 `sort:{field,order}`，但后端 `Page()` 只认 `filter.__orderby`，根本不读 `sort` 字段——排序条件被静默忽略，最后靠前端 `buildTree` 内存排序兜住。要么后端实现 `sort`，要么前端别传。 |
| B2 | `DynWebPageController.Render:89 / 106` | 同一个 `_templates.GetById(row.TemplateId)` **调了两次**（tpl/tpl2），多查一次库。 |
| B3 | `DynamicCrudService.Insert:243` | 自增主键取回失败时 `catch { return 1; }` **静默返回假 Id=1**，前端拿到错误主键。应抛错或返回真正的 identity。 |
| B4 | `Views/Platform/Mgmt/DynWebPageMgmt copy.cshtml` | **遗留副本文件**（带 "copy"），应删除，避免以后改错文件。 |
| B5 | `dyn-core.js` 1080 行 | God object：mount/unmount/render/reload/fetch/mask/scope/serialize/ext-merge 全在一个文件。不影响运行，但维护时定位慢，建议按职责拆 3–4 个模块。 |
| B6 | `dyn-core.js:204-263` | **双弹窗体系并存**：layui layer 优先，降级 ElementPlus ElMessageBox，再降级原生 `confirm()`。两套 UI 库（layui + Element Plus）同时加载，风格和体积都不统一。 |
| B7 | `dyn-call.js:26-43` | mask 注释说"按 el 计数 count"，实际**没有计数**：`showMask` 见到 `__dynMask` 就 return、`hideMask` 直接删。同元素并发两个请求，先完成的会把另一个的 loading 提前关掉。 |
| B8 | `dyn-blocks-common.js:166` | `scan()` 里 `if (!out[role])` ——**同 role 出现多个 Block 只取第一个句柄**，页面放两个 ListApp 会丢一个。应支持数组或带序号 role。 |

## 六、头脑风暴：50 条改进建议

> 按"投入小见效快 → 长期价值"排序，不必全做，挑顺眼的。

### A. 立刻能修的小硬伤（1–10）
1. 修 B1：后端 `Page()` 实现 `sort` 字段，或前端 TreeApp 改成传 `filter.__orderby`，别让契约各说各话。
2. 修 B2：`Render()` 里 `_templates.GetById` 只调一次。
3. 修 B3：`Insert` 自增取回失败就抛异常，别 `return 1` 骗人。
4. 删 `DynWebPageMgmt copy.cshtml`。
5. 修 B7：DynCall 的 mask 改成引用计数，并发请求不互相抢 loading。
6. `First()` 改成 `Where(...).Take(1).ToList()`，别全表。
7. `DynWebPageController.Render` 里 `paramsjson` 和 `configjson` 写同一份——加个 TODO，明确废弃期后只留一个。
8. `ProjectDbResolver.Resolve` 加个内存缓存（ConcurrentDictionary，项目编辑时清）。
9. `DynamicCrudService` 的列元数据按 `dbConn+table` 缓存 5 分钟。
10. `DbFactory` 的 Platform/Business client 改成单例复用（IsAutoCloseConnection 已开，client 本身可复用）。

### B. 安全（你说后置，但记着）（11–18）
11. 给 `/api/dyndata` 和 `/api/rpc` 加鉴权中间件（哪怕先写死内网/开发态开关）。
12. `Dyn:Rpc:EvalEnabled` 生产默认改 `false`。
13. 给可被 RPC invoke 的方法加 `[RpcCallable]` 标记，`GetCallableMethods` 只返回带标记的。
14. 表白名单：平台元数据表（Dyn*）和业务表分开，业务表需要配置才允许 dyndata 访问。
15. eval 加代码长度 + 频率限制（MaxCodeLength=20000 有了，再加每分钟调用次数）。
16. RPC 异常日志里别回显完整 code（现在日志打 code 前 200 字符，够了，但响应 msg 别带堆栈）。
17. `DynPageExt.IsValidPath` 已做防穿越，保持；同时限制 ExtViewPath 只能在 `Views/DynPages/Ext/` 目录下。
18. 生产关闭 Razor 运行时编译（预编译视图）。

### C. 性能（19–26）
19. `RpcEvaluator` 按 code 哈希缓存 DynamicExpresso 的 Delegate（同代码不重复编译）。
20. RPC 超时不要靠 `Task.WhenAny` 假赛跑——至少文档写清楚"超时后线程继续跑"，慢查询用 SqlSugar 命令超时。
21. `UnwrapTaskAsync` 别 busy-wait，改成 `await Task.WhenAny(task, Task.Delay(...))`。
22. `LastResultTruncated` 从实例字段移到返回 DTO，并发不串。
23. TreeApp 大表支持懒加载（按父节点展开时再查子级），别一次 10 万行。
24. `DataTableToJson` 手撸转 JObject 换成直接 `Queryable<dynamic>().Select`，少一层 DataTable。
25. DynParams 的 `makeView.touch` 每次递归整条父链，深层嵌套页面可优化成只 touch 当前层。
26. DynBlocks.search 的列表请求加防抖（FilterApp 输入即查时）。

### D. 一致性 / 架构裂缝（27–36）
27. 统一弹窗：只留 Element Plus，把 layui layer 的依赖剥掉（现在双套并存）。
28. `DynBlocks.scan` 支持同 role 多个实例（返回数组或按 role:序号）。

30. 历史 PageSetting 的 columns 扁平格式 vs 新 childrenctrls：写一个适配器在前端统一转成组件树，别在后端 `BuildSlotValues` 里 switch 散落。

34. DetailApp 的按钮固化问题：已经有 `list:toolbar` 扩展槽了，把 DetailApp 也补上 `detail:buttons` 槽，别再写死 Save/Cancel。

### E. 开发者体验 / 少写 JS（37–44）
37. 三屏生成器加"右侧实时预览"（你之前提的：选完表立刻看到 filter/detail/list 长什么样，满意再入库）。
38. 动作可视化配置面板：把"打开弹窗/刷新列表/调后端 service/跳转"做成下拉选项，参数从 `$params` 映射，不用写 GS。

40. Markdown DSL 补全：写一个 `dyn.dsl` 的实时预览 + 错误定位（第几行哪个字段错）。
41. 设计器里接 `/api/rpc/services`，让"调后端 service"的参数面板有方法签名智能提示。
42. 模板市场/导入导出：把模板 JSON 导出成文件，团队内复用。
43. 一键"恢复模板默认值"：配置改乱了回退到 DefaultJson。
44. 运行时给 DynCom 渲染的组件打个角标（"由动态控件渲染"），点击直接开设计器——你之前提的，辨识度+快速调整。

### F. 自举与长期价值（45–50）
45. 用本平台生成"组件管理"页面做第一个自举试点（生成真实 cshtml，边做边补组件缺陷）。

49. 把"失败变吵"再推一步：warnings 不只 console，在页面右上角攒一个可点开的小铃铛（DynDebug 浮层已有雏形）。
50. 写一页"三分钟上手"：建表 → 选模板 → 配参数 → 出页面，配截图。自举页面本身就是最好的文档。

## 七、结论

这套系统的**架构判断是对的**：插件化内核、统一参数链、显式句柄、布局壳、RPC 桥、Razor 扩展逃逸口——每一块都是冲着"内部复杂交给框架、使用者只管配置"去的，而且大多已经落地，不是概念。

现在它卡在 **6.5 分**，主要不是设计问题，而是三类工程债：
1. **安全裸奔**（你有意后置，记着就行）；
2. **几处明确的性能浪费和小 bug**（client 不池化、元数据每次查、sort 契约脱节、假 Id）——这些是投入很小、收益很大的；
3. **零测试 + 双轨残留**——决定了它能不能从"自己跑着顺"变成"敢给别人用"。

按上面路线图走，阶段一补完小硬伤就到 7.5；阶段二加鉴权和测试到 8.5；阶段三自举 + 收敛裂缝到 9+。**不需要推翻重来，只需要在现有正确方向上把工程债清一清。**
