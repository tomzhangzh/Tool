# VueLibV4 使用手册

> 面向三类使用者：**业务页面开发者**、**配置/设计器使用者**、**框架扩展者**。
> 所有示例均按当前代码约定书写；参数与端点细节见 [02-API参考](./02-API参考.md)。

---

## 1. 环境与启动

| 项 | 值 |
|---|---|
| SDK | .NET 8（`net8.0`） |
| 数据库 | SQLite（平台库 + 业务库，连接串见 `appsettings.json`） |
| 默认地址 | `http://localhost:5010`（`appsettings.json:Urls`） |
| 启动配置 | `Properties/launchSettings.json`：HTTP `5116`、HTTPS `7273` |

```powershell
# 工作目录：e:\Tom\Tool\VueLibV4
dotnet restore
dotnet build
dotnet run --project src/VueLibV4.Web/VueLibV4.Web.csproj
```

> 两处端口不一致（5010 vs 5116）是已知现状：`dotnet run` 若读取 launchSettings 会走 5116；以控制台输出为准。
> `Seeder` 启动初始化在 `Program.cs` 中被注释，**首次运行不会自动建表**，需先准备 `App_Data` 下的数据库文件。

登录：`admin / admin123`（`POST /api/platform/permission/login`）。开发期 `Dyn:Auth:Enabled` 默认关闭；`Ai:ApiKey` 为空时 AI 生成会返回配置缺失错误。

## 3. 第一个页面

### 3.1 方式 A：手写 Razor + 约定式启动（推荐入门）

```html
<!-- Views/.../MyFirst.cshtml -->
<div dyn-init="CreateApp"
     data-dyn-url="/Platform/Block/Load?blockName=filter-list&webpageId=1">
</div>

@section Scripts {
<script>
DynLib.ready(function () {
    // 此时 dyn / DynCom / DynActionHelper / DynCall 已就绪
    console.log('actions:', DynActionHelper.actionList().length);
});
</script>
}
```

`dyn-init="CreateApp"` 会在 `DynLib.ready` 后自动发起片段加载并挂载，无需手写 `Vue.createApp`。

### 3.2 方式 B：手动挂载 JSON 配置

```js
DynLib.ready(async function () {
    var res = await dyn.fetchPartial('/api/platform/pagesetting/get?id=12'); // 返回 ApiResult
    var cfg = {
        model: { Name: '', Status: 1 },
        components: res.data.config,        // 组件树（ConfigJson 解析结果）
        config: { component: 'DynElForm' }
    };
    dyn.mount(document.getElementById('host'), cfg);
});
```

### 3.3 方式 C：裸标签直接写

```html
<div id="app">
  <dyn-el-form :model="model" label-width="100px">
    <dyn-el-form-item label="姓名" required>
      <dyn-el-input v-model="model.Name" placeholder="请输入" clearable></dyn-el-input>
    </dyn-el-form-item>
  </dyn-el-form>
</div>
<script>
DynLib.ready(function () {
  Vue.createApp({ data: () => ({ model: { Name: '' } }) }).mount('#app');
});
</script>
```

> 组件由 `DynCom.ensureRegistered` 按 `/api/component/list` 自动注册，无需逐个 `app.component`。

## 4. 组件配置（设计器/PageGen 产物）

### 4.1 组件节点

```json
{
  "component": "DynElSelect",
  "modelname": "Status",
  "options": {
    "comoptions": {
      "placeholder": "请选择",
      "sourceType": "dict",
      "dictType": "CommonStatus",
      "clearable": true
    },
    "labeloptions": { "label": "状态", "required": true }
  },
  "validators": [{ "type": "required", "message": "请选择状态" }],
  "childrenctrls": []
}
```

### 4.2 选项数据源

| `sourceType` | 必配 | 说明 |
|---|---|---|
| `static` | `optionValuesText` 或 `optionValues` | 每行 `值,标签`，优先级最高 |
| `dict` | `dictType` | `GET /api/dyncommon/dicts?type=` |
| `table` | `table`/`valueField`/`textField` | `GET /api/dyncommon/options` |
| `sql` | `sql` | `GET /api/dyncommon/sqloptions` |
| `ajax` | `ajaxUrl` | 自定义接口（返回数组） |

### 4.3 属性联动与条件

```json
{
  "options": {
    "bindings": {
      "comoptions.disabled": "{{ $model.Status === 0 }}",
      "labeloptions.label":  "{{ $model.Type === 'A' ? '甲类名称' : '名称' }}"
    },
    "evalCondition": "if ($model.Status === 0) return { comoptions: { readonly: true } };"
  }
}
```

- `bindings` 优先级：静态属性 < `bindings` < `evalCondition`。
- 可写 `comoptions.x` / `labeloptions.x` / `itemoptions.x` / `shell.x`。
- 容器可用 `compassthrough` 把父级属性下发给子组件（白名单模式）。

### 4.4 校验

```json
"validators": [
  { "type": "required", "message": "必填" },
  { "type": "pattern", "pattern": "^[A-Z]{2}\\d{4}$", "message": "格式 AAnn" },
  { "type": "custom", "expr": "$model.End >= $model.Start", "message": "结束不得早于开始",
    "enableWhen": "$model.Mode === 'range'" }
]
```

父容器通过元素 `__dynValidate()` 聚合子组件 `__dynErrors`，失败时阻止提交（DetailApp 已内置）。

## 5. 动作管道

### 5.1 内置动作用法

```html
<!-- 提示 -->
<el-button dyn-click="Toast('保存成功')">保存</el-button>

<!-- 管道：请求 → 提示 → 刷新 -->
<el-button dyn-click="PostBack|Toast('已提交')|Reload">提交</el-button>

<!-- 带参数 -->
<el-button dyn-click="OpenWindow({ url:'/Platform/Detail/Modal?id=14', title:'详情', width:'900px' })">
  打开详情
</el-button>
```

- 管道用 `|` 分隔；上一步返回值进入 `ctx.$result`。
- 任一步返回 `false` 中止后续；抛错被管道捕获并 `showMessage('error', ...)`。
- 事件名即动作名（大小写不敏感，`ActionHelper.` 前缀可省略）。

### 5.2 常用动作速查

| 场景 | 动作 |
|---|---|
| 请求后处理 | `PostBack` / `PostData` |
| 局部刷新 | `Reload`、`UpdateEl`（别名 `Submit`/`ReloadTarget`） |
| 表格操作 | `Grid`（刷新/选中/导出等） |
| 弹窗 | `Open`(`OpenWindow`)、`Close`(`CloseWindow`)、`SetWin`(`SetWindow`) |
| 反馈 | `Toast`(`showMessage`)、`Notify`、`Confirm` |
| 模型 | `SetVueModel`、`SetVar`、`Calc`、`SetParams`、`SetAttr` |
| 流程 | `Chain`、`Delay`、`Switch`、`TriggerEvent`、`Redirect` |
| 工具 | `Copy`、`Download`、`EvalJs` |

### 5.3 自定义前端动作

```js
DynActionHelper.defineAction('SaveCustomer', async function (options, ctx) {
    var ok = await dyn.confirmAsync('确定保存？');
    if (!ok) return false;
    await DynCall.post('/api/dyndata/save', {
        table: 'Customer',
        data: ctx.model,
        project: ctx.params.project
    });
    dyn.showMessage('success', '保存成功');
}, {
    label: '保存客户',
    group: '业务',
    doc: '把当前 model 保存到 Customer 表',
    options: [{ name: 'table', type: 'string', desc: '默认 Customer' }],
    example: `dyn-click="SaveCustomer({ table:'Customer' })"`
});
```

注册后即可在任意模板用 `dyn-click="SaveCustomer"`，也会自动出现在「动作助手」Demo 页。

### 5.4 数据库动作

在 `DynActionHelper` 表新增一行（`IsEnabled=1`）：

| 字段 | 示例 |
|---|---|
| `Code` | `ApproveOrder` |
| `ActionType` | `script` / `api` / `chain` / `url` |
| `ParmsJson` | `{"url":"/api/business/order/approve","method":"post"}` |
| `ScriptCode` | `/* script 类型：可直接写 JS，ctx 同上 */` |

前端启动时 `GET /api/platform/dynactionhelper/all` 自动注册，调用方式与内置动作一致。

## 6. 用 Block + 布局壳搭建页面

### 6.1 三步

1. **准备配置**：为筛选/列表/详情各建一条 `PageSetting`（可用 PageGen 生成）。
2. **建页面实例**：`DynWebPage` 写 `SpecJson`（布局、槽位、连线）。
3. **访问**：`/Platform/Shell/PageRender?code=xxx`。

### 6.2 SpecJson 示例

```json
{
  "layout": "filter-list-open-window",
  "layoutProps": { "split": 300 },
  "slots": {
    "filter": { "block": "filter", "settingId": 12 },
    "master": { "block": "list",   "settingId": 13, "model": { "pageSize": 20 } },
    "detail": { "block": "detail", "settingId": 14 }
  },
  "wires": [
    { "from": "filter.changed", "to": "master.loadData", "with": "$event" },
    { "from": "master.add",     "to": "detail.newForm" },
    { "from": "master.edit",    "to": "detail.editForm", "with": "$event" },
    { "from": "detail.saved",   "to": "master.reload" },
    { "from": "detail.saved",   "to": "shell.closeDetail" },
    { "from": "detail.cancel",  "to": "shell.closeDetail" }
  ]
}
```

### 6.3 Block 端口备忘

| 角色 | 可发命令 | 会发事件 |
|---|---|---|
| filter | `submit` | `changed` |
| list | `loadData`、`reload` | `add`、`edit`、`addChild` |
| detail | `newForm`、`editForm` | `saved`、`cancel` |
| tree | `reload` | `nodeClick`、`addRoot`、`addChild` |

排错三件套：浏览器控制台 warning（未注册命令/槽位缺失）、`/Platform/Block/Inspector?webpageId=`、`DynDebug` 浮层。

### 6.4 自定义 Block

```js
// 在 Block 视图的 Scripts 中
DynLib.ready(function () {
    var cfg = DynBlocks.fetchConfig(document.currentScript.closest('[data-blk-role]'));
    var h = DynBlocks.createHandle(document.getElementById('blk-root'));
    h.reg('loadData', function (payload) { /* 加载 */ });
    h.onReady(function () { /* 首屏初始化，禁止在此 emit */ });
    h.emit('changed', { filter: {} });   // 仅用户交互后发
});
```

## 7. 页面生成与 AI

### 7.1 规则生成

1. 进入 `/Platform/Page/PageGen`；
2. 选择项目库 → 表 → 勾选字段与控件；
3. 预览 JSON → 生成，自动落库三条 `PageSetting` 与一条 `DynWebPage`；
4. 如勾选「生成布局壳」，同时生成可运行的 `/Platform/Shell/PageRender` 页面。

API：`POST /api/business/pagegen/generate`（落库）、`/preview`（仅预览）。

### 7.2 AI 生成

`POST /api/business/pagegen/ai`

```json
{ "prompt": "做一个客户列表，按姓名搜索，可新增编辑，列表显示姓名/手机/状态", "tableName": "Customer", "project": "demo" }
```

返回 `{filter,list,detail,reasoning}`。要点：

- 组件名必须来自 `/api/platform/componentmeta/all` 提供的清单，否则被 `ValidateConfigTree` 剔除并降级为默认控件。
- `Ai:ApiKey` 为空时直接报错；模型/端点见 `Ai:Model`、`Ai:BaseUrl`。
- 生成结果建议先在设计器里走一遍再落库。

### 7.3 模板导入

`/Platform/Page/Demo/TemplateImport` 演示「粘贴 Element 模板 → `DynTemplate` 转换」：`dyn-template.js` 的 `TAG_MAP` 同时兼容 `el-form`/`elform`、`el-form-item` 自动扁平化。

CLI 侧亦可直接调用：`DynTemplate.parse(html)` / `DynTemplate.toHtml(tree)`（以页面内 `window.DynTemplate` 为准）。

## 9. 权限配置

1. 登录后进入权限矩阵：`/Platform/Permission/Grid?roleId=1`。
2. 资源键约定：
   - 操作级：`Customer|Delete`；
   - 字段级：`Customer.Phone`（配合 `data-permission-field`）；
   - 页面级：`DynWebPage.ResourceKey`。
3. 前端声明：

```html
<el-button data-permission-op="Customer|Delete">删除</el-button>
<el-button data-permission-op="Customer|Delete" data-permission-mode="hide">删除</el-button>
```

4. 后端**必须**再校验一次：`PermissionFilter` 只保证登录，资源级授权需在控制器/服务中显式判断。
5. 行级过滤：实现 `IPermissionHook`（参考 `DemoRowLevelHook`）并在 `Program.cs` 替换注册。

## 11. 常见坑（按出现频率排序）

1. **TDZ**：`_BaseLayout` 的 `setupScripts` 早于 `modelinfo` 声明。任何 setup 内同步读 `modelinfo` 都可能抛 `ReferenceError`；用 `try { void modelinfo } catch { nextTick(retry) }`。
2. **`el-form` 小写标签**：Element 模板里 `<elform>` 需经 `TAG_MAP` 归一，手写模板请用 `dyn-el-form`。
3. **组织层级**：`el-form-item` 会被扁平化，不要假设它一定生成嵌套节点。
4. **配置键驼峰**：新代码统一小写键（`comoptions`），旧键仅在迁移期被自动改写。
5. **`comExtra` 不落库**：其中放引用/函数，写进 `jc.options` 会导致 JSON 序列化失败或导出丢函数。
6. **layer 层级**：Element 弹层 z-index 基准 20000000，高于 layui；自定义弹窗不要低于此值。
7. **Seeder 被注释**：新环境没有表 → 所有 API 500；先执行建库脚本。
8. **端口**：`Urls=5010` 与 `launchSettings=5116` 不一致，联调前确认实际端口。
9. **AI Key**：`Ai:ApiKey` 必须留空提交；填真实值会被 GitHub push protection 拦截。
10. **DB 动作不生效**：确认 `IsEnabled=1` 且 `Code` 与模板中调用名完全一致；`/script` 可用来核对生成结果。
11. **Block 首屏无数据**：检查 `slots` 名是否与壳期望一致、`settingId` 是否有效、控制台是否有「未注册命令」warning。
12. **手写请求绕过权限**：`fetch/axios` 直连不会带 `X-Requested-With`，也绕开统一错误处理；统一用 `DynCall`。
13. **旧菜单 URL 404**：存量数据库需执行 `src/VueLibV4.Web/Data/migrate-routes-20261027.sql`，把 `/Platform/Page/*` 等旧路由迁移到新路由，否则历史菜单/快捷方式打开会 404。
