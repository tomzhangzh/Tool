# VueLibV4 框架设计

> 基线：2026-10-27 当前工作区代码（解决方案 `VueLibV4.sln`，三个项目，.NET 8 + Vue 3 + Element Plus）。
> 本文只描述**代码里真实存在**的机制；评估与改进建议见 [04-框架评估](./04-框架评估.md)。

---

## 1. 总体定位

VueLibV4 是一个「**配置驱动 + 积木编排**」的低代码页面框架，通常被描述为三层能力叠加：

| 层 | 形态 | 关键词 |
|---|---|---|
| 渲染层 | Vue 3 组件树 | 组件注册表、配置树、DynDynamicCom 递归渲染 |
| 编排层 | Block（独立 Vue App）+ 布局壳（shell）+ 连线（wire） | 端口契约、句柄、ready 握手 |
| 数据层 | 统一数据端点 + 动态 CRUD + RPC 能力桥 | project 数据域、DynamicExpresso |

页面既可以**手写 Razor 视图**直接使用组件，也可以由 **PageSetting 配置 + SqlSugar 动态 CRUD** 完全驱动，还可以由**布局壳 + Block** 拼装。

## 3. 前端内核：显式插件装配（dyn-kernel）

这是当前版本最重要的架构演进：从「`<script>` 顺序 + 全局鸭子类型」升级为**声明式插件契约**。

[dyn-kernel.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-kernel.js#L1-L128)

```js
DynKernel.register({ name, stage, requires, setup(ctx) })
```

| 阶段（严格顺序） | 含义 | 典型插件 |
|---|---|---|
| `core` | 挂载内核 | dyn-core |
| `components` | 组件注册与动态加载 | dyn-com、dyn-load-com |
| `params` | 参数上下文 | dyn-params |
| `services` | 请求/RPC/事件总线 | dyn-call、dyn-rpc、dyn-eventbus |
| `actions` | 动作管道 | dyn-action |
| `blocks` | 积木公共契约 | dyn-blocks-common |
| `layout` | 布局壳运行时 | dyn-layout-engine |
| `designer` | 设计器 DSL | dyn-dsl |
| `debug` | 调试浮层 | dyn-debug |

关键特性：

- `ctx.provide(name, api)` / `ctx.use(name)`：显式能力表，未 provide 时回退全局（`Vue`/`axios`）。
- `requires` 缺失 → 插件 `skipped` 并 `console.error`，不中断其他插件。
- `setup` 抛异常 → 插件 `failed`，内核继续。
- **热装配**：`boot()` 完成后再 `register` 的插件立即执行（供 AJAX 片段/按需引入）。
- **乱序兜底**：先于内核加载的模块把描述推入 `window.__DYN_KERNEL_PENDING__`，内核加载后消费。

### 3.1 资源加载器

[dyn-lib.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-lib.js)

- 版本 `4.4.4`；模块 URL 优先取服务端烘焙的内容哈希 `window.DYN_ASSET_HASHES`，缺失时回退版本号，实现「改文件即失效缓存」。
- 顺序加载第三方库（Vue、jQuery、Lodash、Element Plus + Icons、Layui、Tailwind、Sortable、vue-draggable-plus、CodeMirror、axios）后，再顺序加载 18 个 dyn 模块，最后 `DynKernel.boot()` → `DynLib._fireReady()`。
- `_fireReady()` 自动扫描 `document.body` 执行 `dyn.initActions`，并统一注入 `X-Requested-With: XMLHttpRequest`。

> 该链是**串行**的（`chain.reduce`），首屏成本直接等于「全部脚本下载 + 顺序解析」之和，见评估文档性能项。

## 4. 页面加载与渲染链路

```
浏览器 GET /Platform/Shell/Desktop
  └─ PageShellController.Desktop()             → Areas/Platform/Views/Page/Desktop.cshtml
      └─ _ViewStart → _BaseLayout?              （页面壳）
          └─ <div dyn-init="CreateApp" data-dyn-url="...">   （约定式启动）
              └─ DynLib.ready → dyn.initActions → ActionHelper.CreateApp
                  └─ dyn.fetchPartial(url)      → 片段 HTML 或 JSON 配置
                      └─ dyn.mount(el, cfg)     → Vue.createApp
                          ├─ DynCom.setupApp     （Element Plus + Icons + 注册表）
                          ├─ DynCom.ensureRegistered('/api/component/list')
                          └─ 递归渲染：DynDynamicCom → 具体组件 → _BaseLayout
```

### 4.1 dyn-core（挂载内核）

[dyn-core.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-core.js#L1106-L1156) 暴露的统一对象（`dyn === dynCore === DynCore`）：

| 能力组 | API |
|---|---|
| 配置/常量 | `VERSION`（4.0.0）、`CFG`、`normalize`、`clean`、`deepClone` |
| 元素与作用域 | `resolve`、`findAncestor`、`closestDynInit`、`getApp`、`getClosestApp`、`getProxy`、`getModel`、`getScopeModel` |
| 挂载 | `mount`、`mountConfig`、`unmount`、`render`、`html` |
| 片段与表单 | `fetchPartial`、`serializeForm`、`collectParams`、`reload`、`setDynCfg`、`getVueModel` |
| 参数 | `params`、`attachParams` |
| 路径 | `getByPath`、`setPathVal`（优先 lodash `_.set`） |
| UI | `showMessage`、`confirmAsync`、`getLayer` |
| 扩展 | `installActionApi`（把动作 API 平铺到 `dyn.*`） |

`mount` 的要点（[L531-L649](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-core.js#L531-L649)）：读取 `dynconfig`/`dynmodel` → `DynCom.setupApp` + `ensureRegistered` → `Vue.createApp` → 挂载后注册 `__dynApp` 幂等句柄、执行初始化动作、扫描 Block 句柄。

### 4.2 dyn-com（组件注册表）

[dyn-com.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-com.js)

- `ensureRegistered(app)`：清单只拉一次（模块级 `_regPromise`），但**对每个 createApp 各注册一次**——否则设计器四分区中后挂载的 app 里 `dyn-*` 会退化为未注册自定义元素。
- 组件来源：`GET /api/component/list` → 每项含 `ComponentName`、`LoadUrl`、`isComposite`、`compositeConfigJson`。
- `DynLoadCom(name)`：`defineAsyncComponent` 懒加载 `GET /api/component/define/{name}`，返回 `{templateContent, scriptContent, styleContent, meta}`；样式按组件名去重注入。
- `DynCom.register/get/meta/loadMeta`：`loadMeta` 拉 `/api/platform/componentmeta/all`，解析 `PropsMeta`/`AllowDrop`/`SlotsDefine`。
- Element Plus 以 `zIndex: 20000000` 安装，确保弹层高于 layui layer（基准 19891014）。

### 4.3 组件配置契约（_BaseLayout）

所有 `Dyn*` 组件共用 [Areas/Component/Views/Common/_BaseLayout.cshtml](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/Areas/Component/Views/Common/_BaseLayout.cshtml) 的 `comConfig`。默认结构即落库契约：

```json
{
  "component": "DynElInput",
  "modelname": "UserName",
  "options": {
    "comoptions": {},
    "comlisteners": {},
    "labeloptions": { "label": "", "required": false, "show": true },
    "itemoptions": { "style": {}, "class": "" },
    "wrapperoptions": {},
    "compassthrough": "comoptions.size,labeloptions.labelposition,labeloptions.labelwidth",
    "uiGlobalProps": { "size": null, "disabled": null },
    "defaultLabelOptions": { "labelwidth": "auto", "requiredmark": true },
    "evalcondition": ""
  },
  "validators": [],
  "childrenctrls": [],
  "slots": {},
  "extendinfo": {}
}
```

核心机制：

> **机制层与视图分离**：合并、表达式求值、属性穿透、选项加载、校验五类机制实现于 [dyn-node-config.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-node-config.js)（纯函数，无响应式/DOM 依赖，可被 node 直接单测）；`_BaseLayout` 只保留 props、响应式接线与模板。对外入口 `window.DynNodeConfig`（别名 `DynNode`）；设计器拖放与画布 Sortable 生命周期由 `DynNodeConfig.bindDesignerNode` 承载。

1. **两种输入模式**
   - 配置树：`jsonconfig`（落库 JSON，设计器/PageGen 产物）；
   - 裸标签：不传 `jsonconfig` 时用 `label/required/placeholder/comoptions/labeloptions/...` 合成内存配置（`directMode`），复用同一套逻辑。
2. **配置键契约（单一权威，全小写无分隔）**：`options` 下框架定义的组固定为 `comoptions / labeloptions / itemoptions / wrapperoptions`，字符串型键为 `compassthrough / evalcondition`；`labeloptions` 子键为 `label / show / required / labelposition / labelwidth`。运行时**不做任何驼峰兼容**，历史数据由 `Data/migrate-configkeys-20261027.sql` 一次性迁移（2026-10-27 起）。
3. **值绑定四通道**（`modelinfo` computed）：
   - `modelexpr`（只读）+ `modelsetexpr`（写回）；
   - `parentmodelinfo` + `modelname`（路径绑定，容器通过 `parentModelPrefix` 拼前缀）；
   - `v-model`（`modelValue` / `emit('update:modelValue')`）；
   - 组件内部 `ref`。
4. **选项数据源** `comoptions.sourceType`：`static | dict | table | sql | ajax`；`optionValuesText` 每行「值,标签」优先于 `optionValues`。
5. **属性穿透**：容器 `provide('comExtraPass')`，子组件按 `compassthrough` 白名单继承父值；`passThroughWhiteListMode` 控制是否启用白名单。
6. **属性关联 `bindings`**：键为 `comoptions.x` / `labeloptions.x` / `itemoptions.x` / `shell.x`，值为 `{{ expr }}`；优先级 `静态 < bindings < evalcondition`。
7. **`evalcondition`**（联动脚本）：在 model 任意字段变化时执行一段脚本，返回 `{shell, labeloptions, comoptions}` 补丁；`DYN_LIB_CONFIG.disableEvalJs` 可全局关闭。
8. **校验**：`validators[]` 支持 `required/min/max/length/pattern/email/phone/number/custom`，可用 `enableWhen` 条件启用；结果写回根元素 `__dynErrors`/`__dynValidate` 供父级聚合。
9. **运行时扩展槽 `comExtra`**：只放 ref/reactive/函数（如 DynTable 的 `rows/loadList`），禁止写入 `jc.options`，不参与 JSON 导出。
10. **TDZ 规避**：`setupScripts` 位于 `modelinfo` 声明之前，任何引用 `modelinfo` 的早期逻辑必须 `try { void modelinfo } catch { nextTick(retry) }`——`loadComOptions` 即按此实现。

## 6. Block 积木体系

### 6.1 设计三分

| 概念 | 归属 | 职责 |
|---|---|---|
| Block | 独立 Vue App | 完整业务能力（筛选/列表/详情/树/看板/页签…），自读 `data-blk-config`，不依赖根 App |
| Shell | 真代码视图 | 只负责布局与自身 UI 状态机（分隔条等），声明 `slots`/`defaultWires`/`commands`/`onMount` |
| Wire | 配置 | `{ from:'node.event', to:'node.cmd'|[...], with?: 模板 }` |

### 6.2 端口契约

[dyn-blocks-common.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/blocks/dyn-blocks-common.js#L24-L29)：

| 角色 | 命令（输入） | 事件（输出） |
|---|---|---|
| `filter` | `submit` | `changed` |
| `list` | `loadData`、`reload` | `add`、`edit`、`addChild` |
| `detail` | `newForm`、`editForm` | `saved`、`cancel` |
| `tree` | `reload` | `nodeClick`、`addRoot`、`addChild` |

后端在 [BlockContracts.cs](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Platform/Models/BlockContracts.cs) 用强类型镜像了这些契约（含 `FilterConditionPayload`、`DetailSavedPayload`、`WireSpec`、`PageLayoutSpec`），用于文档与静态校验对齐。

### 6.3 句柄与挂载时序

`createBlockHandle(element)` 提供：`reg(cmd, fn)`、`onReady(fn)`、`ready()`、`send(cmd,payload)`、`on(evt,fn) → off`、`emit(evt,payload)`、`introspect()`、`destroy()`。

关键约定：

- **mounted 阶段只做自身初始化，不得发对外事件**；外事件只能由用户交互触发。
- 引擎绑完全部 wire 后按 `filter → master → detail → tree → 其余 → shell` 顺序调用 `ready()`，保证首屏事件不丢且不重复加载。
- 命令/端口未注册时**失败变吵**：`console.warn` + `DynDebug.note`，不再静默 reject。

### 6.4 布局壳运行时

[dyn-layout-engine.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/layouts/dyn-layout-engine.js#L180-L304) 的 `DynLayouts.mount(root)`：

1. 并发挂载壳内全部 `[data-dyn-mode="createApp"]`；单个失败只记 warning，不连累全局。
2. `[data-layout-slot]` → `{ 槽位名: handle }`；缺失记 warning。
3. 校验槽位期望角色 vs 实际放置角色。
4. 执行壳 `onMount`（可返回 `dispose`）。
5. 合并 wire：壳 `defaultWires`（`origin:'default'`，缺失槽位安静跳过）+ 页面 `wires`（`origin:'page'`，缺失即报错）；`replaceDefaultWires` 可整替。
6. `ready()` 握手。
7. `destroy()` 逐层回收：wire off → disposers → block handle destroy → `dyn.unmount`。

已注册壳（`Views/DynLayouts`）：`list-master-detail`、`tree-master-detail`、`filter-list-open-window`、`filter-list-drawer`、`filter-list-drawer-left`。

Block 视图：`Views/DynBlocks/Apps/{FilterApp,ListApp,DetailApp,TreeApp,TabsBlock,KanbanBoardBlock,WidgetApp}.cshtml`。

### 6.5 数据面

Block 不需要配置任何 URL，统一走 [dyn-blocks-common.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/blocks/dyn-blocks-common.js#L46-L85)：

```text
POST /api/dyndata/search   {table,page,size,filter,sort?,project?}
GET  /api/dyndata/get      ?table=&id=&project=
POST /api/dyndata/save     {table,data,project?}   （按主键自动判增/改）
POST /api/dyndata/delete   {table,keys:{Id:..},project?}
```

`project` 数据域：省略 = 默认业务库 `BusinessDb`；`__platform__` = 平台元数据库 `PlatformDb`；其他 = `DynProject.Code/Id` 独立库（`ProjectDbResolver`）。

## 7. 参数上下文 DynParams

[dyn-params.js](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Web/wwwroot/dyn/dyn-params.js) 维护一棵**挂载点上下文树**：

- `DynParams.ensure(el, parentEl)`：建立/复用上下文；`attach(el)`：片段注入接入最近上下文。
- `fromEl(el)`：任意元素取所属上下文；`byId(id)`：游离容器交接（`data-dyn-ctx`）。
- 能力：`set`/`get`/`commit`/`fork`/`watch`/`view`/`resolveValue`/`destroy`。
- 值模板占位符：`{{$params.x}}`、`{{$model.x}}`、`{{$result.x}}`（也支持裸 `$params.x` / `$result.x`）；缺失时保留占位以暴露配置错误。
- 变更轨迹：`DynParams.trace()`（最近 100 条，新→旧）、`onTrace(fn)`。

页面级参数面板（ParamsJson）由 `/Platform/Block/ParamsPanel` / `/Platform/Block/SaveParams` 端点配合 `dyn-dsl` 的 `extractProps` 驱动，形成「模板参数 → 页面实例参数」的可视化编辑闭环。

## 8. 动作管道（DynActionHelper）

```js
defineAction(code, fn, meta)   // 注册；返回规范化后的小写 code
DynActionHelper.run(code, options, ctx)   // 大小写不敏感
DynActionHelper.actionList()   // 内置 + DB，含文档/示例
```

- **命名契约**：注册表键统一小写（`defineAction('SetVueModel')` → 存为 `setvuemodel`）；解析/取元信息大小写不敏感，管道执行不受影响。
- **参数契约**：`ACTION_DOCS[].options[]` 用 `{ name, aliases[], type, desc }` 表达主名与别名（如 `{name:'selector', aliases:['target']}`），不再用 `'selector|target'` 字符串编码别名。
- **33 个内置动作**（按用途归类，详见 API 文档）：应用/请求、刷新/加载、弹窗/窗口、消息/确认、模型/变量、DOM/组件、流程控制、导航/工具。
- **管道语法**：`dyn-click="A|B|C"`，上一步 `$result` 传给下一步；任一步返回 `false` 中止。
- **ctx**：`element`（等同 `el`）、`model`、`params`、`options`、`$event`、`$result`、`$callStack`。
- **DB 动作**：`GET /api/platform/dynactionhelper/all` 拉取启用行（`api/chain/script/url` 四种 `ActionType`），`registerDbAction` 注册并标记 `source:'db'`；`GET /script` 生成前端注册脚本。
- **元信息**：`ACTION_DOCS` 提供 `label/group/doc/options/example/aliasOf/needEl/demo/demoCtx`，`actionList()` 分组排序供「动作助手」Demo 页动态渲染与试跑。

## 11. 一次典型请求的完整数据流

```text
用户点「查询」
  → FilterApp 触发 submit → handle.emit('changed', {filter})
  → Shell wire: filter.changed → master.loadData（with: '$event'）
  → ListApp 收到 loadData → DynCall.post('/api/dyndata/search', {table,page,size,filter,project})
  → DynDataApiController.Search → DynamicCrudService.Query（SqlSugar，按 project 选库）
  → 信封 {code:0,data:{rows,total}} → DynCall 解包 → Vue 表格刷新
```

写操作：

```text
用户点「保存」
  → DetailApp 校验（组件 __dynValidate 聚合）→ /api/dyndata/save
  → 动态 CRUD 判主键 → 增/改 → 返回 ApiResult
  → handle.emit('saved', {action, row})
  → wire: detail.saved → list.reload（列表刷新）
```
