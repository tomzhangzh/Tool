## 2. 分项评分与证据

### 2.1 架构分层与边界 — 8.0 / 10

**成立的部分**

- 三个项目依赖严格单向：`Web → Platform → Services`（`Web.csproj` 仅引用 Platform）。
- 前端从「全局脚本堆叠」升级为 **DynKernel 插件契约**（`name/stage/requires/setup`），阶段顺序固定，失败隔离（`skipped/failed` 不阻断）。
- Block 与 Shell 职责分离清晰：Block 是独立 App、Shell 是真代码视图、Wire 是纯配置，三者边界在 [BlockContracts.cs](file:///e:/Tom/Tool/VueLibV4/src/VueLibV4.Platform/Models/BlockContracts.cs) 有强类型镜像。
- 数据面收口到 `/api/dyndata/*` 单一入口 + `project` 数据域坐标；Block 无需各自配 URL。

**原扣分点（已于 2026-10-27 修复）**

- `PageController` 已拆为 `PageShellController`（页面入口）、`PageDetailController`（弹窗/详情）、`PageBlockController`（Block 装载与参数）、`PagePermissionController`、`PageChartController`，共享逻辑抽到 `Core/PageRenderSupport.cs`。
- `DynWebPageController` 已拆为 `DynPageController`（CRUD）、`DynPageRenderController`（render/paramschema）、`DynPageTemplateController`（export-template/ext-skeleton），统一前缀 `api/platform/dynpage`。
- `ToolController` 已拆为 `ComponentCheckController`、`PageGraphController`、`DbErGraphController`、`MarkdownViewerController`，工具视图迁至 `Areas/Platform/Views/Tools/`。

**复核后的剩余扣分点**

- `PageShellController` 仍同时承担视图入口与运行时三屏装配（`DynWebPage`），页面壳与数据装配尚未完全分离。
- `PageChartController` / `PagePermissionController` 目前只是把端点挪出，尚未沉淀为独立服务。
- 路由迁移未保留旧别名，存量库必须执行 `Data/migrate-routes-20261027.sql`，属于一次性的运维成本。

### 2.2 模块内聚与耦合 — 7.0 / 10

- 正向：`DynCall` 统一请求、`DynParams` 统一参数、`DynPermission` 统一前端权限，避免散落。
- 正向：`dyn-template.js` 用 `TAG_MAP` 收敛 Element 标签差异（含 `elform` 兼容）。
- 负向：`dyn-action.js` 约 **1600 行**同时包含 33 个动作、管道解析、DB 动作加载、文档元数据，属于「一个文件一个模块」的典型膨胀。
- 负向：`dyn-debug.js` 约 **1700 行**，调试 UI 与内核观测耦合，生产环境仍需随包加载。
- 负向：`_BaseLayout.cshtml` 约 **840 行**，聚合配置迁移、数据源、绑定、校验、条件、插槽、透传七大机制，任何一处的修改都可能影响全部组件。

### 2.3 可扩展性 — 8.5 / 10（最强项）

- **组件**：视图 + `DynCom` 注册行 / `ComponentMeta` 双通道，运行时按需 `defineAsyncComponent` 加载。
- **动作**：`defineAction` + DB 表双通道，支持 `api/chain/script/url` 四类，且 `actionList()` 自查文档化。
- **页面**：Block 可独立开发；布局壳可注册新壳（现有 5 个）；Wire 可页面级覆盖默认连线。
- **数据**：免模型 CRUD（SqlSugar）+ DynamicExpresso RPC + 多项目库解析。
- **生成**：规则生成 + AI 生成，AI 侧有组件白名单校验，具备「生成-校验-降级」闭环。
- 扣分：扩展点虽多，但缺少**统一的扩展契约文档与版本兼容声明**（例如 Block 契约变更如何影响存量页面）。

### 2.4 规范一致性 — 6.5 / 10

- 配置键双轨：`comOptions/labelOptions/comInnerInfo` 与 `comoptions/labeloptions` 并存，靠运行时原地迁移兜底。
- 页面实例参数双轨：`blocks[slot]` 与旧扁平键 `FilterPageSettingId/ListUrl` 并存（`DynPageViewHelper.SlotValue` 回退）。
- 渲染双轨：`PageSetting.RenderMode=Front/Back` 两套路径，列表列定义仍存在「后端渲染 + 前端 columns」交叉。
- 端口双源：`appsettings:Urls=5010` 与 `launchSettings=5116` 不一致。
- 命名混用：`DynElInput` 与 `ComPassword` 两类前缀同时存在；`PostBack/PostData`、`Open/OpenWindow` 依赖别名弥合。
- 评分理由：有兼容意识（迁移、别名、回退），但**缺少唯一权威契约与自动化校验**，长期会让新人误用旧键。

### 2.5 可维护性 — 6.0 / 10

- 大文件集中：`dyn-action`、`dyn-debug`、`_BaseLayout`、`PageGenService`（1100+ 行）、`Seeder`（1100+ 行）。
- 单一职责薄弱：控制器既拼装视图模型又做业务判断（如 `PageController.DynWebPage` 内联大量数据装配）。
- 生命周期风险：`_BaseLayout` 的 TDZ 规避依赖 `try/catch + nextTick` 重试，属于「已知坑」而非根治。
- 正向：`DynPageViewHelper` 已把四处重复的「PageSetting → JObject」收敛，说明团队有意识做去重。
- 评分理由：可读、可改，但改动半径大、回归成本高。

### 2.6 文档与示例 — 6.0 / 10

- 正向：Demo 页覆盖广（ActionHelper/Combination/Grid/Crud/Gallery/TemplateImport/CodeMirror/Rpc/TabsParams/CascadeSelect/ListView/Kanban/Widget/Mac），并且动作助手直接由 `ACTION_DOCS` 动态生成，**文档即实现**。
- 正向：本目录本次补齐了设计/API/手册/评估四份文档。
- 负向：历史 `docs/` 下文档版本多、口径不一（旧键、旧端口、旧包结构），无「单一事实源」与「文档-代码一致性校验」。
- 负向：AI 生成、Block 契约、权限模型三个高风险区域缺少完整的「输入-输出-失败」示例。

### 2.7 性能与首屏 — 6.5 / 10

- **串行加载**：`dyn-lib` 用 `chain.reduce` 顺序加载第三方库（Vue/jQuery/Lodash/Element Plus/Icons/Layui/Tailwind/Sortable/vue-draggable-plus/CodeMirror/axios）再顺序加载 18 个内核模块，首屏时间 ≈ 全量下载 + 串行解析。
- **无打包/无按需**：`dyn-debug`（1700 行）、设计器相关模块随主链加载，即使普通页面用不到。
- **组件懒加载**：`DynLoadCom` 按需 `defineAsyncComponent`，这点是加分项。
- **缓存策略**：`DYN_ASSET_HASHES` 内容哈希 + 版本号回退，静态资源缓存友好。
- 扣分：缺少「基础包 + 场景包」分层、无 HTTP/2 预加载提示、无首屏体积预算。

### 2.8 安全与权限 — 7.0 / 10

- 正向：全局 `PermissionFilter`、资源级/字段级权限、前端 `DynPermission`、`ApiKeyAuthMiddleware`、行级 `IPermissionHook`，形成多层防线。
- 正向：登录兼容历史明文升级哈希；前端日志端点匿名但加 IP 限流。
- **高风险 1（代码执行）**：`dyn.eval`（DynamicExpresso）、`EvalJs` 动作、`evalCondition`、`custom` 校验器均可执行代码；一旦配置面被低权限用户写入，等同 RCE/前端脚本注入。
- **高风险 2（凭据入库）**：`appsettings.json` 中 `Dyn:Auth:ApiKey` / `CookieSecret` 有真实值，仓库泄露即失守。
- **中风险 3（前端权限非安全边界）**：`DynPermission` 仅是 UI 体验，若后端未逐端点校验资源键，前端隐藏形同虚设。
- **中风险 4（匿名上报）**：`POST /api/log/frontend-error` 可被刷日志（已有限流，仍需配额与告警）。
- 评分理由：机制齐全，但「默认关闭 + 配置即开关 + 凭据明文」使其停留在「可配安全」而非「默认安全」。

### 2.9 测试覆盖 — 2.5 / 10（最低项）

- 解决方案仅 3 个生产项目，**无任何测试项目**（无 xunit/nunit，无 `*.Tests`）。
- 回归方式：人工 Demo 页 + 验收截图 + 控制台告警。
- 高风险区域无测试：`ValidateConfigTree`（AI 配置校验）、`DynamicCrudService`（任意表写入）、`Eval`（表达式）、`DynPageViewHelper`（槽位回退）、`DynLayouts`（wire 校验）。
- 评分理由：低代码框架的配置组合爆炸，缺少测试意味着**每次改动都是全量回归赌博**。

### 2.10 开发体验（DX） — 7.5 / 10

- 正向：Razor 运行时编译（改视图免重启）、动作助手可试跑、`InspectorData`、`DynDebug`、`ParamsPanel`、`PageGraphDemo`、AI 生成。
- 正向：`DynKernel` 的热装配与 pending 队列让「AJAX 片段里追加模块」变得可行。
- 负向：调试入口分散在 5+ 个页面，缺少统一「问题诊断台」；错误信息在部分路径仍以 `console.warn` 为主，未汇总。
- 负向：文档口径不统一，新人需读源码才能确认「该用哪个键」。

## 3. 关键风险清单

| 级别 | 风险 | 触发条件 | 影响 |
|---|---|---|---|
| P0 | 任意代码执行面过大 | 低权限用户可写 `evalCondition`/DB 动作/`custom` 校验器 | 服务器或前端被控 |
| P0 | 仓库凭据泄露 | `appsettings.json` 含真实 `ApiKey/CookieSecret` | 接口被冒用、Cookie 被伪造 |
| P1 | 零自动化测试 | 任意重构/升级 | 线上回归不可控 |
| P1 | 配置双轨长期共存 | 新页面沿用旧键 | 隐性失效、迁移成本递增 |
| P1 | 新环境无法启动 | `Seeder` 被注释 + 无迁移脚本 | 交付/演示受阻 |
| P2 | 首屏串行加载 | 弱网/多页签 | 用户感知慢，影响低代码口碑 |
| P2 | 大文件改动半径 | 修改基础布局/动作 | 影响全部页面 |

## 4. 改进优先级 TOP 5

### P0-1 建立最小可行测试体系（预计把「测试覆盖」从 2.5 → 6.0，总分 +2.5）

- **动作**：新建 `tests/VueLibV4.Tests`（xUnit）；先覆盖 5 个纯函数/服务：
  1. `ValidateConfigTree`（AI 配置合法性 + 降级）；
  2. `DynamicCrudService`（增/改/删/分页 + 参数化，禁止字符串拼接）；
  3. `RpcEvaluator`（白名单成员、超时、MaxRows）；
  4. `DynPageViewHelper.SlotSettingId/SlotValue`（新键优先 + 旧键回退）；
  5. `PageGenService.BuildXxxCfg`（字段类型 → 控件映射）。
- **验收**：`dotnet test` 全绿；CI 强制 PR 必过；核心服务行覆盖率 ≥ 60%。

### P0-2 安全基线（把「安全与权限」从 7.0 → 8.5，总分 +1.8）

- **动作**：
  1. `Dyn:Auth:ApiKey/CookieSecret` 迁移到环境变量或用户机密，仓库只留空值；
  2. `EvalJs`/`evalCondition`/`custom` 默认禁用，需显式白名单表达式（成员访问白名单 + 长度/超时限制）；
  3. 后端对每个 `/api/*` 端点补齐资源键断言，前端权限仅作 UI；
  4. `frontend-error` 增加令牌桶 + 单 IP 日配额。
- **验收**：安全用例（越权访问、表达式逃逸、日志洪泛）全部被拦截并有审计记录。

### P1-3 配置契约收敛（把「规范一致性」从 6.5 → 8.0，总分 +1.5）

- **动作**：
  1. 定义 `component.schema.json` + `page.spec.schema.json`（JSON Schema），作为设计器/PageGen/AI 的唯一权威；
  2. 明确 canonical 键（全小写），旧键只在「读取层」兼容并记录告警计数；
  3. `PageSetting.RenderMode` 明确唯一推荐路径，另一条标记为 Legacy；
  4. 增加「配置体检」端点（如 `POST /api/platform/pagesetting/lint`），扫描存量页面并输出迁移清单。
- **验收**：新页面 0 旧键；lint 报告可量化存量脏数据；AI 生成配置 100% 通过 schema。

### P1-4 首屏与内核拆分（把「性能」从 6.5 → 8.0，总分 +1.2；「可维护性」+0.6）

- **动作**：
  1. 拆 `dyn-action` → `actions/{app,window,data,model,flow,util}.js`；拆 `dyn-debug` 为按需加载；
  2. `dyn-lib` 改为「基础包（core/com/params/services）+ 场景包（actions/blocks/layout/designer/debug）」，普通页面不加载设计器与调试；
  3. 首屏脚本设预算（gzip 后 ≤ 350KB）并纳入构建检查。
- **验收**：普通列表页首屏脚本体积下降 ≥ 40%；设计器功能不受影响；Chrome Performance LCP 改善可量化。

### P2-5 部署与初始化闭环（把「DX」从 7.5 → 8.5，总分 +1.0）

- **动作**：
  1. 提供 `db/init.sql` 或恢复 Seeder 的受控入口（`--seed` 开关），并纳入启动自检；
  2. 统一端口（保留一处，另一处引用）；
  3. README 增加「5 分钟跑起来」路径（含示例库与示例页面 id）。
- **验收**：全新机器按文档可在一次启动内打开桌面并跑通一个 CRUD 页面。
