# VueLibV4 设计方案

## 1. 总体目标

在 V1（`E:\Tom\Tool\VueLib`）与 V3（`E:\Tom\Tool\VueLibV3`）之上融合出 V4：

- 后端 **ASP.NET Core 8 + SqlSugar + SQL Server 双库**（PlatformDb 平台元数据库 + BusinessDb 业务库）。
- 前端 **原生 Vue 3.5 UMD（h() 渲染，无打包）**，dyn 模块拆分。
- **组件定义沿用 V1 机制**：组件在 Razor View 与 DB 双定义，由 layout.cs 统一处理。
- 桌面沿用 V1；运行时 / 设计器沿用 V3 已验证实现。

## 2. 组件双定义源（核心，本版本重点）

### 2.1 为什么这样设计

用户明确要求"组件应该和 V1 一样是在 View 和 DB 中定义的，使用 layout.cs 来处理"。
即：组件**代码优先落 Razor View**（可版本化、可调试、IDE 高亮），**DB 只存元数据与可选内容**；运行时拉取定义。

### 2.2 双定义源

| 源 | 位置 | 内容 | 优先级 |
|----|------|------|--------|
| ① Razor View 代码 | `Views/Shared/Components/{组件名}.cshtml` | template / script / style 三段标记 + 文件头元数据注释 | **高（代码为准）** |
| ② 数据库 | `PlatformDb.ComponentMeta`（TemplateContent/ScriptContent/StyleContent/PropertyConfigJson/DefaultConfigJson） | 组件内容与属性 schema | 低（回退） |

解析优先级：**Razor View 有定义 → 用 View；否则回退 DB**。
列表合并：DB 行 + 扫描 `Views/Shared/Components/*.cshtml` 补全 DB 中不存在的组件。

### 2.3 .cshtml 组件文件约定

```razor
@* ComponentType: Common *@
@* RoutePath: /xxx *@
@* Description: 描述 *@
@model VueLibV4.Web.Dtos.ComponentViewModel
@{ Layout = null; }

<!--COMPONENT_TYPE:0-->

<!--TEMPLATE_START-->
<div class="my-comp">{{ title }}</div>
<!--TEMPLATE_END-->

<!--SCRIPT_START-->
export default { name: "MyComp", props: { title: String } };
<!--SCRIPT_END-->

<!--STYLE_START-->
.my-comp { padding: 8px; }
<!--STYLE_END-->
```

### 2.4 处理链路（layout.cs 装配）

```
_Layout.cshtml
  ├─ @await Component.InvokeAsync("DynComRegistry")
  │     → DynComRegistryViewComponent.Invoke()
  │         → ComponentService.GetEnabledListAsync()
  │         → Views/Shared/Components/DynComRegistry/Default.cshtml
  │         → <script type="application/json" id="dyncom-registry">[...]</script>
  ├─ <script src="~/dyn/vue-loader.js">   ← vueLoadCom 动态加载器
  ├─ <script src="~/dyn/dyn-*.js">         ← 校验/动作/核心/模板/组件/设计器
  └─ @Html.RenderDynActions()             ← 输出服务端注册的 dyn-init-* 隐藏 div
```

### 2.5 关键服务

- `RazorComponentRenderer.RenderAsync(name)`：用 `IRazorViewEngine.GetView` 把 `/Views/Shared/Components/{name}.cshtml` 渲染成字符串，再正则提取三段标记与 `COMPONENT_TYPE` / `ROUTE_PATH`。
- `ComponentService.GetDefineByName(name)`：先 Razor 后 DB；`GetEnabledListAsync()` 合并 DB + 文件扫描。
- `ComponentController`：`GET /api/component/list`、`GET /api/component/define/{name}`、`POST /api/component/defines`（只读拉取走 GET；动态 CRUD 才要求 POST）。信封 `{success, message, data}` 与 V1 `vue-loader.js` 约定一致。
- 前端 `vue-loader.js`：`vueLoadCom(name)` → `GET /api/component/define/{name}` → `new Function` 解析 `export default` → 注入 `template`/`style` → `DynCom.register(name, options)` 并缓存。

## 3. 动作系统（DynActionHelper）

- 所有动作入库 `DynActionHelper` 表，前端启动 `GET /api/platform/dynactionhelper/all` 动态注册。
- 动作四类：`script`（脚本，上下文 `$action/$args/$ctx/$api`）/ `url` / `api` / `chain`（动作链，支持 `when` 条件）。
- V4 在 V3 运行时基础上补齐 **V1 内置动作**：`postback / postdata / confirm-postdata / reload / open / close / updateel / evaljs / load / setVueModel / showmessage / redirect`，`run(code,args,ctx)` 内置优先、DB 兜底。
- 新增 `dyn-{event}-{action}` / `dyn-init-{action}` **属性委托模型**：`_Layout` 的 `@Html.RenderDynActions()` 把服务端 `ExecJS(...)` 渲染为隐藏 div（如 `dyn-init-evaljs='{"script":"..."}'`），动作系统 init 扫描自动执行；事件委托覆盖 change/click/dblclick/error/focus/select/mouseover。
- `setVueModel` 用 lodash `_.set` 写响应式 model。

## 4. 数据访问（免模型动态 CRUD）

- `DbFactory` 开双库：`PlatformDb()` / `BusinessDb(cs?)` / `ProjectDb(cs)`。
- `DynamicCrudService` 用 `SqlSugar.DbMaintenance` 读主键/列元数据，`InsertableByObject` / `UpdateableByObject`，分页 + `filter` 查询规范（op: eq/gt/like/in/between...）。
- **CRUD 类 API 全部 POST**（search/insert/update/delete/save/test）；只读拉取（list/define/all/get/render）走 GET。
- 列类型规则：字符串 → NVARCHAR；INT/BIT/DECIMAL/DATETIME2 写入时按列 DataType 自动转换。

## 5. 桌面 / 设计器

- **桌面**（`Views/Platform/Page/Desktop.cshtml`）：V1 视觉——`.desktop` 渐变动画背景、`.desktop-icons` Emoji 图标区（双击打开窗口）、`.taskbar` 任务栏 + 开始按钮 + 时钟；数据接 V3 API `/api/platform/desktopshortcut/all`、`/api/platform/desktopsolution/all`（PascalCase 字段）。
- **设计器**（沿用 V3 悬浮 overlay 不包装 DOM 方案）：左侧 Tab（组件库/模板/结构树）+ 左右折叠、拖拽移动 + 容器占位高亮、`onClickCapture` 选中、循环引用防护；右侧属性面板（属性/样式/事件/校验/JS）。

## 6. 数据库约束

- 平台 9 表：DesktopSolution / DesktopShortcut / DynProject / DynDict / ComponentMeta / DynActionHelper / DynTemplate / DynWebPage / DynCom。
- 业务 3 表：Student / Course / BusinessDict。
- **平台表主键 `Id INT IDENTITY(1,1)`**；字符串列统一 `NVARCHAR`。
- `ComponentMeta` 增补内容列：TemplateContent / ScriptContent / StyleContent / PropertyConfigJson / DefaultConfigJson（幂等 ALTER）。

- 运行时渲染核心沿用 V3 的 `DynCore.DynRender`（h() JSON 配置树模型），因为 V3 设计器/模板运行时深度依赖其 designMode 钩子；V1 的 `dynCore`（jQuery partial 模型）未整体替换，但其动作语义已在 `dyn-actionhelper.js` 补齐。
