## 二、核心亮点（经源码确认）

### 2.1 DynKernel 阶段化插件内核（确认亮点）
`dyn-kernel.js` 把启动拆为 9 个 stage：core → components → params → services → actions → blocks → layout → designer → debug。
- 插件显式声明 `requires`，缺依赖直接报错
- `__DYN_KERNEL_PENDING__` 队列处理加载顺序
- 支持 boot 后热装配
- 比多数自研低代码的"script 顺序加载 + 全局变量"干净一个量级

### 2.2 Block 契约 + Layout 主板模型（确认亮点）
- Block 是独立 VueApp，通过 `__dynBlock` 句柄暴露 send/on/emit/destroy
- Layout 是主板，注册 shell、绑定 wires、统一调 ready
- `DynBlocks.CONTRACTS` 静态声明端口，连线时校验
- 新增 Block 不需要改 Layout，关注点分离清晰

### 2.3 混合渲染模型（确认亮点）
- JSON 只存配置参数，不描述整个页面
- Razor / Vue / HTML / jQuery 都能接入
- DynSlotHost 占位 + 动态注入
- 配置化和手写代码可在同一页面共存

### 2.4 时序握手机制（确认亮点）
- Block 不在 mounted 里发对外事件
- 统一用 `onReady` 钩子，wire 绑好后才发首屏事件
- Filter.ready → emit changed → List.loadData，List._driven 标记防重复
- 没有 Filter 的独立 List 页，onReady 兜底加载

### 2.5 全套开发工具链（确认亮点）
| 工具 | 作用 |
|------|------|
| DynDiv Debug | 运行时查看组件、参数、改值、查 ActionHelper |
| PageGraphDemo | Block 消息链路可视化 |
| DbErGraph | 数据库 ER 图，字段级连线，在线改中文注释 |
| ComponentCheck | 组件长廊质检，逐个挂载验证 |
| PageGen | 读表结构一键生成三屏页面 |

### 2.6 其他确认亮点
- **JS Bridge**：前后端双向通信，第三方 UI 库可参与业务
- **Vue 嵌套**：标记标签自动创建实例，支持多层嵌套
- **WithAction**：后端主动下发 UI 指令，反转前后端调度关系
- **多桌面工作台**：Windows / macOS 风格 Shell，演示效果强
- **FormItem Diff**：字段改值红三角标记，hover 看新旧值
- **TreeApp 拖拽**：Sortable 跨层级排序，串行提交防 SQLite 锁

## 三、Bug 清单（按严重程度，✅ 表示已修复）

### P0 — 真实 Bug，会导致功能异常

#### ✅ Bug 1：Layout destroy 不销毁 Block（生命周期泄漏）
**文件**：`dyn-layout-engine.js`
**问题**：destroy 只解绑 wire 和 disposer，没有遍历各 Block 句柄调 destroy，也没有调 dyn.unmount。Layout 销毁后 Block 的 Vue 实例、事件监听全部残留，反复进出页面累积内存和重复事件。

**已修复**：destroy 里遍历非 shell 句柄调 destroy()，再调 `global.dyn.unmount(root)` 级联销毁全部 Vue 实例。

---

#### ✅ Bug 2：Ready 顺序没有强制 filter → list → detail
**文件**：`dyn-layout-engine.js`
**问题**：按 Object.keys(handles) 顺序调 ready，handles.shell 第一个，之后按 DOM 顺序。如果模板 DOM 顺序不是 filter→list→detail，ready 顺序就错了，时序握手机制失效。

**已修复**：显式定义 `READY_ORDER = ['filter','master','detail','tree']`，按优先级调 ready，剩余节点和 shell 最后。

---

#### ✅ Bug 3：Kanban 重复加载
**文件**：`KanbanBoardBlock.cshtml`
**问题**：onReady 调 loadData，$nextTick 又兜底 loadData。Layout 环境下两次并发请求，可能竞态覆盖。

**已修复**：加 `_bootLoaded` 标记，onReady 和兜底 setTimeout 只允许触发一次。

---

#### ✅ Bug 4：Kanban 卡片没有按 BoardId 过滤
**文件**：`KanbanBoardBlock.cshtml`
**问题**：cards 查询只过滤 IsActive，跨看板的卡片全部显示，数据混乱。

**已修复**：filter 加 `BoardId: { op: 'eq', value: self.boardId }`。

---

#### ✅ Bug 5：TabsBlock 子 Tab 无法动态解锁
**文件**：`TabsBlock.cshtml`
**问题**：disabled 是 Razor 静态生成，主记录保存后 Tab 不解锁。

**已修复**：改为 `:disabled="!currentId"`，保存后 currentId 更新，Tab 自动解锁；openEdit 时预标记全部子 tab。

---

### P1 — 隐患，边界场景会出问题

#### ✅ Bug 6：blocks-common requires 声明不完整
**文件**：`dyn-blocks-common.js`
**问题**：注释明说依赖 DynCall，但 requires 为空。重构 stage 顺序时会炸。

**已修复**：`requires:['call']`。

---

#### ✅ Bug 7：Vue2 语法残留 .native
**文件**：`KanbanBoardBlock.cshtml`
**问题**：Vue3 已移除 `.native`，事件不生效。

**已修复**：改为 `@@keyup.enter`。

---

#### ✅ Bug 8：DbMeta FkList 空引用
**文件**：`DbMetaController.cs`
**问题**：外键引用目标表主键时 PRAGMA 的 to 列为 NULL，`GetString(4)` 抛异常。

**已修复**：IsDBNull 判断，to 列默认 "Id"。

---

#### ✅ Bug 9：DbMeta PRAGMA 直接拼接表名
**文件**：`DbMetaController.cs`
**问题**：表名含双引号时 PRAGMA 语法错误。

**已修复**：加 Q() 辅助方法，双引号双写。

---

#### ✅ Bug 10：TabsBlock onTabChange 没绑定
**文件**：`TabsBlock.cshtml`
**问题**：定义了 onTabChange 方法但没绑 tab-change 事件，切 Tab 时不标记加载。

**已修复**：el-tabs 加 `@@tab-change="onTabChange"`。

---

#### ✅ Bug 11：Kanban 排序逐条发请求
**文件**：`KanbanBoardBlock.cshtml`
**问题**：Promise.all 并发写 SQLite 会 database is locked。

**已修复**：改为串行 Promise 链。

---

### P2 — 代码质量问题，不影响功能（待修）

#### Bug 12：硬编码 Author
**文件**：`KanbanBoardBlock.cshtml`
```js
data: { CardId: ..., Content: text, Author: 'Tom' }
```
**建议**：从当前登录用户取，或通过配置注入。

#### Bug 13：无元数据缓存
- DbMeta 每次请求全量读 sqlite_master + 全表 PRAGMA
- DynWebPage、Template、Block 每次访问查库
**建议**：IMemoryCache 缓存，表结构变更时失效。

#### Bug 14：无认证授权
- 所有 API 裸奔
- DynDiv Debug、看板、ER 图任意访问
- 生产环境必须加登录 + 角色权限

#### Bug 15：后端无操作日志
- 只有前端错误上报到 `/api/log/frontend-error`
- 数据增删改、WithAction 下发没有审计记录

## 四、上一版评估的修正

对照 `2026-10-04-架构评估.md`，需要修正的点：

   - onReady 机制确实是亮点，写得比预想的好

## 七、结论

**架构方向没有问题，是一个有差异化的设计。**
- 不走全 JSON 路线，基于 .NET MVC 混合渲染，在国内 .NET 生态有辨识度
- Block 契约、时序握手、全套工具链是真正的亮点
- 多桌面工作台和 WithAction 是演示加分项

**P0+P1 已修复，当前可交付真实项目原型。**
- 生命周期：destroy 级联清理 Vue 实例和事件
- 时序：Ready 顺序显式保证
- 看板/Tabs：功能闭环，数据隔离正确

**剩余 P2 是工程化基建，不影响架构方向。**
- 认证授权、元数据缓存、操作日志是上线前必须补的
- 补完后就是一个可以对外讲的 .NET 低代码产品
