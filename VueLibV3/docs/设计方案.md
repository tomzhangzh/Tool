# VueLibV3 详细设计方案

> 目标：一个「**C# 后端 + 原生 UMD 前端、无需打包、免 Model、组件与动作全部入库**」的企业级低代码平台。
> 技术栈：ASP.NET Core 8（MVC + Areas）+ SqlSugar ORM（SQL Server 双库）+ Vue 3 UMD（`h()` 渲染，运行时不做模板编译）+ ElementPlus / Lodash / LayUI / Tailwind.css / ECharts / CodeMirror。

## 1. 总体架构

```
┌────────────────────────────── 浏览器（无打包工具，直接 <script> 引用）──────────────────────────────┐
│  index.html / designer.html / webpage.html / demo/*.html                                              │
│    └─ dyn-lib.js（依赖加载器）→ vue / element-plus / lodash / layui / tailwind / echarts / codemirror  │
│    └─ dyn-validator / dyn-actionhelper / dyn-core / dyn-template / dyn-com / dyn-designer              │
└──────────────────────────────────────────┬─────────────────────────────────────────────────────────────┘
                                           │ HTTP (JSON)
┌──────────────────────────────────────────▼─────────────────────────────────────────────────────────────┐
│  ASP.NET Core 8  Web  （Areas 分层）                                                                    │
│  ├─ Areas/Platform/Controllers  ── 9 个控制器（/api/platform/*）                                        │
│  ├─ Areas/Business/Controllers  ── DynData（免模型数据）+ BusinessDict（业务词典）                       │
│  └─ Core/  DynamicCrudService（免模型 CRUD）· DbFactory（双库工厂）· Seeder（建库+种子）                 │
└──────────────────────────────────────────┬─────────────────────────────────────────────────────────────┘
                                           │ SqlSugar
                    ┌──────────────────────┴──────────────────────┐
              PlatformDb（平台元数据库）                     BusinessDb（业务数据库）
              DesktopSolution/Shortcut · DynProject ·       Student · Course · BusinessDict
              DynDict · ComponentMeta · DynActionHelper ·   （业务词典放业务库，可动态扩展任意业务表）
              DynTemplate · DynWebPage · DynCom
```

**分层约定**：
- 所有**平台相关控制器放在 `Areas/Platform`**；业务数据控制器放 `Areas/Business`。
- 前端**页面/组件/动作加载全部动态化**：组件注册表（dyn-com）、动作注册表（dyn-actionhelper）、页面渲染（DynRender）都是同一套代码，数据来自数据库。

## 2. 前端运行时 dyn-lib 三段式

用户要求将 `dyn-lib.js` 分割为 `dyn-core`、`dyn-actionhelper`，按需扩展。V3 实际拆为 6 个模块，职责单一：

| 模块 | 职责 | 依赖 |
|---|---|---|
| `dyn-lib.js` | 头部静态变量（BASE/DEFAULT_LIBS/DYN_MODULES）+ 顺序加载 + `ready()` 回调 | 无 |
| `dyn-validator.js` | 校验规则（required/email/phone/pattern/min/max/length/custom）→ `toRules()` 转 el-form rules | 无 |
| `dyn-actionhelper.js` | 动作注册表 + `run/runChain`，上下文 `$action/$args/$ctx/$api` | 无 |
| `dyn-core.js` | `DynRender` 递归 VNode 渲染 + `normalize/clean/getPath/setPath/mount` | Vue / DynCom |
| `dyn-template.js` | `importTemplate(DOMParser→JSON)` / `exportTemplate(JSON→模板)` | 无 |
| `dyn-com.js` | Dyn* 组件库 + ElementPlus 全局注册 + 组件元数据加载 | Vue / ElementPlus |
| `dyn-designer.js` | 设计器（组件面板/画布/属性面板/导入导出） | 以上全部 |

**示例（页面只需两步）**：

```html
<script src="/dyn/dyn-lib.js"></script>
<script>
  DynLib.ready(function () {
    var app = Vue.createApp({ /* ... */ });
    DynCom.setupApp(app);          // 注册 ElementPlus + 图标 + DynRender + 全部 Dyn 组件
    app.mount('#app');
  });
</script>
```

**扩展第三方库**：在 `dyn-lib.js` 头部的 `DEFAULT_LIBS` 数组中追加即可（例如 `{ url: 'vue-validator.global.min.js', name: 'vue-validator' }`），加载链自动包含。

## 3. 数据库设计（双库 · 全 nvarchar）

### 3.1 双库策略
- **PlatformDb**：平台元数据（解决方案/桌面/项目/词典/组件元数据/动作/模板/页面/组件）。
- **BusinessDb**：业务数据（学生/课程/业务词典）。**业务词典放业务库**（`BusinessDict`），平台词典（`DynDict`）只存平台自身数据词典。

> 选择 SQL Server（用户首选），若部署环境无 SQL Server，可把连接串切换为 `Data Source=LocalDB` 或 SQLite —— 由于全部使用 SqlSugar 抽象 + 动态 CRUD，切换成本极低。

### 3.2 平台表（9 张，全部 nvarchar）

| 表 | 说明 | 关键字段 |
|---|---|---|
| `DesktopSolution` | 桌面解决方案 | Id/Name/Code/Description/Icon/SortNo/IsActive |
| `DesktopShortcut` | 桌面快捷方式 | Id/SolutionId/Name/Code/Url/Icon/TargetType(page/action/url)/SortNo/IsActive |
| `DynProject` | 项目（一个 Solution 可有多个 Project，即不同数据库） | Id/SolutionId/Name/Code/DbType/ConnectionString/Description |
| `DynDict` | 平台数据词典 | Id/DictType/DictCode/DictName/SortNo/IsActive |
| `ComponentMeta` | 组件元数据（驱动设计器与运行时） | Id/ComponentName/Label/Category/Icon/AcceptAll/AllowDrop/CanDropInto/SlotsDefine/PropsMeta/IsElementPlus |
| `DynActionHelper` | 动作助手（脚本全部入库） | Id/Name/Code/ActionType(script/url/api/chain)/Script/ParamsJson/Language/Description |
| `DynTemplate` | 预定义模板 | Id/Name/Code/Category/Icon/TemplateJson/ConfigJson/Description |
| `DynWebPage` | 动态页面 | Id/ProjectId/Name/Code/TemplateId/PageJson/ConfigJson/Url |
| `DynCom` | 组合组件（代码已有定义时以代码为准） | Id/Name/Code/Category/ComJson/Description |

**全 nvarchar 示例（建表语句片段）**：

```sql
CREATE TABLE [DynActionHelper] (
  [Id]         nvarchar(64)  NOT NULL PRIMARY KEY,
  [Name]       nvarchar(128) NOT NULL,
  [Code]       nvarchar(64)  NOT NULL,
  [ActionType] nvarchar(32)  NOT NULL,          -- script/url/api/chain
  [Script]     nvarchar(max) NULL,              -- 脚本或 URL 模板或动作链 JSON
  [ParamsJson] nvarchar(max) NULL,
  [Language]   nvarchar(32)  NULL,
  [Description] nvarchar(512) NULL,
  [SortNo]     nvarchar(16)  NULL,
  [IsActive]   nvarchar(4)   NULL
);
```

### 3.3 业务表（3 张示例，可任意扩展）
`Student`（学生）、`Course`（课程）、`BusinessDict`（业务词典，含 ParentId 支撑树形）。

## 4. 免 Model 动态 CRUD

**核心思路**：SqlSugar 的 `DbMaintenance.GetColumnInfosByTableName(table)` 可以拿到表的**主键、字段、类型、可空**等信息——只要知道表名，就能实现 Insert / Update / Delete / Query / Page / Sort，无需 C# Model 类。

`Core/DynamicCrudService.cs` 提供（方法签名示例）：

```csharp
public List<Dictionary<string, object>> Query(ISqlSugarClient db, string table, string where = null, object param = null, string orderBy = null)
public Dictionary<string, object> First(db, table, where, param)
public (List<Dictionary<string, object>> rows, int total) Page(db, table, int page, int size, string where, object param, string orderBy)
public object Insert(db, table, JObject data)   // InsertableByObject
public object Update(db, table, JObject data)   // UpdateableByObject + WhereColumns(主键)
public int Delete(db, table, JObject keys)      // Deleteable<object> + WhereColumns(主键)
public JObject Meta(db, table)                  // 主键列表 + 字段列表（供前端动态表单/表格使用）
```

**分页 + 条件 + 排序示例（HTTP）**：

```
GET /api/business/dyndata/page
    ?table=Student
    &project=Business-School
    &page=1&size=20
    &filter={"Name":{"op":"like","value":"张"},"Age":{"op":"ge","value":"18"}}
    &__orderby=CreateTime desc
```

`filter` 支持操作符字典：`eq / neq / gt / ge / lt / le / like / notlike / in / between`，值统一按字符串处理（对应全 nvarchar 设计）。

**保存示例（POST /api/business/dyndata/save）**：

```json
{ "table": "Student", "project": "Business-School",
  "data": { "Id": "student-1", "Name": "张三", "Age": "20", "ClassName": "一班" } }
```
> 带主键 → 更新；不带主键 → 新增。更新时主键由 `Meta(table)` 推导，无需传入。

| 实体 | 保留 | 改进 |
|---|---|---|
| `ComponentMeta` | 保留 | 新增 `AcceptAll`（容器任意接收）、`AllowDrop/CanDropInto`（拖拽准入）、`SlotsDefine`（插槽定义）、`PropsMeta`（属性面板自动渲染 schema） |
| `DesktopShortcut` | 保留 | `TargetType` 扩展为 page/action/url 三种打开方式 |
| `DesktopSolution` | 保留 | 无 |
| `DynActionHelper` | 保留 | **所有动作（含脚本）必须入库**；`ActionType` 四类：script/url/api/chain；`ParamsJson` 声明参数 schema |
| `DynDict` | 保留 | 明确为**平台数据词典**；业务词典放入业务库 `BusinessDict` |
| `DynProject` | 保留 | 归属 `DesktopSolution`（一个 Solution 多个 Project = 不同数据库）；`ConnectionString` 支持 `(startup)` 占位由 Seeder 注入 |
| `DynTemplate` | 重新设计 | `TemplateJson` = 可实例化的 DynCom 配置树；`ConfigJson` = 模板参数 schema（用户配置后即生成页面） |
| `DynWebPage` | 保留 | `PageJson` 为空时**回退模板 TemplateJson**（模板即页面）；`Render` 接口返回 `{id,name,code,config,configjson}` |

## 6. DynCom 组件体系

### 6.1 设计目标
- **设计时/运行时一套代码**：都用 JSON 配置 + `h()` VNode 递归渲染（`DynCore.DynRender`），**运行时不做模板编译**。
- **组件全部入库**（ComponentMeta），代码中有定义的以代码为准（"如果存在定义不用在数据库中定义"）。
- **dynCom 使用 view（模板）实现**，而不是写在 JS render 里 —— 例如 DynGridContainer / DynCrudPage / DynDesktop 等全部用 `<template>` 字符串定义，维护直观。

### 6.2 组件分类

| 分类 | 组件 |
|---|---|
| 容器组件 | `DynGridContainer`（grid/flex）、`DynCard`、`DynForm`、`DynWrapper`（开放容器）、`DynSlot`（插槽占位）、`DynFragment`（不产生 DOM）、`DynForEach`（循环）、`DynCombination`（组合：开放属性+容器+插槽）、`DynOpenWindow`、`ElCard/ElRow/ElCol/ElTabs` 等 |
| 数据组件 | `DynCrudPage`（免模型增删改查）、`DynTable`（免模型表格）、`DynTree`（免模型树）、`ElTable/ElTree/ElPagination` |
| 展示组件 | `DynText`、`DynEChart`（ECharts）、`DynCodeMirror`（JSON 编辑器）、`DynDesktop`（桌面） |
| 表单组件 | ElementPlus 全量：ElInput/ElSelect/ElDatePicker/ElRadioGroup/... + `DynValidator` 校验 |
| 特殊 | `DynCombination`（组合组件）、`DynOpenWindow`、`DynDesktop` 都按组件实现 |

### 6.3 统一组件配置结构（示例）

```json
{
  "component": "DynNInput",
  "modelname": "",
  "options": {
    "comoptions":   { "placeholder": "请输入", "clearable": true },
    "comlisteners": { "click": "ShowMessage" },
    "labeloptions": { "label": "输入框", "required": false, "show": true },
    "itemoptions":  { "style": {}, "class": "" }
  },
  "validators": [],
  "childrenctrls": [],
  "slots": {},
  "extendinfo": {}
}
```

### 6.4 容器 grid 布局（用户点名要求）

容器 `comoptions` 即 CSS 样式；子组件用 `itemoptions.class` 配 `col-span-2`：

```json
{ "component": "DynGridContainer",
  "options": { "comoptions": { "display": "grid", "grid-template-columns": "1fr 1fr", "gap": "16px 24px" } },
  "childrenctrls": [
    { "component": "ElInput", "options": { "comoptions": { "placeholder": "左格" } } },
    { "component": "ElInput", "options": { "comoptions": { "placeholder": "右格" } } },
    { "component": "ElButton",
      "options": { "comoptions": { "text": "跨两列", "type": "primary" },
                   "itemoptions": { "class": "col-span-2" } } }
  ] }
```

### 6.5 校验（DynValidator）

```json
"validators": [
  { "type": "required", "message": "请输入姓名" },
  { "type": "pattern", "pattern": "^1[3-9]\\d{9}$", "message": "手机号格式不正确" },
  { "type": "custom", "script": "return v && v.length >= 2;", "message": "至少 2 个字符" }
]
```
运行时自动转换为 el-form rules，随 labeloptions 包装为 `ElFormItem`。

### 6.6 空值统一处理（用户点名要求）
- **保存时**：`null / "" / [] / {}` 不写入数据库 —— `DynCore.clean()` 递归剔除。
- **加载时**：补默认值 —— `DynCore.normalize()` 填充基础结构（labeloptions/itemoptions/validators/childrenctrls/slots/extendinfo）+ `ComponentMeta.PropsMeta[].default`。

```js
var cleaned = DynCore.clean(cfg);            // 保存前
var cfg = DynCore.normalize(apiConfig);      // 加载后
```

### 6.7 属性框组件
设计器右侧属性面板由 `ComponentMeta.PropsMeta` **自动渲染**：string→输入框、number→数字框、boolean→开关、select→下拉、json→CodeMirror、color→取色器。任何新增组件只需在元数据中声明 PropsMeta，属性面板零代码扩展。

## 7. 设计器（不包装 DOM 的悬浮选中层）

### 7.1 问题
传统设计器在选中/拖拽时会在组件外面**包装一个操作 div**，这会破坏 CSS Grid/Flex 布局 —— 例如 `display:grid` 的子项被多包一层后不再参与网格布局，`col-span-2` 失效。

### 7.2 方案（已实现）
**不包装 DOM，采用「绝对定位悬浮选中层」**：

1. 渲染时给每个组件根元素打标记：`data-dyn-uid="n1"`（由 `DynCore.uidOf` 分配，WeakMap 关联 JSON 节点）。
2. 选中/悬停/拖拽事件**直接绑定在组件根元素上**（`@click/@mouseover/@dragover/@drop`），不产生额外 DOM。
3. 选中框是一个绝对定位的 `div`（`pointer-events:none`），位置用 `getBoundingClientRect()` 实时计算，容器滚动/尺寸变化时用 `ResizeObserver` 刷新。

```
┌─ canvas（position:relative）─────────────────────────┐
│  ┌─ DynGridContainer (display:grid; 1fr 1fr) ──┐    │
│  │ [组件A]  [组件B]   ← 布局完全不受干扰          │    │
│  │ [组件C col-span-2]                            │    │
│  └───────────────────────────────────────────────┘    │
│  ┌─ dyn-overlay（position:absolute; pointer-events:none）┐
│  │  边框 + 顶部工具条（上移/下移/复制/删除）              │
│  └───────────────────────────────────────────────────────┘
└───────────────────────────────────────────────────────────┘
```

**拖拽准入**：由 `ComponentMeta.AllowDrop / AcceptAll` 驱动 —— `AcceptAll="1"` 的容器可接收任意组件；否则只在 `AllowDrop` 白名单内接收（如 ElTable 只接收 ElTableColumn）。

**页面大时拆 View**：设计器左侧（组件库）、中间（画布）、右侧（属性/事件/校验/结构/JSON）本就是独立面板；运行时页面也支持 `dyn-init` 拆分（left/center/right/top 各为独立 DynCom 子树）。

## 8. 模板导入 / 导出（Vue Template ⇄ JSON）

### 8.1 可行性结论
**可行，且有明确边界**。`dyn-template.js` 已实现双向转换：

**导入**（粘贴 ElementPlus Vue Template → JSON）：
- `DOMParser` 解析 HTML 片段；
- 递归映射：标签→`component`（kebab→Pascal）、`v-model`→`modelname`、`:prop`→`comoptions.__expr`、`@click`→`comlisteners`、`class/style`→`itemoptions`、`<template #xxx>`→`slots`；
- **边界**：复杂表达式（三元、函数调用）降级存 `__expr`（设计器里作为动态表达式保留），指令类（v-if/v-for）存入 `extendinfo`，导入后可在设计器二次微调。

**示例**：

```html
<ElForm :model="formData" label-width="100px">
  <ElFormItem label="姓名" required>
    <ElInput v-model="formData.name" placeholder="请输入姓名" clearable />
  </ElFormItem>
  <ElButton type="primary" @click="ShowMessage">提交</ElButton>
</ElForm>
```

导入得到（节选）：

```json
{ "component": "ElForm", "options": { "comoptions": { "label-width": { "__expr": "'100px'" } } },
  "childrenctrls": [
    { "component": "ElFormItem", "options": { "labeloptions": { "label": "姓名", "required": true } },
      "childrenctrls": [ { "component": "ElInput", "modelname": "formData.name",
          "options": { "comoptions": { "placeholder": "请输入姓名", "clearable": true } } } ] },
    { "component": "ElButton", "options": { "comlisteners": { "click": "ShowMessage" } } }
  ] }
```

**导出**（JSON → Vue Template）：仅作为**代码导出工具**（便于交付源码），运行时仍用 `h()` 渲染、不编译模板。

## 9. DynActionHelper 动作助手（全部入库）

**约束：所有 actionHelper 都必须在 DB 中存在（包括脚本），支持动态注册 / 生成脚本。**

| ActionType | Script 含义 | 示例 |
|---|---|---|
| `script` | 可执行 JS，上下文 `$action/$args/$ctx/$api` | `$api.msg($args.message || '操作成功');` |
| `url` | URL 模板（`{param}` 占位） | `"/webpage.html?code={code}"` |
| `api` | 接口地址模板 | `"{url}"`（GET/POST，返回 data） |
| `chain` | 动作链 JSON `[{action,params,when}]` | 依次执行多个动作，`when:"result"` 表示上一步成功才继续 |

**三种接入方式**：
1. **动态加载注册**（默认）：前端启动时 `DynActionHelper.loadAll()` → `GET /api/platform/dynactionhelper/all` → `registerAll`。
2. **生成脚本注入**：`GET /api/platform/dynactionhelper/script` 返回文本 JS（`DynActionHelper.register({...})` 序列），可 `<script src>` 直接注入。
3. **按需拉取**：`run(code)` 未注册时自动 `GET /get?id=code` 注册后执行。

**执行示例**：

```js
DynActionHelper.run('ChainDemo', {}, { reload: () => table.reload() });
// 链：提示 → 确认 → （确认成功才）提示完成
```

**页面联动**：任何管理页面能使用 dyn-actionhelper 就使用（按钮事件 `comlisteners.click = "动作Code"`），例如学生管理页的「刷新」动作 `RefreshStudentList` 通过 `$ctx.reload()` 调用页面上下文。

## 10. DynTemplate / DynWebPage（模板即页面）

- `DynTemplate` 是**预定义模板**：`TemplateJson`（DynCom 配置树）+ `ConfigJson`（参数 schema）。
- `DynWebPage` 是**真正的动态页面**：选择 template + 用户配置参数（实例化 PageJson）→ 运行。**PageJson 为空时回退模板 TemplateJson**，即"模板 + Config 即页面"。

**种子示例**：`student-manage` 页面 → 模板 `tpl-student`（DynCrudPage，免模型操作 Student 表）；`tree-list-page` → 模板 `tpl-treelist`（左 DynTree + 右 DynTable）；`home-page` → 主页模板。

**渲染接口**：`GET /api/platform/dynwebpage/render?code=student-manage` → `{ id, name, code, config(配置树), configjson(参数) }`，前端 `DynCore.mount(config)` 直接运行。
